Reference 01

FileGDB 八层知识地图

遇到任何 FileGDB 问题，先判断它属于哪一层，再找证据。不要从 API 现象直接跳到磁盘格式结论。

1 · 逻辑信息模型

Workspace、Dataset、Feature Dataset、Feature Class、Table、Field、Feature。

2 · 文件家族

.gdbtable、.gdbtablx、.spx、.atx、.freelist 和辅助文件。

3 · 系统元数据

SystemCatalog、Items、ItemTypes、ItemRelationships、XML Definition 和 Documentation。

4 · 表与记录

Header、字段描述符、NULL bitmap、记录长度、字段值、FID 和物理 offset。

5 · 空间模型

Geometry、Spatial Reference、origin、scale、resolution、tolerance、Z/M 和拓扑。

6 · 索引

SPX/ATX B+ 树只产生候选；最终属性和几何判断仍不可省略。

7 · 执行与可靠性

Query Planner、Cursor、缓存、损坏输入、回退、生命周期和 Reader-only 边界。

8 · 高级数据集

Raster、Topology、Network、Terrain、Parcel Fabric 等由基础数据、元数据、规则和派生结构共同构成。

端到端主链路

.gdb directory
  → system catalog
  → logical dataset / physical table mapping
  → field descriptors
  → TABLX slot and record offset
  → record fields and geometry
  → SPX / ATX candidates
  → final predicates
  → FeatureCursor / WKB
定位规则：先问“这个问题改变的是对象含义、磁盘位置、字节解释、候选集合，还是最终结果？”答案通常会把问题限定到一到两层。

三个不能混淆的完整性

完整性问题
Physical read字节、记录和原始 XML/Binary 是否无损可取？
Structured schemaDomain、Subtype、Relationship 和层级是否被结构化还原？
Behavioral parityArcGIS 的规则、拓扑、网络和编辑行为是否真的可执行？
学习时请随时向 AI 追问，但要求它标记证据等级并指出未知项。
