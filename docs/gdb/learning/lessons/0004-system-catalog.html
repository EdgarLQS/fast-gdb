Week 04 · Catalog

系统表是 Geodatabase 的“自我描述”

系统表职责UUID 关系与 Catalog 映射边界和失败语义

业务记录告诉你“有哪些值”；系统表告诉你“这些对象是什么、彼此如何关联、应该表现成什么”。

四张核心表

系统表职责
GDB_Items列出对象，保存名称、类型、路径、Definition 和 Documentation
GDB_ItemTypes定义对象类型及类型层级
GDB_ItemRelationships记录对象 UUID 之间的关系实例
GDB_ItemRelationshipTypes定义关系类型和方向语义
item UUID ── type UUID ──→ item type
    │
    ├─ catalog path / physical name
    ├─ XML Definition / Documentation
    └─ relationship UUIDs ─→ other items
真实数据对照
build/dev/bin/explorgdb_cli dump-records \
  test_data/gdb/acceptance_metadata.gdb/a00000004.gdbtable
build/dev/bin/explorgdb_cli dump-records \
  test_data/gdb/acceptance_metadata.gdb/a00000005.gdbtable

第一条命令观察 GDB_Items 的 Name、PhysicalName、Path 和 Type UUID；第二条命令从 GDB_ItemTypes 观察类型 UUID、名称和父类型。先完成 UUID 关系追踪，再由 CatalogResolver 连接业务表编号。

EsriConfirmed四张核心系统表的产品语义来自 Esri。FastGdbConfirmed本项目还审计 GDB_Datasets 等兼容表，并区分 missing、empty 与 unreadable。

AI 审核题

AI 读取 GDB_Items 失败后返回空图层列表，并称数据库为空。

审核要点：空、缺失、损坏和不可读必须使用不同诊断；否则会把错误伪装成有效结果。

闭卷复述

UUID 在系统表中解决什么问题？

稳定关联对象、类型和关系，不依赖显示名称或物理编号。

Definition XML 为什么既重要又危险？

它承载丰富 Schema，但版本和对象类型不同，不能用脆弱的单一模板假设。
