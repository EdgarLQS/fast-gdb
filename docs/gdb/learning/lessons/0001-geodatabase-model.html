Week 01 · Logical model

先分清“对象”与“文件”

本周唯一目标：看到 Feature Class 时，脑中同时出现“带几何字段的表”和“由系统元数据赋予行为的数据集”，而不是把它想成一个独立文件。

核心模型

Geodatabase workspace
├─ standalone table
├─ standalone feature class
├─ feature dataset
│  ├─ feature class
│  └─ topology / network / terrain ...
└─ schema behaviors
   ├─ domain / subtype
   └─ relationship / attachment / rules
概念最小定义不要误解为
Table按字段定义组织的行集合一定包含空间数据
Feature Class具有 OID 和 Geometry 等语义的表一个可独立解释的单文件
Feature Dataset共享空间参考的逻辑容器磁盘中的普通子目录
Schema behavior系统元数据定义的约束和关联业务记录本身
EsriConfirmedEsri 官方架构说明把 Feature Class 描述为带空间列的表，并说明系统表共同赋予 Geodatabase 行为。FastGdbConfirmedfast-gdb 通过 Catalog 和 MetadataReader 分别处理物理定位与结构化元数据。

AI 审核题

AI 说：“Feature Dataset 就是 `.gdb` 目录里的一个子文件夹，所以遍历目录即可得到层级。”

审核要点：这混淆了逻辑容器与物理目录；应从系统元数据中的路径、类型和关系还原层级。

闭卷复述

Feature Class 为什么本质上是表？

记录和字段按表存储；几何列、系统元数据、空间参考和规则让它表现为 Feature Class。

“记录可读”为什么不等于“Geodatabase 完整”？

Domain、Subtype、Relationship、Topology 等行为来自系统元数据和派生结构。
