Week 13 · Query

索引是计划的一部分，WHERE 才是语义

ATX 与 WHEREQuery PlannerCursor 和生命周期

ATX 可加速特定单字段比较，但 Query Planner 必须判断表达式是否兼容，并在物化记录后执行最终 WHERE、空间条件和结果窗口。

查询层次

QueryRequest
  → validate arguments / budget / cancellation
  → choose FID / ATX / SPX / combined / scan plan
  → candidate FIDs or sequential records
  → materialize projected fields + geometry
  → final WHERE and spatial predicates
  → offset / limit / ordering
  → FeatureCursor
对象职责
ATX按已知 key 编码和比较关系产生候选 FID
WHERE compiler保存 NULL、字符串转义、逻辑组合和比较语义
Planner选择可证明正确的路径，而不是选择“看起来最快”的路径
Cursor管理一次查询的迭代、移动、资源借用和状态

AI 审核题

AI 看到 LOWER(name)='road' 中包含 name 字段，于是直接查 name 的 ATX。

审核要点：函数表达式改变 key 语义；除非存在匹配的函数索引并被可靠识别，否则不能当作直接字段索引。

闭卷复述

Planner 的正确性优先级是什么？

先保证候选不会漏掉合法结果和最终语义一致，再优化候选规模与 I/O。

Cursor 为什么有生命周期约束？

它借用 Layer 的文件、映射、Schema 和查询状态；源变化或并发 Cursor 可能使这些前提失效。
