Week 07 · Records

记录解析是一台由 Schema 驱动的游标

从记录开头依次消费 bitmap 和字段 payload。任何字段宽度或 NULL 判断错误，都会让后续字段整体错位。

解析流程

record length
  → NULL bitmap for nullable fields
  → field 1: null ? skip : decode
  → field 2: null ? skip : decode
  → ...
  → exact end-of-record check
状态存储含义
NULL位图表示没有值，通常不消费该字段 payload
Empty string字段存在，长度为 0
Zero-length Binary/XML字段存在，payload 长度为 0
Missing added field旧记录可能没有后来新增 nullable 字段的位图/值
Truncated声明需要更多字节但记录已结束，应报损坏
记录拆解表

选取 acceptance_metadata 中一条已知记录。建立列：字段顺序、nullable bit、长度前缀、起始 offset、结束 offset、解释值、证据标签。允许借助 AI 计算，但必须人工核对 offset 是否连续。

FastGdbConfirmed本仓库对新增 nullable 字段的旧记录有兼容测试。DataObserved单个样本只能证明该 Schema/版本下的记录。

AI 审核题

AI 为每个字段都分配一个 NULL bit，并按字段总数计算 bitmap。

审核要点：OID 和非 nullable 字段等不一定参与；应由实际 field layout 合同决定。

闭卷复述

为什么空值和空字符串不能合并？

一个表示字段不存在值，另一个表示字段存在且值长度为零；查询和默认值语义不同。

如何发现游标错位？

检查每个字段消费的 offset、记录末端一致性，并使用已知后续字段或原始值对照。
