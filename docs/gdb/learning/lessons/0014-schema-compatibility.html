Week 14 · Behavior

记录可读，只完成了第一层完整性

Geodatabase 行为由系统元数据把多个基础表连接起来。Domain、Subtype、Relationship 和 Attachment 需要同时理解原始 XML、结构化结果和版本边界。

行为模型

workspace domains ─→ field / subtype bindings
subtype code       ─→ defaults + per-field domains
relationship class ─→ origin + destination + keys + cardinality + composite
attachment         ─→ attachment table + GlobalID relationship
feature dataset    ─→ catalog hierarchy + shared spatial reference
能力证明完整需要什么
Physical read原始记录、XML、Binary 不丢失
Structured metadataXML/系统表被稳定解码成 Domain、Subtype、Relationship 等对象
Behavioral parity规则、编辑、拓扑或网络行为与 ArcGIS 一致
Version compatibility跨 ArcGIS/GDAL 版本和字段类型样本验证
能力矩阵

使用 tests/createdata/DATASET_GUIDE.md，为 Domain、Subtype、Relationship、Attachment、64-bit OID、CDF/SDC 建立四列：产品语义、当前样本、fast-gdb 状态、未验证项。跳过项必须写原因。

EsriConfirmedDomain/Subtype/Relationship 的产品语义。FastGdbConfirmed当前 MetadataReader 的结构化输出和系统表审计。Unknown未有样本的版本组合不能升级为支持。

Reader 生命周期

fast-gdb Reader 可能持有 mmap、文件描述符、Schema、TABLX 和索引页。外部写入前必须销毁 Reader 图，写入完成后重新扫描；源变化检测不是并发读写保证。

AI 审核题

AI 成功解析 GDB_Items 的 XML，便宣布支持 Attachment 和 Relationship。

审核要点：还需关联系统表、键、基数、方向、附件业务表、真实样本与失败诊断；XML 可读不等于结构化和行为完整。

闭卷复述

missing、empty、unreadable 为什么必须分开？

它们分别表示不存在、有效但无数据和解析失败；合并会把兼容或损坏问题伪装成正常结果。

Reader-only 与了解 freelist 是否矛盾？

不矛盾。理解 Writer 产生的磁盘状态有助于正确读取，但不意味着产品提供 Writer。
