Week 05 · GDBTABLE

同一个文件里，Schema 决定 Record 的读法

总体字节布局Schema 与 Record 边界版本和安全读取

不要把 `.gdbtable` 当成“连续行”。它先提供解释记录所需的表头和字段描述，再存放可变长度记录。

布局心智图

0 ─ File header
    ├─ version / flags / counts
    └─ field descriptor offset
        ↓
    Field descriptor section
    ├─ table/geometry metadata
    └─ ordered field descriptors
        ↓
    Record/data area
    ├─ length + row payload
    ├─ holes / reusable space
    └─ later records

具体字节宽度必须按版本和源码证据确认。这个图表达关系，不替代格式表。4GB 以上表和不同 configuration keyword 可能触发宽度或存储分支，不能从小样本外推。

标准答案提示

学习台中的 M05 标准答案直接展示 Header、Field Descriptor 和 Record/Data 区的标准布局，并区分已确认结构、版本分支和未知区域；证据实验会自动生成真实文件摘要，无需自行标图。

GdalConfirmedGDAL OpenFileGDB 源码提供可审计的表结构实现。DataObserved真实文件可确认值和偏移。Inferred只凭重复模式猜出的字段必须保留推断标签。
