## 3. 当前并发边界

| 场景 | 类型 | 断言 |
|---|---|---|
| Reader 关闭后 GDAL 写、再重开 | 正式门禁 | 必须读取新数据 |
| 已有 Reader + GDAL Writer | Characterization | 只记录 old/new/mixed/error |
| Writer 打开时新 Reader | Characterization | 只记录 old/new/mixed/error |
| GDALClose 后旧 Reader | Characterization | 只记录，不支持复用 |
| 销毁旧 Reader 后新开 | 正式门禁 | 必须读取新数据 |

ADR-008 当前仍不将重叠读写改为具有一致性保证的支持能力。实施计划进一步提出：
同进程统一管理的 Writer 先发布 `WriterPending`，停止新的 fast Reader，等待旧 mmap
Reader 安全退出后再开始修改；Pending/Active 期间可由调用方显式选择原生 GDAL
读取，但结果必须标记为 `UnverifiedConcurrentRead`，不能作为正确性结果。

## 4. Adaptive Reader 覆盖

| 场景 | 合同测试 | 断言 |
|---|---|---|
| 稳定 fast 读取 | `StableSourceUsesFastVerified` | fast-gdb，`Verified` |
| Writer Pending 阻断 fast | `WriterPendingStopsNewFastReads` | 新请求不增加 fast Reader 计数 |
| 旧 cursor 安全点过期 | `FastCursorExpiresAtNextSafePoint` | 关闭底层 Reader，返回 `ReaderExpired` |
| Pending 等待超时 | `PendingTimeoutClearsPendingAndRecovers` | 返回 `ReadersActive`、撤销 Pending，后续请求可恢复 |
| 更新许可条件 | `UpdatePermitRequiresFastReadersDrained` | fast Reader 归零后才允许调用方打开 update Dataset |
| Writer 打开失败 | `UpdateOpenFailureCancelsPending` | 调用方撤销 Pending，不增加 generation |
| Active 通知丢失 | `AbandonedActiveTokenRemainsFailClosed` | 不猜测 Writer 已结束，禁止新 fast Reader |
| 默认 Writer 策略 | `DefaultPolicyReturnsBusyWithoutCallingBackends` | `SourceBusy`，fast/GDAL 均不调用 |
| 显式 GDAL 并发策略 | `ExplicitPolicyUsesFreshGdalUnverified` | fresh GDAL，`UnverifiedConcurrentRead` |
| 未验证标记不可升级 | `UnverifiedResultIsNeverReportedVerified` | Writer 中途结束仍保持 Unverified |
| GDAL 错误 | `GdalFailureKeepsDiagnosticAndConsistency` | 明确 open/read/close 错误 |
| 关闭通知 | `ClosedUpdateNotificationIncrementsGeneration` | generation 增加，旧 Reader 过期 |
| 旧 Reader 写后失效 | `OldReaderExpiresAfterClosedUpdateNotification` | 旧对象图不得跨 generation 复用 |
| 写后恢复 | `PostWriteRebuildReturnsFastVerified` | 新 Reader 读取新 generation，`Verified` |
| 稳定源查询 parity | `AllQueryKindsMatchOnStableSource` | 全部 QueryKind 与 GDAL 对照 |
| REPACK 安全 | `RepackNeverOverlapsFastMmap` | fast Reader 计数非零时 Writer 不得启动 |
| 协调压力 | `MultipleReadersSingleWriterStress` | 无 mmap/Writer 重叠、无崩溃或死锁 |

adaptive-reader.gdal-unverified.*
adaptive-reader.parity.*

## 5. 构建矩阵

| 构建 | GDAL | 完整测试 | 目的 |
|---|---:|---:|---|
| Linear release | OFF | OFF/ON | 纯 Reader 和安装面 |
| Hybrid release | ON | OFF/ON | GDAL geometry fallback |
| Boundary | ON | OFF | 聚焦读写生命周期 |
| Full | ON | ON | Reader 回归与 parity |
| Sanitizer | 可选 | 选择性 | ASan/UBSan/LSan |
| Adaptive | ON | ON | coordinator/lease/fresh GDAL Reader 编排 |

Adaptive 构建已进入实现阶段，必须保持 `linear` 无 GDAL 依赖。当前本地验收基线为
GDAL 3.9.3；其它 GDAL 版本需单独验证。fast-gdb 只提供无 GDAL Writer 类型的外部更新协调令牌；
OpenFileGDB update Dataset 的打开、写入、Flush 和关闭全部由调用方负责。

## 6. 性能门禁

性能结果只有在以下条件全部满足时有效：

- 记录数和 FID 一致；
- 字段校验和一致；
- WKB/几何一致；
- final match 与 GDAL 一致；
- fast 性能数据没有 Reader/GDAL update 生命周期重叠；
- 记录 commit、平台、编译器、GDAL、manifest 和缓存状态。

`UnverifiedConcurrentRead` 的 GDAL 并发数据只能单独作为诊断 profile，不能和稳定
fast 路径合并为一个性能结论。Adaptive 性能计划还要求：

- 稳定路径只在 query 或 cursor 打开时读取协调状态，不在逐 Feature 热路径加锁；
- v1 不收集外部文件快照，只依赖同进程协调状态和 fast Reader 租约；
- 分别记录 FID lookup、顺序扫描、空间查询的额外延迟；
- 任何优化都不能绕过 Pending/Active 路由、租约排空和强制 Unverified 标记。

## 7. 明确删除的测试类别

- 自研 Writer 功能测试；
- VersionedGdbStore；
- Append/Update/Delete/Transaction/Recovery；
- Writer 性能；
- Writer package consumer；
- Writer macOS 专项工作流。

GDAL 写入测试的目标是验证 fast-gdb Reader 兼容性，不代表 fast-gdb 提供 Writer。
Adaptive Reader 测试验证路由、状态标记、租约、失效和写后恢复；Writer 活动期间的
GDAL 结果不验证业务一致性，只验证它始终携带 `UnverifiedConcurrentRead`。
