# 功能与基准测试覆盖矩阵

本文把“能力、测试代码、实际证据、数据、平台和 CI 门禁”放在同一张表中。测试数据生成和路径规则见[测试数据准备与跨平台验证指南](03_测试数据准备与跨平台验证.md)。

当前分支：`codex/spatial-attribute-query`。联合查询实现和测试代码已完成，三轮静态代码自审与文档自检已完成；由于构建和 Actions 证据缺失，状态仍为 **Code review ready / Formal acceptance blocked**。

## 状态定义

| 状态 | 含义 |
|---|---|
| `GATED` | 已在 CI 或正式门禁中执行，失败会阻断合并 |
| `CODE_READY` | 实现和测试代码完成，可进行代码审核，但尚无完整运行证据 |
| `OBSERVE` | 可重复执行并记录结果，暂不按耗时阻断 |
| `MANUAL` | 依赖外部数据、ArcGIS Pro、大磁盘或冷缓存环境 |
| `MISSING` | 尚未形成可复现的自动化证据 |
| `BOUNDARY` | 产品明确不支持或只提供降级行为，不属于测试遗漏 |

## 基准测试矩阵

| 场景 | 入口 | 数据规模 | 对照 | 状态 | 判定 |
|---|---|---:|---|---|---|
| 写入：GDAL 与 binary writer | Writer 既有 benchmark | 1K–10M | GDAL 或同平台 main | `OBSERVE` | 与本分支分开 |
| 顺序读取与零拷贝扫描 | `R1_*`、`R2_*` | 100K/10M | GDAL、per-record | `OBSERVE` | 记录 median/p95 和总要素数 |
| 空间密度矩阵 | `SpatialDensityBenchmark.*` | 1M/10M | current-vs-main、GDAL | 既有 `GATED` | current-vs-main 最大回退 5% |
| 属性查询 | `R5_*`、`R6_*` | 100K | GDAL | `OBSERVE` | FID 集合先一致，再比较耗时 |
| 空间与属性联合查询 | `SpatialWhereBenchmarkTest.Point100KSchemaV2Evidence` | 100K，10% bbox × 10% 属性 | 联合入口、旧式双查询求交、GDAL 联合过滤 | `CODE_READY` | 显式运行；逐 FID 一致后写实际 execution_path、correctness、median/p95 |
| 联合查询完整矩阵 | 尚未完成 | 100K 1%/10%/80%/100% + 10M 多几何 | current/main、GDAL | `MISSING` | 5% 回退门禁和外部 evidence |
| 35GB/5 亿级真实数据 | 尚无统一入口 | 生产级 | 无 | `MISSING` | 不从 10M 或长稳结果外推 |

普通功能回归不得默认执行耗时基准。联合查询基准由 `FAST_GDB_RUN_SPATIAL_WHERE_BENCHMARKS=1` 显式开启，原始结果只进入外部 evidence/artifact，不提交仓库。
