## 3. 当前并发边界

| 场景 | 类型 | 断言 |
|---|---|---|
| Reader 关闭后 GDAL 写、再重开 | 正式门禁 | 必须读取新数据 |
| 已有 Reader + GDAL Writer | Characterization | 只记录 old/new/mixed/error |
| Writer 打开时新 Reader | Characterization | 只记录 old/new/mixed/error |
| GDALClose 后旧 Reader | Characterization | 只记录，不支持复用 |
| 销毁旧 Reader 后新开 | 正式门禁 | 必须读取新数据 |

ADR-008 不将重叠读写改为支持能力，而是计划在协调模式下提前拒绝，在检测到变化时丢弃结果。

## 4. Planned Adaptive Reader 覆盖

| 场景 | 计划测试 | 目标断言 |
|---|---|---|
| Writer active | `WriterActiveReturnsBusyWithoutCallingEitherBackend` | `SourceBusy`，fast/GDAL 调用数为 0 |
| generation 变化 | `GenerationChangeExpiresExistingReader` | 旧 Reader 返回 `ReaderExpired` |
| 稳定 fast 读取 | `StableFastReadReturnsMaterializedFastResult` | 返回完整 fast 结果 |
| fast 期间源变化 | `ChangedSourceDiscardsFastResult` | 丢弃结果并记录变化文件 |
| fast 不支持且源稳定 | `StableUnsupportedFastReadUsesFreshGdal` | fresh GDAL 成功返回 |
| GDAL 期间源变化 | `ChangedSourceDuringGdalReadDiscardsFallbackResult` | 丢弃 GDAL 结果 |
| 写入完成 | `CompletedWriteFreshGdalReadsNewGeneration` | 读取完整新 generation |
| GDAL cache 隔离 | `FreshGdalFallbackDoesNotReuseCachedDataset` | 每次 fresh open/close |
| 协调压力 | `adaptive-reader.stress.*` | 只允许完整旧、完整新或 Busy；无 mixed、无崩溃 |
| 无协调外部 Writer | `adaptive-reader.uncoordinated.*` | best-effort 分类，不建立普遍保证 |

规划测试目标：

```text
fast_gdb_adaptive_reader_test_runner
adaptive-reader.unit.*
adaptive-reader.coordinated.*
adaptive-reader.uncoordinated.*
adaptive-reader.gdal-fallback.*
adaptive-reader.stress.*
```

上述 target 当前不存在。

## 5. 构建矩阵

| 构建 | GDAL | 完整测试 | 目的 |
|---|---:|---:|---|
| Linear release | OFF | OFF/ON | 纯 Reader 和安装面 |
| Hybrid release | ON | OFF/ON | GDAL geometry fallback |
| Boundary | ON | OFF | 聚焦读写生命周期 |
| Full | ON | ON | Reader 回归与 parity |
| Sanitizer | 可选 | 选择性 | ASan/UBSan/LSan |
| Adaptive | ON | 计划 | activity/snapshot/fresh GDAL Reader 编排 |

Adaptive 构建只有在 ADR-008 进入实现阶段后才允许增加，且必须保持 `linear` 无 GDAL 依赖、安装面无 Writer API。

## 6. 性能门禁

性能结果只有在以下条件全部满足时有效：

- 记录数和 FID 一致；
- 字段校验和一致；
- WKB/几何一致；
- final match 与 GDAL 一致；
- 没有 Reader/GDAL update 生命周期重叠；
- 记录 commit、平台、编译器、GDAL、manifest 和缓存状态。

Adaptive 性能计划还要求：

- 协调模式只增加两次轻量 activity/generation 观察；
- 文件快照按查询依赖收集，不默认哈希整个 GDB；
- 分别记录 FID lookup、顺序扫描、空间查询的额外延迟；
- 任何优化都不能绕过 fail-closed、结果物化和读取后校验。

## 7. 明确删除的测试类别

- 自研 Writer 功能测试；
- VersionedGdbStore；
- Append/Update/Delete/Transaction/Recovery；
- Writer 性能；
- Writer package consumer；
- Writer macOS 专项工作流。

GDAL 写入测试的目标是验证 fast-gdb Reader 兼容性，不代表 fast-gdb 提供 Writer。Adaptive Reader 测试也只验证读取、拒绝、失效和只读恢复。
