# 功能与基准测试覆盖矩阵

本文把“能力、测试证据、数据、平台和 CI 门禁”放在同一张表中。测试数据的生成和路径规则见[测试数据准备与跨平台验证指南](03_测试数据准备与跨平台验证.md)；本矩阵只记录覆盖状态和缺口。

## 状态定义

| 状态 | 含义 |
|---|---|
| `GATED` | CI 中执行，正确性失败会阻断合并 |
| `OBSERVE` | 可重复执行并记录结果，暂不按耗时阻断 |
| `MANUAL` | 依赖外部数据、ArcGIS Pro、大磁盘或冷缓存环境 |
| `MISSING` | 尚未形成可复现的自动化证据 |
| `BOUNDARY` | 产品明确不支持或只提供降级行为，不属于测试遗漏 |

## 功能测试矩阵

| 能力域 | 主要证据 | 数据 | 平台/门禁 | 当前状态 | 后续缺口 |
|---|---|---|---|---|---|
| 二进制基础类型、UTF-16、varint、OLE DATE | `BinaryReaderTest.*`、`Utf16Test.*`、`VarintTest.*`、`OleDateTest.*` | 内存合成 | Linux/macOS/Windows 纯 C++ | `GATED` | 仅保留极端平台时间跳过 |
| Catalog、`.gdbtable`、`.gdbtablx`、`.gdbindexes` | `GdbCatalogTest.*`、`GdbTableTest.*`、`GdbTablxTest.*`、`GdbIndexesTest.*`、`FullAuditTest.*` | 合成 + 本地 `test_spatial_gdb.gdb` | 纯 C++核心门禁；真实样本本地验收 | `GATED`/`MANUAL` | 增加损坏文件分类报告 |
| 几何 Point/MultiPoint/Line/Polygon、Z/M/ZM | `geometry.*`、`GeometryContract*`、`WriterTest.*` | 合成 + 普通 GDB | 三平台纯 C++ | `GATED` | 增加跨编译器 WKB 快照 |
| CircularArc/Bezier/EllipticArc 线性化 | `CurveGeometry*`、`RealDataReleaseContractTest.*` | 合成 + 本地 `testcurve.gdb` | 三平台合成门禁；ArcGIS Pro 数据手工验收 | `GATED`/`MANUAL` | 原生 curve WKB 仍为实验能力 |
| 空间索引与精确查询 | `SpatialIndexTest.*`、`SpatialQueryAdaptiveTest.*`、`QueryEngineIntegrationTest.*` | 普通 GDB + 1K/100K 矩阵 | Linux CI；Windows 专项 | `GATED` | 增加 polygon 1M/10M 矩阵 |
| 属性索引与 WHERE | `AttributeIndexTest.*`、`NumericQueryTest.*`、`StringQueryTest.*` | 合成 + 普通 GDB | Linux GDAL CI | `GATED` | 外部真实字段类型差异 |
| metadata、SRS、domain、relationship 摘要 | `MetadataReaderTest.*`、`MetadataReaderIntegrationTest.*` | 合成 + 普通 GDB | Linux GDAL CI | `GATED` | relationship join/级联属于范围外 |
| usegdal 数据源、字段、查询、事务、连接池 | `T_Datasource_*`、`T_Query_*`、`T_Transaction_*`、`T_Pool_*` | GDAL 临时 GDB | Linux GDAL CI | `GATED` | Windows/macOS GDAL 完整回归列为 P1 |
| writer 二进制追加、几何序列化、索引创建 | `WriterTest.*`、`IndexCreatorTest.*` | 临时可重建 GDB | Linux GDAL CI | `GATED` | 系统表同步、原地删除和完整编辑仍为 `BOUNDARY` |

## 基准测试矩阵

| 场景 | 入口 | 数据规模 | 对照 | 状态 | 判定 |
|---|---|---:|---|---|---|
| 写入：GDAL single/batch 与 binary writer | `PerformanceBenchmarkFixture.W1_*`、`W2_*`、`W3_*`、`WriterTest.T_W03_BulkWritePerformance` | 1K/10K/100K/1M/10M | GDAL 或同分支历史值 | `OBSERVE` | 先校验数量、重开读取和索引 |
| 顺序读取与零拷贝扫描 | `R1_*`、`R2_*` | 100K/10M | GDAL、per-record | `OBSERVE` | 记录 median/p95 和总要素数 |
| 空间密度矩阵 | `SpatialDensityBenchmark.*` | 1M/10M | current-vs-main、GDAL | `GATED` | current-vs-main 最大回退 5% |
| 属性查询 | `R5_*`、`R6_*` | 100K | GDAL | `OBSERVE` | FID 集合先一致，再比较耗时 |
| 索引创建 | `benchmark_index_creation <gdb_path>`、`IndexCreatorTest.*` | 100K | GDAL/历史值 | `OBSERVE` | 输出耗时、文件和查询正确性 |
| 完整工作流 | `C1_*`–`C6_*` | 100K | GDAL、binary writer | `OBSERVE` | 写入、索引、读取、查询全链路通过 |
| Windows mmap/异步/冷缓存 | `run_spatial_acceptance.ps1` | 1M/10M | main A/B | `MANUAL` | 只有提供 RAMMap 才能声明 strict-cold |
| 内存、并发、长稳、35GB/5亿级 | 尚无统一入口 | 生产级 | 多平台 | `MISSING` | 后续性能专项 |

普通功能回归不得默认执行耗时基准；读写、索引和完整工作流由 `FAST_GDB_RUN_FULL_BENCHMARKS=1` 显式开启，空间查询仍由 `FAST_GDB_RUN_SPATIAL_BENCHMARKS=1` 控制。空间 current-vs-main 脚本已经输出 CSV；读写/索引基准本轮先保留现有控制台结果，统一 JSON/CSV 结果格式列为下一步基准工具任务。目标字段为：代码版本、平台、编译器、GDAL 版本、数据 manifest、场景、缓存状态、采样次数、median、p95、吞吐量、结果数、正确性状态和基线差异。

## CI 分层

| 层级 | 运行内容 | 频率 |
|---|---|---|
| 核心门禁 | 三平台纯 C++ 几何 + Linux GDAL 功能回归；本地 fixture 契约按环境启用 | push/PR |
| 空间门禁 | Linux/macOS current-vs-main 10M；Windows mmap/I/O | 相关 PR/手工 |
| 真实数据验收 | ArcGIS 曲线、外部业务 GDB、完整矩阵 | 发布前/手工 |
| 性能专项 | 内存、并发、长稳、生产级规模 | 后续专项 |
