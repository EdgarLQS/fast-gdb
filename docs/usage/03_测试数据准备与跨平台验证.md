# 测试数据准备与跨平台验证指南

本文是 fast-gdb 测试数据和验证流程的权威入口。新环境先执行“最小验证”，再根据目标选择真实数据、性能或 Windows 专项验收；数据集内部字段和历史结果仍由各专题文档记录。

## 1. 数据分层与清单

所有相对路径均以仓库根目录为起点。大型数据按需生成并复用，不要求提交到版本库。

| 层级 | 数据集 | 典型规模 | 随仓库提供 | 生成方式 | 主要用途 |
|---|---|---:|:---:|---|---|
| 小型正确性 | `test_data/gdb/test_spatial_gdb.gdb/test_spatial_gdb.gdb` | 约 2.8 MB，双层 `.gdb` 包装 | 否，本地准备 | GDAL/外部样本副本 | catalog、table/tablx/index、空间查询、普通真实数据契约 |
| ArcGIS 曲线 | `test_data/gdb/testcurve.gdb` | 约 42 MB、44 图层、约 112 万要素 | 否，本地准备 | ArcGIS Pro `arcpy` | 曲线、Z/M/ZM、FID 间断、坏拓扑、CRS、真实发布契约 |
| GDAL 基准 | `test_data/large/large_test.gdb` | 默认 100 万要素，约 191 MB | 按工作副本而定 | `generate_large_gdb` | 100K/1M 空间查询、GDAL 对照、索引工具 |
| GDAL 10M | `test_data/large_10m/large_10m_test.gdb` | 1000 万要素，约 1.9 GB | 按工作副本而定 | `generate_large_gdb` | 10M 性能和 main 分支回归 |
| 空间矩阵 | `test_data/spatial_matrix/*.gdb` | 1K 至 10M；当前完整矩阵约 4.2 GB | 按工作副本而定 | `generate_large_gdb` 分类型生成 | Point/MultiPoint/Line/Polygon、不同规模和覆盖率基准 |
| Windows 矩阵 | `test_data/spatial_matrix/windows/*.gdb` | 由验收清单决定 | 否 | GDAL 生成后复制到 Windows | mmap、异步 I/O、冷/热缓存 A/B 验收 |
| 外部真实数据 | 任意只读 `.gdb` 目录 | 不限 | 否 | 用户提供 | 目标业务数据、特殊 schema、发布前兼容验证 |

`test_data/gdb/zip/testcurve.gdb.zip` 是曲线数据的归档副本；除非测试明确要求压缩包，否则应传解压后的 `.gdb` 目录。实际占用随 GDAL/ArcGIS Pro 版本和生成参数变化，生成 10M 或完整矩阵前应至少预留输出规模两倍的空间。

普通样本只在本地测试环境准备，不提交到仓库；外层目录是仓库布局，真正的数据源是内层 FileGDB 目录。该样本约 2.8 MB，用于 catalog、表、索引、空间查询和普通真实数据契约。曲线样本和所有大型数据同样按需提供，不作为普通 CI 的必备输入。

## 2. 环境与构建

### 2.1 通用依赖

- Windows、Linux、macOS：C++17、CMake 3.15+；
- 纯 C++ 正确性测试不要求 GDAL；
- 数据生成、GDAL 对照、Hybrid 和索引工具要求 GDAL，且 `OpenFileGDB` 驱动可用；
- ArcGIS 原生曲线数据生成只支持装有 ArcGIS Pro 3.x 和 `arcpy` 的 Windows。

先检查 GDAL：

```bash
gdalinfo --version
ogrinfo --formats | grep -i OpenFileGDB
```

PowerShell 使用：

```powershell
gdalinfo --version
ogrinfo --formats | Select-String OpenFileGDB
```

通用完整测试构建：

```bash
cmake -S . -B build \
  -DFAST_GDB_WITH_GDAL=ON \
  -DFAST_GDB_BUILD_TOOLS=ON \
  -DFAST_GDB_BUILD_FULL_TESTS=ON \
  -DBUILD_TESTING=ON
cmake --build build --parallel
```

Windows 多配置生成器在命令末尾增加 `--config Release`，可执行文件通常位于 `build/bin/Release/`；下文 POSIX 命令中的 `build/bin/` 应相应替换。

## 3. 分级验证

### 3.1 最小验证：新环境必跑

无需外部真实数据或大规模生成：

```bash
ctest --test-dir build --output-on-failure -R '^(geometry|hybrid)\.'
./build/bin/gdb_tutorial_test_runner \
  --gtest_filter='GdbCatalogTest.*:FullAuditTest.*:GdbTableTest.*:GdbTablxTest.*:GdbIndexesTest.*:SpatialIndexTest.*'
```

通过标准：命令退出码为 0；不得出现崩溃或断言失败。因未启用可选基准而出现明确的 `GTEST_SKIP` 是合理跳过。

### 3.2 完整回归

```bash
ctest --test-dir build --output-on-failure
```

该命令执行功能回归；读写和完整工作流基准默认跳过。需要显式运行基准时使用：

```bash
FAST_GDB_RUN_FULL_BENCHMARKS=1 \
./build/bin/gdb_tutorial_test_runner --gtest_filter='PerformanceBenchmarkFixture.*:WriteBenchmarkFixture.*:WriterTest.T_W03_BulkWritePerformance'
```

本地同时准备普通或曲线 `.gdb` 后，可运行真实数据契约：

```bash
FAST_GDB_REAL_DATASET="$PWD/test_data/gdb/test_spatial_gdb.gdb/test_spatial_gdb.gdb" \
FAST_GDB_CURVE_DATASET="$PWD/test_data/gdb/testcurve.gdb" \
./build/bin/gdb_tutorial_test_runner --gtest_filter='RealDataReleaseContractTest.*'
```

如需直接查看全部用例及跳过原因：

```bash
./build/bin/gdb_tutorial_test_runner --gtest_list_tests
./build/bin/gdb_tutorial_test_runner
```

### 3.3 普通与曲线真实数据

POSIX：

```bash
FAST_GDB_REAL_DATASET="$PWD/test_data/gdb/test_spatial_gdb.gdb/test_spatial_gdb.gdb" \
FAST_GDB_CURVE_DATASET="$PWD/test_data/gdb/testcurve.gdb" \
./build/bin/gdb_tutorial_test_runner --gtest_filter='RealDataReleaseContractTest.*'
```

PowerShell：

```powershell
$env:FAST_GDB_REAL_DATASET = (Resolve-Path 'test_data/gdb/test_spatial_gdb.gdb/test_spatial_gdb.gdb').Path
$env:FAST_GDB_CURVE_DATASET = (Resolve-Path 'test_data/gdb/testcurve.gdb').Path
& .\build\bin\Release\gdb_tutorial_test_runner.exe --gtest_filter='RealDataReleaseContractTest.*'
```

普通样本必须指向双层包装的内层 `.gdb`。外部数据可替换环境变量路径，但普通变量应指向非曲线样本，曲线变量应指向 GDAL 能识别出曲线的 FileGDB。

### 3.4 性能基准

100K/1M 基准：

```bash
FAST_GDB_RUN_SPATIAL_BENCHMARKS=1 \
./build/bin/gdb_tutorial_test_runner --gtest_filter='SpatialDensityBenchmark.*'
```

10M 基准必须显式开启，避免普通测试意外消耗大量时间：

```bash
FAST_GDB_RUN_SPATIAL_BENCHMARKS=1 \
FAST_GDB_RUN_10M_BENCHMARKS=1 \
./build/bin/gdb_tutorial_test_runner --gtest_filter='SpatialDensityBenchmark.DensityMatrix10M'
```

对指定数据执行覆盖率矩阵：

```bash
FAST_GDB_RUN_SPATIAL_BENCHMARKS=1 \
FAST_GDB_BENCHMARK_PATH="$PWD/test_data/spatial_matrix/point_10000000.gdb" \
FAST_GDB_BENCHMARK_LABEL='local / point / 10m / warm' \
FAST_GDB_BENCHMARK_TRIALS=20 \
./build/bin/gdb_tutorial_test_runner \
  --gtest_filter='SpatialDensityBenchmark.DensityMatrixConfigured'
```

`FAST_GDB_BENCHMARK_CASE` 可限定 `coverage_01pct`、`coverage_10pct`、`coverage_30pct`、`coverage_80pct` 或 `coverage_full`。当前分支与 main 的 POSIX 回归使用：

```bash
python3 scripts/run_spatial_regression.py \
  --current-build build-current \
  --baseline-build build-main \
  --gdb test_data/spatial_matrix/point_10000000.gdb \
  --output benchmark-results
```

### 3.5 Windows 冷缓存与 I/O 验收

Windows 专项脚本会设置 I/O 环境变量、运行 20 次采样并输出 CSV/日志：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/windows/run_spatial_acceptance.ps1 `
  -BuildDir build -DataRoot test_data/spatial_matrix/windows `
  -RamMapPath 'C:\Tools\RAMMap64.exe'
```

该脚本同时执行 cold 和 warm 场景，因此必须通过 `-RamMapPath` 提供 Sysinternals RAMMap；脚本会通过 `FAST_GDB_BENCHMARK_CACHE_CLEAR_COMMAND` 调用它。没有 RAMMap 时不要运行整套脚本，可按 3.4 节手动执行 warm/fresh-open 场景，但不得把 OS page cache 未清除的结果标记为 strict-cold。主分支 A/B 对照使用 `scripts/windows/run_spatial_main_ab.ps1`，具体参数以脚本的 `Get-Help` 和 `docs/evidence/spatial-query-acceptance-test-plan.md` 为准。

## 4. 使用 GDAL 生成数据

`generate_large_gdb` 使用 GDAL OpenFileGDB，随机种子固定为 `42`；相同参数可复现数据分布。若目标目录已存在且图层、几何类型、数量和 `.spx` 完整，生成器会复用它，否则重建目标数据。

```bash
cmake --build build --target generate_large_gdb --parallel

./build/bin/generate_large_gdb \
  --count 1000000 --geometry polygon --distribution uniform \
  --output test_data/large/large_test.gdb

./build/bin/generate_large_gdb \
  --count 10000000 --geometry point --distribution uniform \
  --output test_data/large_10m/large_10m_test.gdb
```

空间矩阵按同一规则分别指定 `point`、`multipoint`、`line`、`polygon` 和 1K/10K/100K/1M/10M 数量。不要让多个进程同时写同一 `.gdb`。生成后至少执行：

```bash
ogrinfo -so test_data/large/large_test.gdb features
./build/bin/verify_gdal_indexes test_data/large/large_test.gdb
```

索引实验工具必须显式接收路径：

```bash
./build/bin/verify_gdal_indexes <gdb_path>
./build/bin/benchmark_index_creation <gdb_path>
./build/bin/generate_100k_polygons <output_gdb_path>
```

`benchmark_index_creation` 和 `generate_100k_polygons` 会修改目标数据，仅对可重建副本运行，不要直接用于唯一的业务数据。

## 5. 使用 ArcGIS Pro 生成专属数据（仅 Windows）

GDAL 适合生成常规几何和规模数据；原生 CircularArc/Bezier、M-enabled 曲线、ArcGIS FID 行为和自动拓扑修复应使用 ArcGIS Pro 3.x 的 `arcpy`。完整的 44 图层、字段和预期结果见 `tests/createdata/DATASET_GUIDE.md`。

使用 ArcGIS Pro 自带 Python 执行，不要使用普通系统 Python：

```powershell
$env:FAST_GDB_ARCPY_OUTPUT = 'C:\fast-gdb-data\testcurve.gdb'
& 'C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe' `
  tests\createdata\generate_all_data.py
```

脚本会删除并重建目标内容，必须先确认 `GDB` 指向可重建测试目录。输出包括图层清单、FID 映射、关键几何预期、空间查询用例和 manifest；生成后用 ArcGIS Pro 打开，确认曲线、空间索引和要素数，再设置 `FAST_GDB_CURVE_DATASET` 运行真实数据契约。

## 6. 环境变量总表

| 变量 | 用途/值 |
|---|---|
| `FAST_GDB_REAL_DATASET` | 普通外部 `.gdb` 目录；启用普通真实数据契约 |
| `FAST_GDB_CURVE_DATASET` | 含原生曲线的 `.gdb`；启用曲线真实数据契约 |
| `FAST_GDB_ARCPY_OUTPUT` | ArcGIS Pro 生成脚本的可重建 `.gdb` 输出路径 |
| `FAST_GDB_RUN_SPATIAL_BENCHMARKS=1` | 总体性能基准开关 |
| `FAST_GDB_RUN_FULL_BENCHMARKS=1` | 读写、索引和完整工作流基准开关；普通功能回归不设置 |
| `FAST_GDB_RUN_10M_BENCHMARKS=1` | 允许 10M 慢基准 |
| `FAST_GDB_BENCHMARK_PATH` | 配置型矩阵的输入 `.gdb` |
| `FAST_GDB_BENCHMARK_LABEL` | 输出中的平台/数据/缓存标签 |
| `FAST_GDB_BENCHMARK_CASE` | 只运行一个覆盖率用例 |
| `FAST_GDB_BENCHMARK_TRIALS` | 采样次数，脚本默认 20 |
| `FAST_GDB_BENCHMARK_MODE=fresh-open` | 每次样本重新打开数据 |
| `FAST_GDB_BENCHMARK_STRICT_COLD=1` | 声明严格冷缓存；必须同时提供清缓存命令 |
| `FAST_GDB_BENCHMARK_CACHE_CLEAR_COMMAND` | 每个样本前执行的 OS 缓存清理命令 |
| `FAST_GDB_SPATIAL_PROFILE=1` | 输出查询漏斗和 I/O profile |
| `FAST_GDB_SPATIAL_DIRECT_SCAN_COVERAGE` | 高覆盖率直接扫描阈值，默认 `0.35` |
| `FAST_GDB_SPATIAL_SCAN_DENSITY` | 候选密度扫描阈值，默认 `0.50` |
| `FAST_GDB_TABLX_CACHE=0` | 基准中绕过进程内 tablx 缓存 |
| `FAST_GDB_WINDOWS_MMAP` | Windows mmap 路径开关 |
| `FAST_GDB_WINDOWS_ASYNC_IO` | Windows 异步 I/O 路径开关 |
| `FAST_GDB_WINDOWS_ASYNC_DEPTH` | 异步读取深度 |
| `FAST_GDB_WINDOWS_BATCH_MB` | fallback 批读取大小 |
| `FAST_GDB_WINDOWS_SPARSE_WINDOW_MB` | 稀疏 mmap window 大小 |
| `FAST_GDB_WINDOWS_FULL_MMAP_MAX_MB` | full mmap 文件大小上限 |
| `FAST_GDB_WINDOWS_IO_TRACE=1` | 输出 Windows I/O 跟踪 |

`FAST_GDB_FORCE_MMAP_FAILURE`、`FAST_GDB_FORCE_WINDOWED_MMAP` 和 `FAST_GDB_FORCE_ASYNC_LAUNCH_FAILURE` 仅用于故障注入测试，不是正常基准配置。

## 7. 三方交叉验证与通过标准

| 检查项 | fast-gdb | GDAL | ArcGIS Pro | 通过标准 |
|---|---|---|---|---|
| Schema/数量 | catalog、table parser | `ogrinfo -so` | Catalog/属性表 | 图层、字段、要素数一致 |
| FID | 0-based row FID | 常见为 1-based OID | ObjectID | 按已声明 offset 映射后集合完全一致，无重复 |
| 几何 | WKB/model、bbox、Z/M | WKB/WKT、extent | Shape/JSON | 类型、空几何、bbox、Z/M 状态和容差内坐标一致 |
| 曲线 | 内置线性化/Hybrid | 驱动能力范围内对照 | 原生曲线权威来源 | 不静默错读；降级和 fallback 有明确状态 |
| 索引 | `.spx/.atx` 解析和查询 | OpenFileGDB 查询 | Add/Rebuild Spatial Index | 查询 FID 集合一致，索引文件可打开 |
| 性能 | median/p95、漏斗 | 同进程参考 | 非强制 | 同数据、同查询、同缓存状态；无正确性差异再比较耗时 |

任何数量相同但 FID 集合不同、重复 FID、非法几何增加、异常退出或未声明的 fallback 都判为失败。性能结果必须记录操作系统、CPU、存储介质、编译类型、GDAL 版本、数据 manifest、查询覆盖率、采样次数和缓存状态，不能把不同平台的绝对耗时直接视为回归。

## 8. 跳过规则与故障处理

- 无 GDAL：使用 `FAST_GDB_WITH_GDAL=OFF` 验证纯 C++ 目标；GDAL/Hybrid/生成器和三方对照不属于本次结果。
- 无 ArcGIS Pro：可使用随仓库曲线样本回归，但不能声明“重新生成的 ArcGIS 原生曲线验收”。
- 无外部真实数据：相关契约明确 `GTEST_SKIP` 合理；仓库自带小型样本仍必须通过。
- 无 10M 数据或磁盘不足：10M/完整矩阵跳过合理，不影响正确性测试；报告中必须注明未测规模。
- 缺少严格清缓存工具：只能报告 warm/fresh-open，不得报告 strict-cold。
- 数据路径不存在：先确认传入的是 `.gdb` 目录而不是父目录或 zip；普通样本尤其要注意双层路径。
- OpenFileGDB 不可用：检查 GDAL 安装和 `ogrinfo --formats`，不要用其他驱动生成后假定格式等价。

最终验收记录至少包含：数据路径与来源、生成参数/manifest、执行命令、通过/失败/跳过数量、GDAL 和 ArcGIS Pro 版本、FID/几何差异、基准 CSV/日志位置。历史基准和 Windows 验收模板见 `docs/evidence/`。
