# fast-gdb Reader 组件设计与使用

## 1. 当前产品组件

fast-gdb 当前只提供两个 Reader 产品：

```text
fast_gdb::linear
    纯 C++ FileGDB Reader

fast_gdb::hybrid
    fast-gdb Reader 主路径
    + GDAL 复杂几何回退
```

`src/edgar/usegdal` 是保留的 GDAL/OGR 历史包装参考目录，不由根 CMake 构建，不安装、不导出，也不构成 FileGDB Writer 产品。目录中存在 `GdbBatchWriter`、`GdbTransaction` 等探索代码，仅供参考；fast-gdb 不对这些类型提供产品 API、ABI 或运行时保证。

生产编辑应直接调用官方 GDAL/OpenFileGDB API。详见 [`src/edgar/usegdal/README.md`](../../src/edgar/usegdal/README.md)。

## 2. Optional Adaptive Reader

ADR-008 已 Accepted，`fast_gdb::adaptive` 是需要 GDAL 的可选 Reader 编排 target，默认关闭。它的当前合同是同进程协调、Busy、Reader 过期和 fresh fallback；未知外部 Writer 检测仍为 best-effort。

其目标不是写入或边写边读，而是：

```text
稳定源
→ fast-gdb 快路径

活动 Writer
→ SourceBusy
→ fast/GDAL 均不调用

读取期间源变化
→ 丢弃结果
→ 旧 Reader 过期

写入结束且源稳定
→ fresh GDAL read-only
→ 完整物化并 GDALClose
→ 前后校验一致后返回
```

协调模式由调用方提供只读的 `writer_active/generation`。无协调外部 Writer 只能做 best-effort 文件变化检测，不能保证绝对发现。

## 3. 读取对象层次

```text
GdbCatalog
    └── CatalogResolver
            └── ResolvedTable
                    └── GdbTableParser
                            ├── FeatureRecord
                            ├── GeometryValue
                            └── QueryEngine / FeatureCursor
```

### 生命周期规则

- `FeatureCursor` 的生命周期不得超过对应 `QueryEngine`；
- `QueryEngine` 使用的表、catalog 和解析结果必须保持有效；
- mmap、fd/HANDLE 和索引页面缓存由对应 Reader 对象拥有；
- 对目标 GDB 进行外部写入前，当前合同要求销毁整条 Reader 对象链；
- 未来 Adaptive 模式检测到 generation 或依赖文件变化时，也必须使整条对象链过期，不能局部 refresh。

## 4. 基本读取

```cpp
#include "gdb_catalog.h"
#include "catalog_resolver.h"
#include "gdb_table.h"

GdbCatalog catalog;
if (!catalog.scan("data.gdb")) return false;

CatalogResolver resolver(catalog);
if (!resolver.load()) return false;

const auto resolved = resolver.resolve("cities");
if (!resolved) return false;

GdbTableParser table(resolved->table_path);
if (!table.open()) return false;
if (!table.load_tablx(resolved->tablx_path)) return false;

FeatureRecord record;
if (table.read_record_by_fid(0, record)) {
    // consume fields
}
```

## 5. 完整要素和 WKB-first

```cpp
FeatureRecord record;
GeometryValue geometry;
if (table.read_feature_by_fid(0, record, geometry)) {
    if (geometry.valid()) {
        consume_wkb(geometry.wkb);
    }
}
```

WKT 是按需调试输出：

```cpp
const auto wkt = geometry.to_wkt();
```

Adaptive 读取若需要前后源校验，必须先把结果复制为自有数据，不能先向调用方暴露 `FieldRef`、mmap 指针、row buffer 视图或活动 cursor。

## 6. 查询

```cpp
QueryEngine engine(catalog, *resolved);
if (!engine.open()) return false;

QueryRequest request;
request.kind = QueryKind::SpatialWhere;
request.xmin = 0;
request.ymin = 0;
request.xmax = 100;
request.ymax = 100;
request.where_clause = "population >= 1000";

FeatureCursor cursor = engine.open_cursor(request);
QueryFeature feature;
while (cursor.next(feature)) {
    consume(feature);
}
```

`.spx` 和 `.atx` 仅用于生成候选；最终结果必须执行完整属性和几何复核。

## 7. 多线程读取

推荐每个线程独立创建 Reader 对象：

- 不共享 `GdbTableParser`；
- 不共享活动 `FeatureCursor`；
- 不共享可变 `QueryEngine`；
- 只共享不可变配置和业务层路由信息。

未来协调模式的 `WriterActivityProbe` 可以由调用方线程安全共享，但它只暴露活动状态和 generation，不管理写入。

## 8. 外部 GDAL 编辑

fast-gdb 不提供写入 API。当前调用 GDAL update 前：

1. 停止新查询；
2. 等待所有 cursor 结束；
3. 销毁 QueryEngine、table 和 catalog；
4. 关闭 mmap 和文件句柄；
5. 使用 GDAL/OpenFileGDB 独占编辑；
6. `GDALClose()`；
7. 从零重建 Reader。

同一个 `.gdb` 目录的 GDAL 写入和 fast-gdb 并发读取不支持。详见 [GDAL 写入与 fast-gdb 读取边界](../testing/03_GDAL边界与读写测试.md)。

`usegdal` 参考层中的代码不能绕过上述生命周期合同，也不应用作正式边界测试或 Adaptive recovery 依赖；正式路径直接调用 GDAL API。

## 9. CMake 使用

### Linear

```cmake
find_package(fast_gdb 0.1 CONFIG REQUIRED)
target_link_libraries(my_reader PRIVATE fast_gdb::linear)
```

### Hybrid

```cmake
find_package(fast_gdb 0.1 CONFIG REQUIRED)
target_link_libraries(my_reader PRIVATE fast_gdb::hybrid)
```

当前不存在 `fast_gdb::writer` 或可链接的 `usegdal` 产品 target。`fast_gdb::adaptive` 已加入可选安装面，但仍需独立完成跨平台、压力、性能和多 GDAL 版本验收。
