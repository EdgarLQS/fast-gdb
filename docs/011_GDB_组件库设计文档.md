### 与原设计的偏差

| 偏差 | 原因 |
|------|------|
| GdbField 使用 `std::variant` 而非 `union` | 类型安全，避免手动类型标记管理 |
| GdbQuery 拆分为 `GdbQueryBuilder` + `GdbQueryParameter` | 关注点分离，构建器与参数解耦 |
| GdbBatchWriter 不持事务锁 | OpenFileGDB 不原生支持事务，由调用方通过连接池隔离 |
| GdbWorkspace 未实现 | 非核心能力，可在需要时补充 |
| 测试数比原设计多 | 原子化拆分更细，每个类独立测试 |
| GdbQuery 空间关系支持 4 种（Intersects/Contains/Within/Disjoint） | GDAL SetSpatialFilter 仅支持 bbox 相交，其他关系需在 Recordset::moveNext() 中后过滤，这是开源界标准做法 |

## Context

用户已完成 GDB 教程（001~010，27 个测试用例），现基于 SuperMap iObjects 的 Datasource→Dataset→Recordset 三层模式，设计 C++ 组件库封装 GDAL GDB 操作。**设计完整，实现分阶段**。组件与教程放在同一目录（fast_gdb/）。

## 核心设计原则

### 1. 生命周期规则（铁律）

```
GdbDatasource — 拥有 GDALDataset*（唯一所有者）
    └── GdbDatasets — 非拥有视图，持有 GdbErrorContext*（生命周期 ≤ datasource）
        └── GdbDataset — 非拥有视图，持有 GdbErrorContext*（生命周期 ≤ datasource）
            └── GdbRecordset — 非拥有视图，持有 GdbErrorContext*（生命周期 ≤ datasource）
```

### 2. 线程安全模型

**对象级不线程安全**：同一个 GDALDataset/OGRLayer/OGRFeature 不跨线程共享。

**多线程读取模式**：通过连接池为每个线程分配独立的 GdbDatasource（各自 GDALOpenEx 打开）。

**GdbConnectionPool 是唯一线程安全的对象**（acquire/release 有 mutex 保护）。

### 3. GDAL 行为忠实映射

- 不承诺 GDAL 不支持的能力
- 事务：先检测 capability，不支持则明确返回失败
- Recordset：GDAL 的 OGRLayer 是顺序游标，Phase 1 只提供 moveFirst/moveNext

## 错误处理策略（共享指针模型）

**只有 GdbDatasource 继承 GdbErrorContext**。所有视图对象持有 `GdbErrorContext* m_errorCtx` 指针，通过 `getLastError()` 转发到 datasource 的错误上下文。

```cpp
class GdbErrorContext {
public:
    void setError(const std::string& msg) { m_lastError = msg; }
    std::string getLastError() const { return m_lastError; }
    void clearError() { m_lastError.clear(); }
protected:
    std::string m_lastError;
};

// GdbDatasource 是唯一所有者，继承错误上下文
class GdbDatasource : public GdbErrorContext { ... };

// 视图对象持有指针，转发调用
class GdbDatasets {
public:
    std::string getLastError() const { return m_errorCtx ? m_errorCtx->getLastError() : ""; }
protected:
    GdbErrorContext* m_errorCtx = nullptr;
};
// GdbDataset、GdbRecordset 同理
```

## Phase 1B：事务能力检测

### 1B.1 GdbDatasource 事务方法

在 GdbDatasource 中新增（m_inTransaction 字段已存在于 1.3）：

```cpp
    bool beginTransaction();
    bool commitTransaction();
    bool rollbackTransaction();
    bool isInTransaction() const { return m_inTransaction; }
```

**实现策略**：
1. beginTransaction() 检查 `supportsTransactions() || supportsEmulatedTransactions()`
2. 若都不支持，返回 false 并设置 `"Transactions not supported by this datasource"`
3. 调用 `GDALDataset::StartTransaction()`，成功后设 `m_inTransaction = true`
4. commitTransaction() 调用 `GDALDataset::CommitTransaction()`，设 `m_inTransaction = false`
5. rollbackTransaction() 调用 `GDALDataset::RollbackTransaction()`，设 `m_inTransaction = false`
6. 任何调用失败时，也设 `m_inTransaction = false`（组件状态复位，并记录错误；不保证驱动内部状态仍可继续使用）

### 1B.2 GdbTransaction（RAII 封装）

## 关键实现细节（经验总结）

### OGRLayer 共享状态问题

OGRLayer 维护持久状态，这是实现过程中踩到的最大坑：

- **滤镜持久化**：`SetAttributeFilter()`/`SetSpatialFilter()` 设置在 Layer 上，不因新 GdbRecordset 而清除
- **共享游标**：`GetNextFeature()` 推进 Layer 级游标，同一 Layer 的多个 Recordset 共享位置
- **解决方案**：
  - `getRecordset()` 中调用 `ResetReading()` 确保新游标从头开始
  - `update()` 中调用 `ResetReading()` 防止游标越界
  - `query()` 执行前清除旧滤镜再应用新查询

### OpenFileGDB 驱动限制

| 限制 | 表现 | 应对 |
|------|------|------|
| 不支持原生事务 | StartTransaction 返回失败 | 组件不封装 begin()，BatchWriter 不调用事务 |
| 自动转换线/面几何 | wkbLineString→wkbMultiLineString，wkbPolygon→wkbMultiPolygon | 测试中接受两种类型 |
| Integer64 存为 Float64 | 读取时类型不匹配 | 测试用 Real 字段 + 容差比较 |

### 线程安全边界

GdbConnectionPool 是**整个组件库唯一线程安全的对象**。

- **进程内多线程**：每线程 `acquire()` 独立连接 → 各自操作 → `release()` 归还
- **跨进程并发**：OpenFileGDB 不支持跨进程写锁，需业务层保证互斥
- **BatchWriter 不需要内部锁**：隔离来自连接独立性，不是来自内部互斥
