## 1. 项目概览

fast_gdb 是 ESRI File Geodatabase（`.gdb`）格式的专题研究项目，**测试即教程** — 369 个 Google Test 测试，每个文件头部注释即完整教程内容。

核心是两个独立 C++ 组件：

- **usegdal**：基于 GDAL 高层 API 的组件库（Datasource→Dataset→Recordset 三层模式），详见 [01_组件库设计与使用.md](../usage/01_组件库设计与使用.md)
- **explorgdb**：纯 C++17 GDB 二进制解析器 + 写入器，**不依赖 GDAL**，详见本文第 4 节

性能数据请参考 [01_性能基准与优化.md](../technical/01_性能基准与优化.md)。

## 3. GDB 二进制格式参考

本章节从字节级描述 GDB 的文件格式，是目前最完整的格式参考。

### 3.1 GDB 目录结构

一个 `.gdb` 目录以文件夹形式存在，内部包含以 `aXXXXXXXX.<ext>` 命名的文件：

| 文件 | 大小 | 说明 |
|------|------|------|
| `gdb` | 8 字节 | 格式标识：version=5, magic=0xDEADBEEF |
| `timestamps` | 384 字节 | 时间戳数据 |
| `aXXXXXXXX.gdbtable` | 变长 | 表数据 |
| `aXXXXXXXX.gdbtablx` | 变长 | FID → 文件偏移索引 |
| `aXXXXXXXX.gdbindexes` | 变长 | 索引元数据 |
| `aXXXXXXXX.spx` | 变长 | 空间索引 B+ 树 |
| `aXXXXXXXX.<field_name>.atx` | 变长 | 属性索引 B+ 树 |
| `fras_bnd_<raster_name>.ras.bnd.x` | 变长 | 栅格波段数据 |

**ID 分配**：系统表占用 a00000000~a00000007，用户数据表从 a00000008 开始。

| ID | 系统表 |
|----|--------|
| 0 | GDB_SystemCatalog |
| 1 | GDB_ItemTypes |
| 2 | GDB_Datasets |
| 3 | GDB_ItemRelationshipTypes |
| 4 | GDB_Items |
| 5 | GDB_ItemRelationships |
| 6 | GDB_DatasetRelationships |
| 7 | GDB_SpatialRefs |

### 3.2 `.gdbtable` 文件格式

#### 文件头

**v3 格式（40 字节，FGDB 9.x）**：

```
偏移  大小  字段              说明
0     4    version           版本号（=3）
4     4    nfeatures_v3      要素数量
8     4    largest_size_record 最大记录长度
12    4    unknown_role      始终为 5
16    4    unknown_16        —
20    4    unknown_20        —
24    8    file_size         文件总大小
32    8    field_desc_offset 字段描述符区起始偏移
```

**v4 格式（48 字节，FGDB 10.x / ArcGIS Pro）**：

```
偏移  大小  字段              说明
0     4    version           版本号（=4）
4     4    has_deleted_features 是否有已删除要素
8     4    largest_size_record 最大记录长度
12    4    unknown_role      始终为 5
16    4    padding           —
20    4    padding           —
24    8    nfeatures_v4      要素数量
32    8    file_size         文件总大小
40    8    field_desc_offset 字段描述符区起始偏移
```

#### Section Header（14 字节）

位于 `field_desc_offset` 处：

```
偏移  大小  字段              说明
0     4    section_length   字段描述符区总长度（不含自身 4 字节）
4     4    section_version  通常为 3
8     4    geom_type_full   图层 Z/M 能力（最高字节 bit7=has_z, bit6=has_m）
12    2    nfields          字段数量（uint16 LE）
```

**重要：图层 Z/M 能力 vs 几何类型 Z/M**

- `layer_has_z` / `layer_has_m`：来自 `geom_type_full >> 24` 的 bit7/bit6，决定 bbox 尾部是否有 zmin/zmax/mmin/mmax
- `geom_flags`（几何字段描述符内）：has_m=bit1, has_z=bit2，决定 morig/mscale/zorig/zscale 是否存在
- 两者不一定一致（图层可能有 Z 能力但某些几何类型没有 Z）

#### 字段类型枚举（17 种）

| 值 | 类型 | 编码方式 |
|----|------|----------|
| 0 | Int16 | 2 字节 LE |
| 1 | Int32 | 4 字节 LE |
| 2 | Float32 | 4 字节 IEEE 754 |
| 3 | Float64 | 8 字节 IEEE 754 |
| 4 | String | varuint(len) + UTF-8 字节 |
| 5 | DateTime | 8 字节 double (OLE DATE) |
| 6 | ObjectId | 不存储（隐式 = FID+1） |
| 7 | Geometry | varuint(len) + 几何 blob |
| 8 | Binary | varuint(len) + 原始字节 |
| 9 | Raster | 变长 |
| 10 | UUID_1 | 16 字节 |
| 11 | UUID_2 | 16 字节 |
| 12 | XML | varuint(len) + UTF-8 字节 |
| 13 | Int64 | 8 字节 LE |
| 14 | Date | 8 字节 double (OLE DATE) |
| 15 | Time | 8 字节 double (OLE DATE) |
| 16 | DateTimeWithOffset | 8 字节 double + 2 字节 int16 分钟偏移 |

#### 字段描述符结构

每个字段描述符的公共前缀：

```
name_len(1) + name(UTF-16, name_len 字符)
alias_len(1) + alias(UTF-16, alias_len 字符)
type(1) — FieldType 枚举值
```

**Geometry 字段描述符（最复杂）**：

```
magic1(1, =0) + flag(1)
wkt_len(2, 字节数) + wkt(UTF-16, wkt_len/2 字符)
geom_flags(1): has_m=bit1, has_z=bit2
xorig(8) + yorig(8) + xyscale(8)               ← 始终存在
[if has_m] morig(8) + mscale(8)                 ← 条件：geom_flags
[if has_z] zorig(8) + zscale(8)                 ← 条件：geom_flags
xytolerance(8)
[if has_m] mtolerance(8)                        ← 条件：geom_flags
[if has_z] ztolerance(8)                        ← 条件：geom_flags
xmin(8) + ymin(8) + xmax(8) + ymax(8)          ← bbox
[if layer_has_z] zmin(8) + zmax(8)              ← 条件：geom_type_full
[if layer_has_m] mmin(8) + mmax(8)              ← 条件：geom_type_full
terminator(1, =0)
nb_grid_sizes(4) + grid_sizes[N x 8]            ← 空间索引网格划分
```

#### 要素记录格式

```
[blob_len: 4 字节 uint32 LE]   ← 记录总长度（不含自身 4 字节）
[nullable_bitmap: N 字节]      ← 每 nullable 字段 1 bit，按字节对齐
[field_value_0]                ← 按字段描述符顺序
[field_value_1]
...
```

**字段值编码**：

| 类型 | 编码 | 说明 |
|------|------|------|
| ObjectId | 不存储 | 隐式 = FID + 1 |
| Int16 | 2 字节 LE | |
| Int32 | 4 字节 LE | |
| Float32 | 4 字节 IEEE 754 | |
| Float64 | 8 字节 IEEE 754 | |
| String/XML | varuint(len) + UTF-8 字节 | |
| DateTime/Date/Time | 8 字节 double (OLE DATE) | 基准 1899-12-30 |
| DateTimeWithOffset | 8 字节 double + 2 字节 int16 | OLE DATE + 分钟偏移 |
| Binary | varuint(len) + 原始字节 | |
| Geometry | varuint(len) + 几何 blob | |
| UUID | 16 字节 | |

### 3.3 `.gdbtablx` 偏移索引

**v3 头部（16 字节）**：

```
偏移  大小  字段               说明
0     4    version           版本号（=3）
4     4    n1024blocks_v3    1024-要素块的数量
8     4    nfeatures_v3      要素总数
12    4    size_tablx_offsets 偏移条目宽度（4/5/6）
```

**偏移编码**：

| 宽度 | 最大文件 | 编码方式 |
|------|----------|----------|
| 4 字节 | 4 GB | 标准小端 uint32 |
| 5 字节 | ~256 TB | byte[0]=低8位, bytes[1:5]=高32位 |
| 6 字节 | ~16 EB | byte[0]=低8位, bytes[1:5]=中32位, byte[5]=高8位 |

**注意**：5 字节编码的 byte[0] 是最低 8 位，bytes[1:5] 是最高 32 位。这种布局与标准小端不同（标准小端每个字节依次贡献 8 位），推测是 FileGDB 将前 8 位单独存储用于某种对齐优化。

### 3.4 `.spx` 空间索引 B+ 树

**文件结构**：N 个 4096 字节页面 + 22 字节 trailer。

**Trailer（22 字节）**：

```
偏移  大小  字段               说明
0     1    value_size        索引值字节数（.spx 总是 8）
1     1    flags             bit5=is_string, bit6=is_numeric
2     4    magic1            必须为 1
6     4    tree_depth        B+ 树深度（1~4）
10    4    total_value_count 总条目数
```

**64-bit 空间索引值编码**：

```
Bit 63-62: grid_level (0=最细格网, 1=中, 2=最粗)
Bit 61-31: cell_x (31 位)
Bit 30-0:  cell_y (31 位)
```

**页面布局（value_size=8）**：

**分支页面（4096 字节）**：

```
[0:4]   next_page_id
[4:8]   entry_count
[8..8+N*4]     child_page_id 数组 (N+1 x 4)
[12+mpp*4..]   值数组 (N x 8)
```

**叶子页面（4096 字节）**：

```
[0:4]   next_page_id
[4:8]   entry_count
[8:12]  UNUSED (padding)
[12..12+N*4]   FID 数组 (N x 4)
[12+mpp*4..]   值数组 (N x 8)
```

### 3.5 `.gdbindexes` 索引元数据

```
nindexes(int32)
每个索引：
  name_len(int32) + name(UTF-16, name_len 字符)
  magic1(uint16) + magic2(int32) + magic3(uint16)
  [if known magic] magic4(int32)
  col_name_len(int32) + col_name(UTF-16)
  magic5(uint16)
```

### 3.6 坐标编码公式

```
整数坐标 = round((真实坐标 - origin) * scale)
真实坐标 = cumulative_int / scale + origin
```

**Point 坐标解码**（有 -1 偏移，因为 raw=0 表示 NULL/EMPTY）：

```
real_coord = (raw_value - 1) / scale + origin
```

**Array 坐标解码**（Polyline/Polygon/MultiPoint，累积 delta 编码）：

```
real_coord = cumulative_int / scale + origin
```

**Bbox 坐标解码**（无 -1 偏移）：

```
real_coord = raw / scale + origin
```

## 4. explorgdb 内部架构

### 4.1 三个读取模式

`GdbTableParser` 支持三种读取模式：

| 模式 | 方法 | 加载内容 | 内存 | 适用场景 |
|------|------|----------|------|----------|
| **按需读取** | `open()` | 仅 header + fields | 极小 | 频繁查询少数要素 |
| **按 FID 读取** | `read_record_by_fid()` | 通过 .gdbtablx 偏移定位 | 逐条 | 随机访问 |
| **零拷贝顺序扫描** | `sequential_scan()` | mmap 回调 | 虚存 | 全表扫描（最快） |

**按需读取流程**：

```
GdbCatalog::scan() → 枚举所有 aXXXXXXXX.* 文件
  ↓
GdbTableParser::open() → 只读 header + fields（mmap, MADV_SEQUENTIAL）
  ↓
GdbTablxParser::parse() → 创建 FID → 文件偏移表
  ↓
GdbTableParser::read_record_by_fid(fid) → 定位 blob → 解码字段
```

**零拷贝顺序扫描** 使用 `FieldRef` 直接指向 mmap 内存，消除 per-record memcpy + variant 构造 + string 堆分配，性能比 GDAL 快 9-12x。

### 4.2 B+ 树导航算法

**分支页面匹配规则**（来自 GDAL FindPages 逻辑）：

- `entry[i]` 是分隔符，表示 `child[i]` 范围的上界
- `child[i]` 的 cx 范围：`[entry[i-1].cx+1, entry[i].cx]`
- `child[0]` 的范围：`[-inf, entry[0].cx]`

匹配步骤：

1. 找到第一个 `entry[i].cx > q_max_cx` → 设为 `iLastPageIdx`（遍历上界）
2. 找到第一个 `entry[i].cx >= q_min_cx` → 从 `child[i-1]` 开始遍历
3. 遍历 `[iFirstPageIdx, iLastPageIdx]` 范围的 child

**叶子页面**：使用 `FindMinMaxIdx` 完整 64-bit 二分查找。

### 4.3 LRU 页面缓存

- 按 depth 分组，每层 4 个 slot，共 `kMaxDepth(4) × 4 = 16` slots
- 单调递增计数器驱动 LRU 驱逐
- 递归遍历时先提取 child IDs 再递归，避免递归驱逐父页面

### 4.4 空间查询的两层过滤

```
第 1 层：.spx B+ 树 → query_bbox → FID 候选集
                  ↓
第 2 层：GdbGeomDecoder::peek_bbox() → 快速排除不重叠的几何
                  ↓
         GdbTableParser::read_record_by_fid() → 完整解码
```

去重优化：同一 feature 可能跨多个 grid_level，使用 bitset（最大 12.5 MB）或 sort+unique 方案。

### 4.5 写入器混合工作流

二进制写入器不直接操作 GDB 格式创建索引，而是采用混合工作流：

```
1. GDAL 创建空 schema（建目录、建图层、建字段）
2. GdbTableWriter 二进制追加数据到 .gdbtable
3. 写入 .gdbtablx 偏移索引
4. GdbIndexCreator（通过 GDAL SQL）创建 .spx / .atx
```

性能口径分两类：Phase C 直写器约 ~0.18 μs/feature；`GdbTableWriter` 在 100K+ 规模约 4.3~4.5 μs/feature。

## 5. 设计模式总结

| 模式 | 应用位置 | 说明 |
|------|----------|------|
| **RAII** | GdbDatasource, GdbRecordset, GdbTransaction | 构造时获取资源，析构时自动释放 |
| **值对象** | GdbField, GdbFeature, GdbConnectionInfo | 深拷贝语义，类型安全封装 |
| **非拥有视图** | GdbDatasets, GdbDataset, GdbRecordset | 不拥有底层 GDAL 指针，生命周期由上游管理 |
| **链式构建器** | GdbQuery | `.where().spatial().limit().offset()` fluent interface |
| **连接池** | GdbConnectionPool | mutex 保护，LIFO 策略，提高缓存局部性 |
| **两层过滤** | 空间查询 | OGRLayer bbox 粗过滤 → Recordset 逐要素精确过滤 |
| **零拷贝** | BinaryReader, FieldRef, sequential_scan | 直接指向 mmap 内存，消除拷贝 |
| **LRU 缓存** | GdbSpatialIndexParser | 按 depth 分组，16 slot，单调计数器驱逐 |
| **mmap + 按需读** | GdbTableParser, GdbSpatialIndexParser | 虚拟内存映射，madvise 预读提示 |
| **预计算** | GdbGeomDecoder | 预计算 1/scale，用乘法代替除法 |
| **委托构造** | GdbDatasource::openExisting → open | 内部构造 GdbConnectionInfo |

```bash
cd fast_gdb && mkdir -p build && cd build
cmake .. && make -j$(sysctl -n hw.ncpu)
./bin/gdb_tutorial_test_runner --gtest_filter='T001_*:T002_*:T003_*'
```

阅读测试文件头部注释：
- `tests/tutorials/test_001_format.cpp` — GDB 格式概述

- `tests/tutorials/test_003_readwrite.cpp` — 读写实战

```bash
./bin/gdb_tutorial_test_runner --gtest_filter='T011_*:T012_*:T013_*'
```

```bash
./bin/gdb_tutorial_test_runner --gtest_filter='*Benchmark*:*WBench*'
```

### Step 4：二进制格式深入

先读 [04_GDB二进制格式图解教程.md](../technical/04_GDB二进制格式图解教程.md) 看带图讲解，再读 [03_技术探索与教训.md](../technical/03_技术探索与教训.md) 了解 B+ 树发现和 mmap 优化背后的故事，最后用 CLI 工具探索真实 GDB：

```bash
./bin/explorgdb_cli explore <gdb_path>
./bin/explorgdb_cli dump-table <gdb_path>/a00000001.gdbtable
./bin/explorgdb_cli dump-indexes <gdb_path>/a00000001.gdbindexes
```

