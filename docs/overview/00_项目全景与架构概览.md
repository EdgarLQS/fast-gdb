# fast-gdb 项目全景与架构概览

## 1. 项目定位

fast-gdb 是 C++17 FileGDB Reader。核心目标是：

- 低依赖读取；
- mmap 和顺序扫描性能；
- FID、属性和空间查询；
- ISO WKB-first 几何输出；
- 与 GDAL 的正确性对照；
- 可选 GDAL Hybrid 复杂几何回退；
- 规划中的 Reader-only Adaptive 编排：检测源变化、拒绝活动写入期间的读取，并在源稳定后使用 fresh GDAL 只读恢复。

项目不提供受支持的 FileGDB Writer。所有生产编辑由调用方直接使用 GDAL/OpenFileGDB 或 ArcGIS 完成。

## 2. 产品

当前安装产品：

```text
fast_gdb::linear
    pure C++ Reader

fast_gdb::hybrid
    fast-gdb Reader + GDAL geometry fallback
```

规划但尚未实现或安装：

```text
fast_gdb::adaptive
    Reader orchestration
    + writer activity / generation observation
    + source snapshot validation
    + fresh GDAL read-only recovery
```

不存在 Writer target、Writer 公共头或 Writer ABI。ADR-008 仍为 Proposed，`fast_gdb::adaptive` 不是当前产品能力。

## 3. 代码架构

```text
src/edgar/explorgdb/common
    binary helpers / shared infrastructure

src/edgar/explorgdb/reader
    catalog / table / tablx / spx / atx
    query / cursor / geometry / WKB

src/edgar/explorgdb/curve_gdal
    optional GDAL geometry fallback

src/edgar/usegdal
    reference-only historical GDAL/OGR wrappers
    not built / installed / exported

tests/usegdal/test_*.cpp
    direct GDAL fixture / parity / boundary tests
```

`src/edgar/usegdal` 保留 datasource、dataset、recordset、query、transaction 和 batch-write 等历史探索代码，仅供参考，不属于产品组件。

Adaptive Reader 计划优先作为 Reader 上层编排实现，不从 `src/edgar/usegdal` 复用 Writer 包装，也不能复用曲线回退的长期 GDAL Dataset 缓存。

## 4. Reader 链路

```text
FileGDB directory
    → GdbCatalog
    → CatalogResolver
    → GdbTableParser
    → QueryEngine
    → FeatureCursor
    → FeatureRecord + GeometryValue
    → ISO WKB
```

规划中的 Adaptive 层位于该链路之上：

```text
activity/generation + source snapshot
    → fast-gdb materialized read
    → validate source
    → return fast result
       or expire Reader / SourceBusy
       or fresh GDAL read-only recovery after quiescence
```

## 5. 外部编辑边界

当前唯一正式合同：

```text
Reader phase
    fast-gdb owns read state

Edit phase
    all fast-gdb objects closed
    GDAL owns update state
```

同一目录边写边读不支持。写后必须完整重开 Reader。参考目录中的写示例不改变上述支持合同。

ADR-008 不把重叠读写变成受支持行为，而是规划将其转换为：

- Writer 活动期间 `SourceBusy`；
- 读取期间源变化则丢弃结果并使旧 Reader 过期；
- 源稳定后使用 fresh GDAL 只读连接恢复；
- 无协调外部 Writer 检测仅为 best-effort。

## 6. 在线更新

不停读更新需要业务层维护两个 GDB 副本并切换逻辑路径。该发布层不属于 fast-gdb。Adaptive Reader 也不负责副本发布、路径切换或旧版本回收。

## 7. 质量门禁

当前门禁：

- pure Reader build and install；
- linear/hybrid package consumer；
- geometry and query regression；
- direct GDAL parity；
- GDAL 写后完整重开；
- 同目录重叠访问观测性测试；
- Windows/Linux/macOS Reader 矩阵；
- 安装和 CMake 导出不引用 `src/edgar/usegdal`。

ADR-008 接受前还需要：

- 三平台 `FileStamp/GdbSourceSnapshot`；
- Writer active 时两个读取后端调用数均为零；
- generation/source 变化使旧 Reader 确定性过期；
- fast 和 GDAL 读取期间变化均丢弃结果；
- fresh GDAL recovery 不复用旧 Dataset；
- 协调压力测试无 mixed、无崩溃；
- adaptive package surface 仍严格 Reader-only。

## 8. 非目标

- FileGDB 创建和编辑产品；
- 受支持的 GDAL Writer wrapper；
- 事务、回滚和恢复；
- fast-gdb 管理 Writer 生命周期；
- generation 发布或在线副本管理；
- Schema migration；
- 对任意无协调外部 Writer 的绝对检测保证；
- 正在写入时通过 GDAL 强行返回结果；
- 写后局部 refresh。

“外部写入检测”不再是整体永久非目标：协调模式检测和无协调 best-effort 变化检测已进入 ADR-008 计划，但当前尚未实现或接受。

## 9. 参考代码治理

`src/edgar/usegdal` 可以用于设计比较、实验或未来独立组件研究，但必须遵守：

1. 不从 Reader 核心链接该目录；
2. 不加入安装导出；
3. 不将其 API 写入产品文档；
4. 不用其存在声称 fast-gdb 支持写入；
5. 若提升为正式组件，必须另立 ADR、target、测试矩阵和兼容性政策。
