# M18.4.2 Writer Update 自我代码审查

## 结论

当前结论：**Request Changes，等待真实 macOS 编译和合同证据。**

静态审查未发现会直接原地修改源 GDB 的路径；所有 Update 均发生在完整 staging 副本中。但在 Actions 可运行前，不能确认 GDAL `SetFeature`、索引维护、Z/M 几何和安装消费在当前 macOS/GDAL 组合上通过。

## 已检查范围

- `WriterUpdateSession` one-shot 状态机；
- staging/backup/publish/rollback；
- FID 和总行数不变；
- 部分字段更新时未设置字段保持原值；
- 属性与几何立即回读；
- 字段类型、nullable、有限数值和几何 family/Z/M 校验；
- 源目录外部修改检测；
- no-GDAL stub 与 GDAL-only 安装面；
- schema-v2 合同及三次重复执行 workflow。

## 本轮发现

### Major-1：commit 重开验证仍需加强

当前实现重开 staging 后确认总行数不变，但没有保存并重新遍历所有本次更新 FID。每次 `end_update()` 已按 FID 回读，能够捕获绝大多数写入错误；正式验收前仍应把更新 FID 集合持久化到 session，并在 commit 重开时逐一确认。

状态：**未完成，阻止 Approve。**

### Major-2：Binary 回读比较缺失

setter 支持 `OFTBinary`，但 `end_update()` 的回读比较目前未核对二进制长度和字节内容。

状态：**未完成，阻止将 Binary 标记为稳定支持。** 在修复前，文档和验收不得声称 Binary Update 已通过。

### Major-3：测试依赖头位置不理想

为快速修复测试缺失的 `<fstream>` 和 `<limits>`，当前公共 `writer_update.h` 临时包含了这两个标准头。不会造成 ABI 错误，但扩大了公共编译面。应把依赖移回测试文件并从公共头删除。

状态：**代码质量问题，需在最终收口时修复。**

### Major-4：索引行为依赖 GDAL 实证

代码依赖 OpenFileGDB `SetFeature` 维护已有属性/空间索引。合同测试已要求新值命中、旧值不再命中、更新几何在新范围命中，但当前没有运行 artifact。

状态：**外部验证阻塞。**

## 已满足的安全属性

- 源 GDB 在 commit 前不被修改；
- 不存在目标 FID时会锁定会话并要求 abort；
- 首个错误不会被后续错误覆盖；
- active update 未结束时禁止 commit；
- 未执行任何 Update 时禁止 commit；
- 发布第二次 rename 失败时尝试恢复 backup；
- 源指纹改变时拒绝发布；
- 析构和 abort 删除 staging。
