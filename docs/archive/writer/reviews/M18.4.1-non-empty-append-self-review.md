# M18.4.1 非空追加自我代码审查

- 审查范围：ADR-002、`WriterAppendSession`、安装面、package consumer、追加合同与测试、macOS workflow
- 审查结论：**代码层面无未处理 Critical；PR 级结论为 Request Changes，等待真实 macOS CI 证据**

## 1. 已发现并修复

### Major-1：私有 PImpl 类型被实现辅助函数引用

初版自由函数直接命名私有嵌套 `Impl`，会触发 C++ 访问控制错误。

处理：仅公开 PImpl 前置声明，字段仍只存在于实现文件。

### Major-2：GDAL-only 源污染 no-GDAL 构建

Writer 使用源文件 glob，初版 `writer_append.cpp` 会在 `FAST_GDB_WITH_GDAL=OFF` 时仍包含 GDAL 头。

处理：CMake 仅在 GDAL 构建定义 `FAST_GDB_WITH_GDAL_ENABLED`；根源文件按该宏选择真实实现或 unavailable stub。无 GDAL 安装不包含 `writer_append.h`。

### Major-3：字段类型可能被 GDAL 隐式转换

初版只校验字段索引和重复写，`Integer`/`Real`/`String` 错配可能被 GDAL 自动转换。

处理：公共 setter 精确核对 OGR 字段类型、nullable 和有限浮点数，再转发到内部 unchecked 存储。

### Major-4：几何错误发现过晚

初版只校验 setter 对应的枚举 base type，没有核对图层 family、Z/M、part 数和环闭合。

处理：公共几何 setter 前置验证图层类型、维度、有限坐标、Polyline 最少点数、Polygon 闭合。

### Major-5：只确认 CreateFeature 成功，未立即核对写入值

GDAL 接受要素不等于属性和几何完全等价。

处理：公共 `end_row()` 保存期望字段与几何，调用内部写入后按新 FID 立即回读，逐字段比较并执行完整几何 `Equals`。失败锁定会话，源数据不会发布。

### Major-6：open 失败后仍可能再次调用 open

初版失败会设置 locked，但 `open()` 的入口条件未检查 locked；第二次打开可能返回 true，却无法继续操作。

处理：公共 `open()` 强制 one-shot，任何首次失败后只能 abort/析构。

## 2. 生命周期与数据安全审查

通过静态审查的路径：

- 所有写入发生在源目录的同级 staging 副本；
- 未提交析构和 `abort()` 删除 staging；
- 字段、几何、行回读、staging 重开或源指纹失败不会重命名源目录；
- 发布先 source→backup，再 staging→source；第二步失败时恢复 backup；
- 发布完成后 backup 删除失败不会触发析构删除新源目录；
- 原 FID 集合在 staging 重开时逐个验证；新 FID 必须严格大于打开时最大 FID并单调增长；
- commit 前再次检测源目录指纹，降低会话期间外部修改被覆盖的风险。

## 3. API 与安装面审查

- `WriterSession` 的空 schema 行为未改变；
- 非空追加是独立 `WriterAppendSession`；
- `writer_append.h` 仅安装在 GDAL 构建；
- no-GDAL stable/legacy 安装均不泄露追加头；
- package consumer 引用构造、析构和状态访问符，验证静态库链接链路；
- 私有 unchecked 方法存在于类私有区，不构成公共可调用 API。

## 5. 已知边界与技术债

### Accepted boundary：无并发读写承诺

source→backup→source 的发布存在短暂路径切换窗口。本阶段只承诺业务层独占写入，commit 窗口不支持并发 Reader。跨进程文件锁与无间隙目录交换留到事务/崩溃恢复阶段。

### Accepted boundary：源指纹不是内容哈希

当前指纹使用相对路径、文件大小和修改时间。它用于发现常规外部修改，不替代 OS 文件锁；恶意保持大小和 mtime 的并发修改不在本阶段威胁模型。

### Minor：目录遍历顺序依赖文件系统稳定性

指纹聚合当前依赖 `recursive_directory_iterator` 顺序。顺序变化只会导致安全失败（拒绝发布），不会导致错误覆盖。后续可改为排序路径后聚合，降低误报。

### Accepted boundary：索引维护委托 GDAL

第一版不直接操作 `.spx/.atx`，由 OpenFileGDB update 维护，并通过索引存在性和查询结果验收。原生索引增量维护不在本阶段。

### Deferred：崩溃自动恢复

进程在两次 rename 之间崩溃时可能留下 backup/staging。当前不自动恢复，符合 M18.4.1 边界；事务/崩溃恢复阶段必须识别这些目录并提供确定性恢复策略。
