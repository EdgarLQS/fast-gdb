# 索引构建方案

## 1. 背景与挑战

### 1.1 GDB 索引类型

| 索引类型 | 文件 | 用途 |
|---------|------|------|
| 空间索引 | `.spx` | 加速空间范围查询（bbox 相交） |
| 属性索引 | `.atx` | 加速字段过滤查询（=, <, >, >=, <=） |
| 索引元数据 | `.gdbindexes` | 记录所有索引的名称、字段、类型 |

### 1.2 为什么需要索引？

使用 `explorgdb` 纯 C++ 二进制写入器时，**不会自动创建索引**。没有索引会导致：
- 空间查询退化为全表扫描（O(N)）
- 属性过滤需要遍历所有记录（O(N)）
- 不兼容 ArcGIS（ArcGIS 期望 GDB 包含标准索引文件）

### 1.3 三种索引方案对比

| 方案 | 写入速度 | 索引质量 | 查询性能 | 适用场景 |
|------|---------|---------|---------|---------|
| 纯 GDAL | 1x (5.4 us) | 完整 | O(log N) | 小数据集，简单流程 |
| GDAL SQL 索引 | 26x (0.21 us) | 完整 | O(log N) | 无 ArcGIS 许可 |
| ArcGIS Pro 索引 | 26x (0.21 us) | 完整 | O(log N) | 大数据集，生产环境 ⭐ |
| 自研索引 ⚠️ | 26x (0.21 us) | 单层 <1000 | O(N) | 已放弃 |

## 2. 推荐方案：混合工作流（GdbTableWriter + 独立索引验证）

⚠️ **受控数据已验证** — 经过 10 万面要素验证；35GB/5 亿级生产数据仍需专项基准

### 2.1 工作流总览

```
┌─────────────────────────────────────────────────────────────┐
│ 步骤 1: 快速写入数据                                          │
│ 工具: GdbTableWriter (explorgdb/writer)                     │
│ 性能: 26x 加速 (0.21 us/feat vs GDAL 5.4 us/feat)         │
│ 输出: 有效的 .gdb（含 schema + 数据）                        │

                            ↓
┌─────────────────────────────────────────────────────────────┐

│ 工具: ArcGIS Pro 或 GDAL 辅助工具                             │
│ 功能: 创建/重建多层 B+ 树索引（.spx + .atx）                   │
│ 质量: 必须结合目标数据和客户端交叉验证                         │
└─────────────────────────────────────────────────────────────┘
                            ↓

│ 步骤 3: 高性能查询                                            │
│ 工具: explorgdb/reader                                       │

```

### 2.2 步骤 1：使用 GdbTableWriter 写入数据

#### 准备 schema（使用 GDAL）

```cpp
#include "gdal.h"
#include "gdal_priv.h"
#include "ogrsf_frmts.h"

bool create_schema(const std::string& gdb_path, const std::string& layer_name) {
    GDALAllRegister();
    std::filesystem::create_directories(gdb_path);
    
    GDALDriver* driver = GetGDALDriverManager()->GetDriverByName("OpenFileGDB");
    GDALDataset* ds = driver->Create(gdb_path.c_str(), 0, 0, 0, GDT_Unknown, nullptr);
    
    OGRSpatialReference srs;
    srs.SetWellKnownGeogCS("WGS84");
    OGRLayer* layer = ds->CreateLayer(layer_name.c_str(), &srs, wkbPolygon, nullptr);
    
    OGRFieldDefn name_field("name", OFTString);
    name_field.SetWidth(100);
    layer->CreateField(&name_field);
    
    OGRFieldDefn pop_field("population", OFTInteger);
    layer->CreateField(&pop_field);
    
    GDALClose(ds);
    return true;
}
```

#### 使用 GdbTableWriter 填充数据

```cpp
#include "explorgdb/writer/gdb_table_writer.h"
#include "explorgdb/writer/geometry_serializer.h"

using namespace explorgdb::writer;

void write_data(const std::string& gdb_path, const std::string& layer_name) {
    GdbTableWriter writer;
    
    if (!writer.open_existing(gdb_path, layer_name)) {
        throw std::runtime_error("无法打开 GDB");
    }
    
    auto& geom_ser = writer.geometry_serializer();
    
    const int N = 100000;
    for (int i = 0; i < N; ++i) {
        std::vector<GeomPoint> ring = {
            {100.0 + i * 0.01, 30.0},
            {100.01 + i * 0.01, 30.0},
            {100.01 + i * 0.01, 30.01},
            {100.0 + i * 0.01, 30.01},
            {100.0 + i * 0.01, 30.0}
        };
        geom_ser.set_rings({ring});
        geom_ser.serialize(GeomType::Polygon);
        
        writer.begin_row();
        writer.append_string(0, "Polygon_" + std::to_string(i));
        writer.append_i32(1, 10000 + i * 10);
        writer.append_geometry(2);
        writer.end_row();
    }
    
    writer.close();
    std::cout << "写入完成: " << writer.row_count() << " 要素\n";
    // 预期输出: 写入完成: 100000 要素
    // 耗时: ~400ms (0.21 us/feat)
}
```

### 2.3 步骤 2：使用 ArcGIS Pro 构建索引

#### 创建空间索引

1. 在 ArcGIS Pro Contents 面板中，右键图层 → Properties
2. 转到 Indexes 标签页
3. 在 Spatial Index 区域：勾选 "Spatial Index"
4. 点击 Apply

**结果**: ArcGIS Pro 创建多层 B+ 树索引，生成 `.spx` 文件

#### 创建属性索引

在同一个 Indexes 标签页：
1. 在 Attribute Indexes 区域，点击 Add
2. 选择字段，输入索引名称
3. 点击 Apply

**结果**: 生成 `.atx` 文件

#### 验证索引文件

```bash
ls -lh /path/to/output.gdb/
# 应该看到：
# a00000009.spx — 空间索引（多层 B+ 树）
# a00000009.name_index.atx — name 字段索引
# a00000009.population_index.atx — population 字段索引
```

### 2.4 步骤 3：使用 Reader 查询数据

#### 空间查询

```cpp
#include "explorgdb/reader/gdb_spatial_index.h"

using namespace explorgdb;

void spatial_query(const std::string& spx_path) {
    GdbSpatialIndexParser parser(spx_path);
    if (!parser.parse()) {
        throw std::runtime_error("无法解析空间索引");
    }
    
    double xmin = 100.0, ymin = 30.0;
    double xmax = 100.5, ymax = 30.5;
    
    std::vector<double> grid_res = {1e7};
    auto fids = parser.query_bbox(xmin, ymin, xmax, ymax, 0, 0, 1e4, grid_res);
    
    std::cout << "查询结果: " << fids.size() << " 个要素\n";
}
```

#### 属性查询

```cpp
#include "explorgdb/reader/gdb_attribute_index.h"

using namespace explorgdb;

void attribute_query(const std::string& atx_path) {
    GdbAttributeIndexParser parser(atx_path);
    if (!parser.parse()) {
        throw std::runtime_error("无法解析属性索引");
    }
    
    auto fids = parser.query_double(50000.0, AttrOp::Ge);
    std::cout << "population >= 50000: " << fids.size() << " 个要素\n";
    
    auto fids2 = parser.query_string("Polygon_12345", AttrOp::Eq);
    std::cout << "name = 'Polygon_12345': " << fids2.size() << " 个要素\n";
}
```

## 3. 替代方案：GDAL SQL 索引（无需 ArcGIS）

🔧 无需 ArcGIS 许可证的纯 GDAL 方案

### 3.1 概述

`gdb_index_creator` 封装了 GDAL OpenFileGDB 驱动的索引创建能力，通过 SQL 接口为已写入的 GDB 添加索引。

### 3.2 快速开始

```cpp
#include "explorgdb/writer/gdb_index_creator.h"
using namespace explorgdb::writer;

// 创建空间索引
CreateSpatialIndex("/path/to/data.gdb", "cities");

// 创建单字段属性索引
CreateAttributeIndex("/path/to/data.gdb", "cities", "name");

// 创建多字段复合索引
CreateCompositeIndex("/path/to/data.gdb", "cities", {"province", "city"});
```

### 3.3 典型工作流

```cpp
#include "explorgdb/writer/gdb_table_writer.h"
#include "explorgdb/writer/gdb_index_creator.h"

using namespace explorgdb::writer;

std::string gdb_path = "/tmp/output.gdb";

// Step 1: 使用 GdbTableWriter 向已有 schema 追加要素
GdbTableWriter writer;
if (!writer.open_existing(gdb_path, "points")) {
    throw std::runtime_error("无法打开已有图层");
}
for (int i = 0; i < 10000; ++i) {
    // 实际调用方先准备 geometry_serializer()，再按字段调用 append_*。
    writer.begin_row();
    writer.append_string(0, "point_" + std::to_string(i));
    writer.append_geometry(1);
    writer.end_row();
}
writer.close();

// Step 2: 创建空间索引
bool spatial_ok = CreateSpatialIndex(gdb_path, "points");
if (!spatial_ok) {
    std::cerr << "Warning: Spatial index creation may have failed\n";
}

// Step 3: 创建属性索引
CreateAttributeIndex(gdb_path, "points", "category");
CreateAttributeIndex(gdb_path, "points", "timestamp");

// Step 4: 验证索引
bool has_spatial = HasSpatialIndex(gdb_path, "points");
std::cout << "Has spatial index: " << (has_spatial ? "yes" : "no") << "\n";
```

### 3.4 性能说明

以下数字来自小规模受控基准，仅用于说明趋势，不能作为 35GB/5 亿级数据的耗时承诺。完整流程还可能包含源数据扫描、几何解码、目标写入、系统表更新、索引重建和结果校验。

**索引创建开销**：

| 数据规模 | 空间索引耗时 | 属性索引耗时 |
|---------|-------------|-------------|
| 1K 要素 | ~10ms | ~5ms |
| 10K 要素 | ~50ms | ~10ms |
| 100K 要素 | ~500ms | ~50ms |
| 1M 要素 | ~5s | ~200ms |

**查询性能提升**：

| 查询类型 | 无索引 | 有索引 | 提升倍数 |
|---------|--------|--------|---------|
| 点查询（1M 数据） | ~500ms | ~5ms | **100x** |
| 范围查询（10% 数据） | ~2s | ~50ms | **40x** |
| 属性等值查询 | ~1s | ~10ms | **100x** |

### 3.5 故障排查

#### SQL 错误是装饰性的

**现象**：执行 `CreateSpatialIndex` 时输出警告：
```
[IndexCreator] Warning: CREATE SPATIAL INDEX SQL failed
  Error: SQL expression not supported by this driver
  Note: OpenFileGDB auto-creates indexes when features are written
```

**原因**：GDAL OpenFileGDB 驱动不支持通过 SQL 显式创建索引，但会在写入要素时自动触发索引创建。

**处理方式**：
1. **忽略警告**：函数返回值 `true` 表示索引已成功创建（或已存在）
2. **验证文件**：检查 GDB 目录下是否存在 `.spx` 或 `.atx` 文件
3. **代码逻辑**：实现中已处理此场景 — SQL 失败后会回退检查文件系统

#### 常见错误

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `Failed to open GDB` | GDB 路径不存在或权限不足 | 检查路径和文件权限 |
| `Layer not found` | 图层名称不匹配 | 使用 GDAL 工具确认图层名 |
| `Field does not exist` | 字段名称错误 | 检查图层 schema |
| `CREATE INDEX failed` | OpenFileGDB 限制 | 检查返回值，通常索引已自动创建 |

### 3.6 最佳实践

1. **批量写入后统一创建索引**：避免每写入一条就创建一次
2. **优先创建空间索引**：空间查询收益最大
3. **根据查询模式选择字段**：仅为高频查询字段创建索引
4. **复合索引字段顺序**：将区分度高的字段放在前面
5. **验证索引创建结果**：使用 `HasSpatialIndex` 或检查文件系统

### 3.7 explorgdb writer 的编辑边界

`GdbTableWriter` 当前是主数据表追加/直写组件，不是完整的 FileGDB 编辑器：

- 支持已有 schema 的批量追加和 `.gdbtablx` 更新；
- 不提供生产级原地删除、freelist 和完整系统表同步；
- 追加后不能假设 `.spx`、`.atx` 与业务数据已经一致；
- “过滤删除后追加”应优先实现为新 GDB 全量重写，完成后统一构建索引并交叉验证；
- 35GB/5 亿级场景必须使用真实数据单独测量，不能用 100K 合成基准线性外推。

## 4. API 参考

### 4.1 IndexDefinition 结构体

```cpp
struct IndexDefinition {
    std::string index_name;              // 索引名称（可选，为空则自动生成）
    std::vector<std::string> fields;     // 字段列表（单字段或多字段）
    bool is_spatial = false;             // 是否为空间索引
};
```

### 4.2 函数清单

| 函数 | 功能 | 参数 |
|------|------|------|
| `CreateSpatialIndex(gdb_path, layer_name)` | 创建空间索引 | GDB 路径, 图层名 |
| `CreateAttributeIndex(gdb_path, layer_name, field_name, index_name="")` | 创建属性索引 | + 字段名, 索引名(可选) |
| `CreateCompositeIndex(gdb_path, layer_name, field_names, index_name="")` | 创建复合索引 | + 字段列表 |
| `CreateIndex(gdb_path, layer_name, definition)` | 通用接口 | IndexDefinition |
| `CreateIndexes(gdb_path, layer_name, definitions)` | 批量创建 | 定义列表 |
| `DropIndex(gdb_path, index_name)` | 删除索引 | 索引名 |
| `HasSpatialIndex(gdb_path, layer_name)` | 检测空间索引 | 图层名 |

### 4.3 完整工作流示例

```cpp
#include "explorgdb/writer/gdb_index_creator.h"
#include <iostream>
#include <filesystem>

using namespace explorgdb::writer;
namespace fs = std::filesystem;

int main() {
    std::string gdb_path = "/data/output.gdb";
    std::string layer = "cities";

    // Step 1: 创建空间索引
    if (!CreateSpatialIndex(gdb_path, layer)) {
        std::cerr << "Warning: Spatial index creation may have failed\n";
    }

    // Step 2: 创建属性索引
    CreateAttributeIndex(gdb_path, layer, "name", "name_idx");
    CreateAttributeIndex(gdb_path, layer, "population", "pop_idx");

    // Step 3: 创建复合索引
    CreateCompositeIndex(gdb_path, layer, {"province", "city"}, "loc_idx");

    // Step 4: 验证索引
    std::cout << "Has spatial index: "
              << (HasSpatialIndex(gdb_path, layer) ? "yes" : "no") << "\n";

    for (const auto& entry : fs::directory_iterator(gdb_path)) {
        if (entry.path().extension() == ".spx" ||
            entry.path().extension() == ".atx") {
            std::cout << "  - " << entry.path().filename().string() << "\n";
        }
    }

    return 0;
}
```

## 5. 自研索引尝试（已放弃）

⚠️ **Phase D 自研索引** — 仅适合学习研究，不适合生产

### 5.1 已完成工作

| 组件 | 文件 | 功能 | 状态 |
|------|------|------|------|
| B+ 树通用写入器 | `bplus_tree_writer.h` | 模板化 B+ 树构建 | ⚠️ 仅单层 |
| 空间索引写入器 | `spatial_index_writer.h` | bbox→网格离散化 + 64 位编码 | ⚠️ 仅单层 |
| 属性索引写入器 | `attribute_index_writer.h` | 多类型字段值 B+ 树 | ⚠️ 框架完成 |
| .gdbindexes 元数据 | `gdb_indexes_writer.h` | 索引注册表生成 | ⚠️ 框架完成 |

### 5.2 技术细节

**空间索引值编码（64 位）**：
```
Bit 63-62: grid_level (0=最细格网, 1=中, 2=最粗格网)
Bit 61-31: cell_x (31 位有符号整数)
Bit 30-0:  cell_y (31 位有符号整数)
```

**B+ 树页面结构（4096 字节）**：
```
叶子页:
  bytes 0-3:   next_page_id
  bytes 4-7:   entry_count
  bytes 12..12+N*4:     fid 数组 (N × 4)
  bytes 12+mpp*4..:     value 数组 (N × value_size)

Trailer（22 字节）:
  byte 0:      value_size
  byte 1:      flags (0x20=is_string, 0x40=is_numeric)
  bytes 6-9:   tree_depth (1-4)
  bytes 10-13: total_value_count
```

**每页最大条目数**: `mpp = (4096 - 12) / (4 + value_size)` — value_size=8 时 mpp=340

### 5.3 限制与决策

| 限制 | 说明 |
|------|------|
| 单层 B+ 树 | 仅支持 < 1000 条目（depth=1，340 条/页） |
| 多层扩展复杂 | depth>1 需要逐层构建分支页，参考 GDAL 实现 |
| 生产质量差距 | ArcGIS Pro 支持 130 亿条目（depth=4） |

**决策**：
- 自研索引代码已删除
- 生产环境使用混合工作流（ArcGIS Pro）或 GDAL SQL 方案

## 6. FileGDB 索引格式参考

### 6.1 空间索引 (.spx)

```
B+ 树结构:
  - 页面大小: 4096 字节
  - 每页最大条目: 340 (value_size=8)
  - 树深度: 1-4 层
  - 最大容量: ~130 亿条目 (depth=4)

索引值编码 (64 位):
  Bit 63-62: grid_level (0=最细, 2=最粗)
  Bit 61-31: cell_x (31 位有符号)
  Bit 30-0:  cell_y (31 位有符号)
```

### 6.2 属性索引 (.atx)

```
B+ 树结构:
  - 与 .spx 相同
  - 支持类型: Int16/32/64, Float32/64, String

值编码:
  - 数值: 直接存储（小端序）
  - 字符串: UTF-16LE，空格填充
```

### 6.3 查询算法

**空间查询 (bbox)**:
1. 将查询 bbox 离散化为网格单元
2. 在 B+ 树中查找匹配的网格单元
3. 返回所有匹配的 FID

**属性查询**:
1. 在 B+ 树中查找匹配的值
2. 支持操作符: =, <, <=, >, >=, <>
3. 返回所有匹配的 FID

**时间复杂度**: O(log N + k) — N: 总条目数, k: 结果数量
