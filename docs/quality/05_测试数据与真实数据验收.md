# 测试数据与真实数据验收

## 1. 原则

/

fast-gdb 只读取 FileGDB。测试数据可由 GDAL/OpenFileGDB、ArcGIS Pro 或其他权威工具生成，但生成或修改阶段必须与 fast-gdb Reader 阶段完全分离。

```text
/

fixture generation/edit
    → close generator
    → fast-gdb read validation
```

## 2. GDAL 生成数据

```cpp
GDALAllRegister();
GDALDriver* driver =
    GetGDALDriverManager()->GetDriverByName("OpenFileGDB");
GDALDataset* dataset = driver->Create(
    "fixture.gdb", 0, 0, 0, GDT_Unknown, nullptr);

// CreateLayer / CreateField / CreateFeature

GDALClose(dataset);
```

只有 `GDALClose()` 完成后才能创建 fast-gdb Reader。

## 3. 修改现有数据

```text
1. 销毁所有 fast-gdb Reader、cursor、mmap 和句柄
2. GDALOpenEx(..., GDAL_OF_UPDATE)
3. 执行 SetFeature/DeleteFeature/Schema/Index/REPACK
4. 释放 Feature 和 SQL result set
5. GDALClose
6. 从 catalog scan 开始重开 fast-gdb
```

同目录边写边读只允许在专用 characterization 测试中出现。

## 4. 测试数据 manifest

每份真实数据应记录：

- 生成工具和版本；
- OS 和文件系统；
- 图层、字段和空间参考；
- 要素数和 FID 分布；
- 几何类型及 Z/M/曲线；
/

- 属性/空间索引；
- 删除槽、NULL 和 Binary；
- 是否执行过 REPACK；
- 校验和或预期查询结果。

## 5. 跨平台矩阵

| 平台 | Reader | GDAL 写后重开 | 重叠观测 |
|---|---|---|---|
| Linux | 必须 | 必须 | 诊断 |
| macOS | 必须 | 必须 | 诊断 |
| Windows | 必须 | 必须 | 诊断 |

重叠观测结果可能不同，不要求平台一致，也不构成支持声明。

## 6. 验收层级

1. 单元测试；
2. 临时 GDAL fixture；
3. 仓库真实 FileGDB；
4. ArcGIS Pro 生成数据；
5. 大规模和损坏数据；
6. installed package consumer；
7. CI artifact。

`SKIPPED`、无步骤 runner 失败或缺失日志都不能算通过。
