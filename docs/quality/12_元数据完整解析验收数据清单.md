# 元数据完整解析验收数据清单

## 1. 目的

本清单用于验证 fast-gdb 是否能够把 FileGDB 中的数据完整取出。

本轮“完整”的定义是 **无损可取出**：

- 系统表、业务表、字段和记录可以逐项读取；
- NULL、字段类型、Binary、XML、UUID、日期和几何数据不丢失；
- Domain、Relationship Class、Feature Dataset 和空间参考可以形成结构化结果；
/

- 结构化解析失败时，仍保留原始记录或原始 XML/Binary，并返回诊断；
- Raster 暂不纳入本轮验收，不需要为 Raster 单独生成数据。

本清单通过前，项目只能宣称“核心矢量读取已验证”，不能宣称“FileGDB 元数据和关系结构完全解析”。

## 3. 必须新生成的数据

/

建议使用 ArcGIS Pro/ArcPy 原生创建一个独立数据集：

```text
acceptance_metadata.gdb
```

不要先经过 GDAL 导出或线性化。每项内容按下表生成。

| 优先级 | 对象或能力 | 具体要求 | 验证目标 |
|---|---|---|---|
| P0 | Feature Dataset | `TransportFD`、`AdminFD` 两个 Feature Dataset，每个包含 2~3 个 Feature Class | Dataset、成员关系、路径和分组 |
| P0 | 根目录对象 | 根目录下 1 个独立 Feature Class、1 个独立 Table | 区分独立对象和 Dataset 成员 |
| P0 | Coded Value Domain | `road_status_domain`：`OPEN`、`CLOSED`、`UNKNOWN` | Domain 定义、编码值和字段绑定 |
| P0 | Range Domain | `speed_range_domain`：范围 0~120 | 最小值、最大值、字段类型和绑定 |
| P1 | Subtype Domain | 一个图层设置 Subtype 字段，不同 Subtype 绑定不同 Domain | Subtype 与 Domain 的组合元数据 |
/

| P0 | Simple Relationship | `roads → road_inspections`，1:M，OBJECTID/Long 外键 | 关系类型、基数、正反向标签、主外键 |
| P0 | Composite Relationship | `parcels → parcel_parts`，1:M 或 1:1，启用 containment | containment、通知策略和关系属性 |
/

| P1 | GUID Relationship | 使用 GlobalID/GUID 作为关系键 | UUID 字段和关系键解析 |
| P1 | 关系属性表 | 如果 ArcGIS Pro 支持，增加带属性的关系类；不支持时记录 `SKIPPED` | 关系额外属性和中间表 |
| P0 | 全字段类型表 | Short、Long、Float、Double、Text、Date、GUID、GlobalID、BLOB；版本支持时加入 BigInteger、DateOnly、TimeOnly、TimestampOffset | 非 Raster 字段是否完整取出 |
| P0 | NULL/边界值 | 每种字段包含 NULL、空字符串、0、负数、最大/最小值、中文和 emoji | NULL 位图和边界值 |
| P0 | Binary | BLOB 写入固定字节串、空 Binary、较长 Binary | 原始 Binary payload |
/

| P0 | XML/对象描述 | 为 Workspace、Feature Dataset 和关键图层填写标题、摘要、标签、说明、限制条件 | Definition、Documentation、ItemInfo XML |
| P1 | 字段元数据 | 设置字段别名、默认值、nullable、长度和字段说明 | 字段描述与 XML 字段信息 |
| P1 | 属性索引 | 对 `status`、`road_id`、`name` 建立属性索引 | `.gdbindexes`、`.atx` 和字段映射 |
| P1 | 空间索引 | 每个几何图层建立有效 `.spx` | 候选、精确过滤和索引关联 |
| P1 | 坐标系 | 至少 EPSG:4326、EPSG:3857；另加自定义 WKT 或 unknown 图层 | `GDB_SpatialRefs` 和图层关联 |
/

| P1 | 稀疏 FID | 创建约 20 条记录，删除中间记录，再追加记录 | 删除槽、FID/ObjectID 映射 |
| P1 | 空几何 | 空 Point、空 Line、空 Polygon 各至少 1 条 | 空几何与 NULL 的区别 |

### 3.1 建议的最小图层布局

```text
acceptance_metadata.gdb
├── root_points                 独立 Point Feature Class
├── root_table                  独立 Table
├── TransportFD                 Feature Dataset
/

│   ├── roads                   Polyline，绑定 status/speed Domain
│   ├── road_inspections        Table 或 Point，作为关系 destination
/

│   └── road_assets             Point，含 GUID/GlobalID
└── AdminFD                     Feature Dataset
    ├── parcels                 Polygon，作为关系 origin
    └── parcel_parts            Polygon，Composite Relationship destination
```

字段类型表可放在根目录下，名称建议为 `all_field_types`。

## 5. 生成规则

/

1. 使用 ArcGIS Pro/ArcPy 原生创建并保留完整 `.gdb` 目录。
2. 记录 ArcGIS Pro 版本和可重复执行的创建脚本。
3. Domain 和 Relationship Class 必须是真实 GDB 对象，不能只手写 XML。
/

4. 对每个对象用 ArcGIS/ArcPy 独立导出清单，作为 fast-gdb 对照基准。
5. 当前 ArcGIS 版本不支持的字段或关系类型必须记录为 `SKIPPED`，不能用其它类型替代。
6. 不需要生成 Raster；Raster 是本轮明确非目标。

## 6. fast-gdb 验收顺序

```text
系统表清单一致
→ 表和字段数量一致
→ 每条记录均可读取
→ NULL/类型/原始 Binary/XML 一致
→ Domain 定义和字段绑定一致
→ Relationship 边和属性一致
→ Feature Dataset 层级一致
/

→ FID/ObjectID 映射一致
→ 几何 WKB、空几何和诊断一致
```

结构化解析失败时，验收结果必须包含：

- 原始系统表记录仍可读取；
/

- 原始 XML/Binary 仍可取出；
- 明确的 `degraded` 或 `unsupported` 状态；
- 不得静默返回空集合或 NULL。

## 7. 验收结果分类

| 状态 | 含义 |
|---|---|
| `LosslessPhysicalRead` | 原始表、字段、记录和 payload 均可取出 |
| `StructuredMetadataRead` | Domain、Relationship、Dataset 层级结构化解析成功 |
| `SemanticGeometryRead` | 几何语义和 WKB 输出满足当前合同 |
| `DegradedWithRawPayload` | 高级语义降级，但原始数据没有丢失 |
| `UnsupportedAndDiagnosed` | 明确不支持，返回原因，未伪装成成功 |

只有所有目标数据达到 `LosslessPhysicalRead`，才能称为“数据都可以拿出来”。
