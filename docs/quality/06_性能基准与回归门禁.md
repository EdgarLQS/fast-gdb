# 性能基准与回归门禁

## 1. 范围

fast-gdb 性能工作只衡量 FileGDB Reader：

- 顺序扫描；
- FID 随机读取；
- 属性查询；
- 空间查询；
- SpatialWhere；
- FeatureCursor；
- 几何解析和 ISO WKB；
- mmap、fd 和缓存路径。

项目不再维护自研 Writer 性能基准。GDAL 写入只用于生成测试数据和验证“写后完整重开”的兼容性。

## 2. 对照对象

| 路径 | 用途 |
|---|---|
| fast-gdb Reader | 被测主路径 |
/

| GDAL/OpenFileGDB Reader | 正确性和性能对照 |
| record + geometry legacy read | 回归对照 |
| FeatureCursor one-pass | 推荐完整要素路径 |

所有性能结果必须先通过数量、FID、字段和 WKB 校验和门禁。

## 3. 指标

- median / p95 / p99；
/

- features/s；
- candidate count 和 final match count；
- mmap/page/index 访问量；
- peak RSS；
/

- 冷/热缓存；
- geometry decode 和 WKB write 分阶段耗时。

## 4. 数据规模

- 1K：功能和快速回归；
- 10K：常规 CI；
- 100K：性能门禁；
- 1M：规模验证；
- 10M：显式长时间基准，不进入默认 CI。

## 5. 外部 GDAL 写入

性能测试需要更新数据时：

```text
close all fast-gdb Reader state
/

→ GDAL edit/generate
→ GDALClose
→ create fresh Reader
→ benchmark
```

禁止在活动 Reader 期间运行 GDAL update、索引重建或 REPACK。否则测量同时包含未定义缓存和文件状态，结果无效。

## 6. 优化原则

- WKB-first，避免无需求 WKT；
- 一次定位记录，一次字段物化；
- 索引只生成候选，最终复核不可省略；
- 低选择性查询允许绕过索引；
- 避免重复排序、重复解码和临时对象；
- 正常路径不启用 profiling 时不引入时钟开销；
- 优化失败必须安全回退，不能返回部分结果。

## 7. 证据规则

性能结论必须记录：

- commit；
- OS、编译器和 GDAL 版本；
- 数据 manifest；
- 缓存状态；
- 样本数；
- 正确性结果；
/

- 原始 JSON/CSV artifact。

没有运行步骤、日志或 artifact 的 CI 不能作为性能证据。
