# VersionedGdbStore 生产运行、恢复与故障处理手册

- **审查标签**：@深度研究
- **日期**：2026-07-22
- **适用对象**：服务开发、发布系统、SRE、值班人员、数据管理员
- **适用状态**：当前仅面向可靠本地文件系统、单进程多 Reader + 单 Writer

## 1. 运行原则

生产环境必须遵守以下原则：

1. `CURRENT` 是唯一活跃 generation 事实来源；
2. published generation 永远只读，不做原地修复；
3. Writer 只编辑 working generation；
4. publish 前关闭全部外部编辑器对象和文件句柄；
5. `publish_state()` 决定后续动作，不能只看 bool；
6. durability uncertain 时优先保留新旧 generation，禁止 GC；
7. ENOSPC 时优先保护当前可读版本，不为腾空间抢先删除旧 generation；
8. 所有人工操作都必须记录 CURRENT、目录清单、租约和错误日志；
9. 不在 NFS/SMB/FUSE/云同步目录/对象存储上执行本手册；
10. 不允许多个进程同时执行 Writer 或 recovery。

## 2. 正常启动流程

### 2.1 启动前检查

- store root 是预期路径；
- 路径不是 symlink/junction/UNC/网络映射；
- CURRENT、generations、work 位于同一 device/volume；
- 文件系统类型在允许矩阵中；
- 磁盘和 quota 有足够余量；
- 上一个 Writer 进程已完全退出；
- 不存在外部 ArcGIS/GDAL 对 store 内目录的 update 连接；
- 若实现了 sidecar owner lock，当前进程成功独占。

### 2.2 `open()` 期望行为

`open()` 应：

1. 建立必要目录；
2. 规范化 store identity；
3. 获取进程内状态；
4. 检查 CURRENT 格式；
5. 确认 CURRENT 指向 `generations/` 下存在的常规目录；
6. 拒绝 path traversal、symlink 和特殊文件；
7. 按当前协议处理 stale temp/work；
8. 在安全条件满足时清理无租约旧 generation；
9. 不猜测“最大 generation id”作为 CURRENT；
10. 任何关键检查失败时 fail closed。

### 2.3 启动后基线日志

建议至少记录：

```text
store_root
canonical_store_root
filesystem_type
device_or_volume_id
current_generation
current_generation_size
available_space
active_readers=0
writer_active=false
durability_uncertain=false
stale_work_count
orphan_generation_count
last_recovery_result
```

## 3. 正常 Reader 流程

### 3.1 获取

```text
acquire_reader
→ snapshot binds CURRENT
→ lease++
→ open GdbCatalog/QueryEngine/GDAL Dataset from snapshot.path()
```

### 3.2 使用

- snapshot 必须位于最外层生命周期；
- 不把裸 generation path 放入长期缓存；
- 每个线程使用独立 QueryEngine/cursor/Dataset；
- 查询期间不 refresh；
- 记录 snapshot generation 和创建时间。

### 3.3 释放

顺序：

1. 关闭 cursor；
2. 释放 Feature/row 对象；
3. 关闭 QueryEngine、GDAL Layer/Dataset；
4. 解除 mmap；
5. 关闭 fd/HANDLE；
6. 最后释放 snapshot；
7. Store 在安全条件下评估 GC。

### 3.4 Reader 告警

建议告警：

- snapshot 年龄超过业务阈值；
- 某旧 generation 被租约保留超过阈值；
- pinned generations 总空间超过阈值；
- Reader 数持续增长不回落；
- GC 多次因租约阻塞。

## 4. 正常 Writer 流程

### 4.1 开始前

- 确认 Store 不处于 uncertain；
- 确认无另一个 Writer；
- 获取当前 generation 和 free space；
- 明确 validator profile；
- 明确外部编辑器版本和预计空间放大。

### 4.2 `begin_write()`

应产出：

```text
transaction_id
base_generation
working_path
copy_mode_requested
copy_mode_effective
fallback_reason
```

### 4.3 编辑 working

允许业务编辑器或 GDAL 修改 working，但必须：

- 不打开 CURRENT generation 为 update；
- 不并发使用多个编辑器；
- 不让 ArcGIS/QGIS 交互式工程长期持有 work；
- 事务失败时先完成编辑器自身 rollback/close；
- 不在 publish 过程中继续写。

### 4.4 关闭外部对象

GDAL 推荐顺序：

1. 完成或回滚 Dataset transaction；
2. 释放所有 OGRFeature；
3. 释放 SQL result set；
4. 清空 layer iteration/filter 状态；
5. FlushCache 仅作为辅助；
6. `GDALClose(dataset)`；
7. 结束所有后台线程；
8. 确认 `.lock`/句柄释放；
9. 再进入 validator。

ArcGIS 工作流建议：在 Store 外完成生成，关闭 ArcGIS Pro/脚本进程后再导入 working；不要直接让 ArcGIS 工程连接 Store 内 work。

### 4.5 publish 阶段

建议阶段化日志：

```text
PUBLISH_VALIDATE_OPEN
PUBLISH_VALIDATE_CATALOG
PUBLISH_VALIDATE_LAYERS
PUBLISH_VALIDATE_RECORDS
PUBLISH_VALIDATE_GEOMETRY
PUBLISH_VALIDATE_SPX
PUBLISH_VALIDATE_ATX
PUBLISH_SYNC_CANDIDATE_FILES
PUBLISH_SYNC_CANDIDATE_DIRS
PUBLISH_PROMOTE_GENERATION
PUBLISH_SYNC_GENERATIONS_DIR
PUBLISH_WRITE_CURRENT_TMP
PUBLISH_SYNC_CURRENT_TMP
PUBLISH_REPLACE_CURRENT
PUBLISH_SYNC_STORE_ROOT
PUBLISH_UPDATE_MEMORY_STATE
PUBLISH_GC
```

每一阶段失败都必须记录：

- transaction id；
- base/new generation；
- 是否已替换 CURRENT；
- publish state；
- errno/GetLastError；
- primary error；
- cleanup error；
- 保留了哪些目录。

## 5. publish 返回值处理

### 5.1 `PublishedDurable`

```text
publish() == true
publish_state() == PublishedDurable
published() == true
```

动作：

- 对外宣布发布成功；
- 新 Reader 可获取新 generation；
- 旧 Reader 继续旧版；
- 允许安全 GC；
- 记录发布指标。

### 5.2 `NotPublished`

```text
publish() == false
publish_state() == NotPublished
published() == false
```

含义：CURRENT 未切换。

动作：

- 当前已发布版本继续服务；
- 根据失败阶段决定修复 working 后重试 validator/publish，或显式 abort；
- 不删除 CURRENT generation；
- 清理失败需单独告警。

### 5.3 `PublishedDurabilityUncertain`

```text
publish() == false
publish_state() == PublishedDurabilityUncertain
published() == true
```

含义：CURRENT 在可见性上已切换，但最终持久化屏障失败，崩溃后究竟保留新 CURRENT 还是旧 CURRENT 无法确认。

立即动作：

1. 停止新 Writer；
2. 禁止 generation GC；
3. 不调用 abort；
4. 不重试 publish；
5. 保留新旧 generation、CURRENT、temp 和日志；
6. 进入只读/降级状态；
7. 释放或等待全部 Reader；
8. 在无 Reader/Writer 后执行 `recover()`。

## 6. `PublishedDurabilityUncertain` 详细处置

### 6.1 现场保护

采集：

```text
CURRENT 原始字节和 stat
CURRENT.tmp-* 列表
all generations 列表、大小、mtime、权限
generation validator 快速结果
work 列表
active reader/writer 状态
filesystem/mount 信息
free space
操作系统错误码
进程日志
```

不要：

- 删除旧 generation；
- 手工把 CURRENT 改回旧值；
- 重新 publish 同一 transaction；
- 启动另一实例尝试“接管”；
- 为释放空间删除未知目录。

### 6.2 recovery 前条件

- 全部 Reader 释放；
- 无活动 Writer；
- 外部 GDAL/ArcGIS 连接全部关闭；
- store root 独占；
- 磁盘有足够空间完成 sync；
- 文件系统恢复正常。

### 6.3 recover 目标

recover 的目标是确认和持久化**当前磁盘上 CURRENT 所表达的事实**，而不是自动选择业务上更好的版本。

建议逻辑：

1. 严格读取 CURRENT；
2. 验证单行、换行、长度和 generation 名称；
3. 确认目标位于 generations 下；
4. 拒绝 symlink/path escape；
5. 确认目标存在；
6. 按策略做 fresh reopen 基础校验；
7. 同步 generation、generations、CURRENT 和 store root；
8. 清除 uncertain；
9. 恢复 Writer gate；
10. 最后再评估 GC。

### 6.4 recover 成功后

- 用新 snapshot 重新读取 CURRENT；
- 执行关键业务查询；
- 核对 expected generation；
- 记录 recovery report；
- 逐步恢复 Writer；
- 不要立即大规模 GC，先保留一个观察窗口。

## 7. ENOSPC 处理

### 7.1 可能发生的阶段

- FullCopy 创建 working；
- CoW 后首次大规模写入；
- `.spx/.atx` 重建；
- 外部编辑器临时文件；
- validator 缓存或读取失败；
- sync file metadata；
- promote 或 CURRENT tmp；
- GC 需要目录操作但文件系统异常。

### 7.2 CURRENT 未切换时

- 保证 CURRENT 继续服务；
- 停止编辑；
- 显式关闭外部句柄；
- 记录失败阶段；
- 可 abort working；
- 仅清理确认属于本事务且未发布的 work；
- 扩容后新建事务，不在半失败事务上继续追加未知写入。

### 7.3 CURRENT 已切换且 uncertain 时

按 uncertain 流程。最重要的规则：

> 不得为了腾空间先删除旧 generation。

因为崩溃恢复后 CURRENT 可能回到旧值。

### 7.4 容量排查

- 是否从 CoW 退化 FullCopy；
- 是否存在长期 Reader 阻塞 GC；
- working 是否重复残留；
- validator/编辑器是否创建大临时文件；
- quota 与文件系统 free space 是否不一致；
- sparse/reflink 的逻辑大小与物理占用是否混淆。

## 8. CURRENT 损坏或非法

### 8.1 症状

- 多行；
- 无结尾换行；
- 超长；
- 包含路径分隔符、`..`；
- 指向 work；
- 指向不存在 generation；
- 指向 symlink；
- 文件为空或读取失败。

### 8.2 默认策略

- fail closed；
- 不猜最大 generation id；
- 不自动选择最新 mtime；
- 不立即删除任何 generation；
- 进入人工恢复。

### 8.3 人工恢复原则

只有在停机、独占和完整备份后：

1. 列出所有 generation；
2. 逐个做 fresh reopen validator；
3. 结合发布日志确认最近成功的 durable generation；
4. 选择明确可信的目标；
5. 通过受控工具写 CURRENT.tmp；
6. sync temp；
7. 原子替换 CURRENT；
8. sync store root；
9. 用 snapshot 验证；
10. 暂缓 GC。

不得只根据目录名数字最大值决定。

## 9. working 残留

### 9.1 常见来源

- 进程崩溃；
- 析构 abort 清理失败；
- ENOSPC；
- 外部句柄阻止删除；
- 运维强杀；
- 权限变化。

### 9.2 处理分类

| 类型 | 处理 |
|---|---|
| 明确属于未发布已终结事务，CURRENT 未引用 | 可删除或隔离 |
| durability uncertain 期间产生 | 保留，先 recover |
| 无法确认 owner/事务 | 隔离到 quarantine，不直接删除 |
| 被外部进程打开 | 先停止外部进程，保留证据 |
| 内含可能有业务恢复价值的数据 | 复制到 Store 外后再处理 |

## 10. 旧 generation 无法 GC

排查顺序：

1. 是否 CURRENT；
2. 是否 uncertain；
3. 是否有 Reader lease；
4. 最老 lease 属于哪个请求/线程；
5. 是否有裸 path 外部访问；
6. Windows 是否有打开 HANDLE；
7. 权限是否允许删除；
8. 是否 antivirus/indexer/backup 工具占用；
9. 删除失败错误码。

不要通过强制删除绕过 lease；应先修复生命周期泄漏。

## 11. Validator 失败

### 11.1 CURRENT 未切换

这是安全失败。处理：

- 保留错误报告；
- 明确失败规则和 layer；
- 使用外部工具检查 working；
- 修复后关闭句柄并重新验证；
- 或 abort。

### 11.2 常见分类

- catalog/system table 无法打开；
- layer 不存在；
- active count 不符；
- full scan count 不符；
- FID 不可读；
- geometry decode 失败；
- `.spx` 解析失败；
- `.gdbindexes`/`.atx` 不一致；
- 未支持 capability 被 strict profile 拒绝。

### 11.3 不应做的事

- 为了上线关闭关键 validator rule；
- 直接把 working 移到 generations；
- 在 published generation 上修复；
- 把“ArcGIS 能打开”当作所有规则通过；
- 把抽样通过当作全量业务证明。

## 12. 外部程序误改 Store

### 12.1 发现信号

- generation mtime 在发布后变化；
- 出现意外 `.lock`；
- CURRENT 未通过 Store 发生变化；
- work/generations 中出现不符合命名规则的目录；
- 文件权限或 owner 改变；
- validator 对已发布版本突然失败。

### 12.2 处理

1. 停止 Writer；
2. 隔离外部程序；
3. 不做 GC；
4. 备份整个 store；
5. 验证 CURRENT generation；
6. 与发布时 fingerprint/日志比较；
7. 若 published generation 被改，视为协议破坏，不能继续声称快照一致性；
8. 从可信 generation 或外部备份重建新 Store。

## 13. 手工业务回滚

业务回滚与 durability recovery 不同。

前提：

- 停止新 Writer；
- 选择已验证且业务认可的历史 generation；
- 确认没有外部直接依赖当前 generation；
- 保留当前 generation 作为历史证据。

步骤：

1. fresh reopen 验证目标历史 generation；
2. 写新的 CURRENT.tmp；
3. sync temp；
4. 原子替换 CURRENT；
5. sync root；
6. 新 snapshot 验证；
7. 对外恢复；
8. 延迟 GC。

推荐未来提供正式 `rollback_to(generation_id)` 工具，而不是要求运维手工编辑文件。

## 14. 监控指标

### Store

- current generation；
- generation count/bytes；
- work count/bytes；
- orphan count；
- free space/quota；
- filesystem type；
- uncertain flag。

### Reader

- active readers；
- oldest lease age；
- per-generation lease count；
- bytes pinned by readers；
- refresh success/failure。

### Writer

- transaction count；
- clone mode；
- FullCopy fallback reason；
- phase durations；
- validator failures；
- publish states；
- recovery count；
- GC errors。

## 15. 事故分级建议

| 事件 | 等级 |
|---|---|
| CURRENT 指向缺失 generation | Sev-1 |
| Published generation 被外部修改 | Sev-1 |
| 多进程 Writer 同时运行 | Sev-1 |
| durability uncertain | Sev-1/Sev-2，取决于可读性 |
| ENOSPC 但 CURRENT 未切换 | Sev-2 |
| GC 阻塞导致磁盘快速增长 | Sev-2 |
| validator 失败、CURRENT 不变 | Sev-3 |
| CoW 退化 FullCopy | Sev-3/容量告警 |
| 单个 stale work | Sev-3 |

## 16. 生产上线门禁

在以下事项未满足前，不应标记为 Production Accepted：

- 三平台真实构建/CTest；
- 本地文件系统矩阵；
- ENOSPC 和 crash-phase fault injection；
- durability uncertain recovery 演练；
- 外部 GDAL Dataset 生命周期测试；
- 长 Reader/GC 压力测试；
- CURRENT 损坏和人工回滚演练；
- capability profile 与高级 GDB 对象策略；
- 跨进程 Writer fail-fast；
- 可审计日志和告警。
