# VersionedGdbStore 跨平台测试与正式验收矩阵

- **审查标签**：@深度研究
- **日期**：2026-07-22
- **目标**：把 `Implemented / Formal acceptance blocked` 转换为可执行、可审计的验收清单
- **原则**：编译通过不等于文件系统语义通过；单次 smoke 不等于崩溃一致性通过

## 1. 验收等级

| 等级 | 定义 |
|---|---|
| L0 静态 | 编译、警告、安装面、API 负向检查 |
| L1 功能 | 正常 Reader/Writer/publish/recover 行为 |
| L2 并发 | 多 Reader、单 Writer、租约、refresh、GC |
| L3 文件系统 | CoW/FullCopy、rename、directory sync、路径 identity |
| L4 故障注入 | ENOSPC、EIO、权限、进程崩溃、阶段失败 |
| L5 兼容性 | 真实 FileGDB、GDAL/ArcGIS、索引、Schema 和高级能力 |
| L6 生产 | 压力、长生命周期、容量、监控、运维演练和可审计 artifacts |

VersionedGdbStore 只有完成 L0～L5 的必选项，才可从 `Formal acceptance blocked` 进入 `Accepted for constrained deployment`。完成 L6 后才可讨论 Production Accepted。

## 2. 平台与文件系统矩阵

### 2.1 macOS

| 环境 | 必测路径 | 断言 |
|---|---|---|
| 最新支持版本 + APFS | `clonefile` 成功 | copy mode 为 CoW；修改 working 不影响 source；旧 Reader 连续读取 |
| APFS 禁用/模拟 clone 失败 | FullCopy fallback | CURRENT 不变；fallback reason 可见；结果与 CoW 路径一致 |
| 非 APFS 本地卷（如可获得） | FullCopy | 不把 clone 失败当作事务失败 |
| case-insensitive APFS | 路径别名 | 大小写/规范化后的同一 store 不允许双 Writer |
| symlink alias | gate 和路径逃逸 | 同一 store 合并；managed GDB symlink 被拒绝 |
| directory sync 注入失败 | uncertain | 保留新旧 generation；阻止 GC/新 Writer；recover 成功 |

### 2.2 Linux

| 文件系统 | CoW 预期 | 必测 |
|---|---|---|
| Btrfs | FICLONE | 文件级 clone、写后私有化、publish、abort、recover |
| XFS reflink=1 | FICLONE | 同上 |
| ext4 | FullCopy | 峰值空间、ENOSPC、性能和清理 |
| tmpfs | 通常 FullCopy/特定行为 | 仅功能，不作为 durable 生产证据 |
| bind mount | identity 风险 | 文档/检测策略；不得绕过 gate |
| NFS/SMB/FUSE | Unsupported | strict mode 必须拒绝，而不是运行成功即算支持 |

### 2.3 Windows

| 环境 | 必测 |
|---|---|
| NTFS 本地盘 | FullCopy、CURRENT 替换、句柄关闭、删除旧 generation |
| 大小写别名 | 同一 store 单 Writer gate |
| junction alias | 是否能识别或 fail-fast |
| UNC/network share | strict mode 拒绝 |
| 长路径/Unicode | store root、generation、错误信息 |
| 文件被 GDAL/ArcGIS/antivirus 占用 | promote/delete 失败保持 CURRENT |
| `MoveFileExW` 最终同步失败注入 | uncertain 与 recover |

## 3. L0：构建、API 与安装面

### 3.1 编译矩阵

- GCC、Clang、MSVC；
- C++17；
- `FAST_GDB_WITH_GDAL=OFF`；
- `FAST_GDB_WITH_GDAL=ON`（Reader hybrid，不改变 Writer public surface）；
- Debug/Release；
- warnings-as-errors；
- ASan/UBSan（Linux/macOS）；
- MSVC AddressSanitizer（可用时）。

### 3.2 安装正向断言

安装后必须存在：

```text
versioned_gdb_store.h
versioned_gdb_validator.h
fast_gdb::writer
```

package consumer 必须能：

- construct/open Store；
- inspect public enums；
- link and run；
- 不依赖源码树 private include。

### 3.3 安装负向断言

必须不存在：

- `writer_legacy`；
- 旧 WriterSession/Append/Update/Delete/Transaction 头；
- 旧 CMake option；
- legacy symbol archive；
- 文档示例中的旧 API。

负向检查只能扫描头目录和 CMake exports，不能因 CHANGELOG 中提到删除项而误报。

## 4. L1：正常功能矩阵

### 4.1 初始化

| 用例 | 断言 |
|---|---|
| 空 store `initialize_from(source)` | 创建 generations/work/CURRENT；source 不受影响 |
| 重复初始化 | 明确失败，不覆盖现有 CURRENT |
| source 缺失 | fail closed，无半初始化目录或可安全清理 |
| source 含 symlink | 拒绝 |
| source 含特殊文件 | 拒绝 |
| CURRENT 格式 | 单行、结尾换行、合法 generation |

### 4.2 Reader

- acquire_reader 返回 current generation；
- snapshot move-only；
- release 后 lease--；
- old Reader publish 后仍读旧 marker；
- new Reader 读新 marker；
- idle refresh 切新版；
- invalid Store 返回无效 Reader 和明确错误；
- success 后 stale error 清空。

### 4.3 Writer

- begin_write 创建 private work；
- 同一进程同 store 第二 Writer 失败；
- 不同 store 可分别 Writer；
- symlink/relative/case alias 共享 gate；
- working owner 可写；
- source/current 不被工作修改影响；
- abort 删除 work 并释放 gate；
- 析构 best-effort abort；
- 清理失败错误可见。

### 4.4 Publish

- validator 成功 → `PublishedDurable`；
- validator 失败 → `NotPublished`，CURRENT 不变；
- promote 前失败 → CURRENT 不变；
- manifest tmp 写失败 → CURRENT 不变；
- CURRENT replace 成功 → 新 Reader 新版；
- old Reader 仍旧版；
- 最后旧 Reader 释放后 GC。

## 5. L2：并发与生命周期

### 5.1 多 Reader 压力

至少覆盖：

- 1、8、32、128 个 snapshot；
- 持续 query 与 publish 同时发生；
- 每个 Reader 校验 generation marker 不变化；
- 新 Reader 按切换点获取新版本；
- 无 use-after-free、data race、deadlock。

### 5.2 长 Reader

场景：

1. R1 持有 gen-1；
2. 连续发布 gen-2～gen-20；
3. R1 不释放；
4. 验证 gen-1 保留，其他无租约旧版本按策略回收；
5. 释放 R1 后 gen-1 可回收。

指标：租约年龄、pinned bytes、GC reason。

### 5.3 refresh

- 无派生对象时成功；
- 有活动 cursor/Dataset 时按 API 约束拒绝或由调用方测试保证；
- refresh 后 path 和 marker 更新；
- 原 generation lease 正确释放；
- refresh 失败时 snapshot 保持可用且错误明确。

### 5.4 Writer gate

- 多线程同时 begin_write，仅一个成功；
- 两 Store 实例 canonical same root，仅一个成功；
- Windows case alias；
- POSIX symlink alias；
- registry entry 生命周期不泄漏。

### 5.5 ThreadSanitizer

Linux/macOS 可用时运行 TSan，重点观察：

- shared State mutex；
- lease map；
- current generation；
- error string；
- writer_active；
- durability uncertain；
- global registry。

## 6. L3：文件系统语义

### 6.1 CoW 正确性

对每个文件：

1. clone/copy 后字节一致；
2. 修改 working 某块；
3. source hash 不变；
4. working hash 变化；
5. 文件权限满足编辑需要；
6. symlink 不被跟随；
7. sparse/xattr/ACL 行为记录。

### 6.2 FullCopy 正确性

- 逐文件完整复制；
- 大文件短写/读错误处理；
- partial destination 失败后清理；
- cleanup error 追加到主错误；
- 无 CURRENT 变化。

### 6.3 同设备保证

- work/generations/root device identity 相同；
- 模拟跨设备路径时 fail-fast；
- promote 不允许退化为 copy+delete 并仍称原子。

### 6.4 CURRENT replacement

POSIX：

- tmp 内容 sync；
- rename 原子可见；
- root directory sync；
- crash 后 old/new 之一完整存在；
- 无半行 CURRENT。

Windows：

- replacement target 已存在；
- delete/replace 权限；
- sharing violation；
- WRITE_THROUGH 行为；
- antivirus/indexer 占用；
- Unicode/long path。

### 6.5 路径 identity

- relative vs absolute；
- `.`/`..`；
- symlink；
- Windows case；
- junction；
- mapped drive vs UNC；
- POSIX bind mount；
- trailing separator；
- Unicode normalization（macOS）。

无法可靠合并的 alias 应 fail-fast 或明确不支持。

## 7. L4：故障注入矩阵

### 7.1 阶段故障点

每个阶段至少注入一次：

| 阶段 | 预期状态 |
|---|---|
| 创建 work 目录 | NotPublished，CURRENT 不变 |
| clone 第一个文件 | NotPublished，partial work 清理/报告 |
| clone 中间文件 | 同上 |
| FullCopy 短写 | 同上 |
| 外部编辑失败 | 调用方 abort，CURRENT 不变 |
| validator catalog | NotPublished |
| validator records | NotPublished |
| validator geometry | NotPublished |
| validator `.spx` | NotPublished |
| validator `.atx` | NotPublished |
| sync candidate file | NotPublished |
| sync candidate directory | NotPublished |
| promote rename | NotPublished |
| sync generations directory | NotPublished，按实际阶段保留候选 |
| write CURRENT tmp | NotPublished |
| sync CURRENT tmp | NotPublished |
| replace CURRENT 前 | NotPublished |
| replace CURRENT 后 root sync | PublishedDurabilityUncertain |
| GC 删除 | PublishedDurable，但返回/记录 GC error 的契约需明确 |
| recover sync | 保持 uncertain，禁止 GC/Writer |

### 7.2 ENOSPC

注入位置：

- clone/full copy；
- 外部编辑；
- index rebuild；
- candidate sync；
- promote；
- CURRENT tmp；
- root sync。

断言：

- CURRENT 前故障不破坏当前 generation；
- CURRENT 后故障进入 uncertain；
- 不提前删除旧 generation；
- 扩容/recover 后可恢复。

### 7.3 EIO/权限

- read EIO；
- write EIO；
- fsync EIO；
- chmod/ACL 拒绝；
- directory create/delete 拒绝；
- Windows sharing violation；
- file locked by another process。

### 7.4 进程崩溃点

通过子进程在阶段后 `_exit/TerminateProcess`：

1. work 创建后；
2. 编辑中；
3. validator 后；
4. candidate sync 后；
5. promote 后；
6. CURRENT tmp 后；
7. CURRENT replace 后；
8. root sync 后；
9. GC 中。

重启断言：

- `open()/recover()` 可推理；
- CURRENT 严格；
- 不猜目录；
- 无 manifest 指向已删除 generation；
- stale work/temp 按状态处理；
- 数据可读。

## 8. L5：真实 FileGDB 兼容矩阵

### 8.1 基础 vector 数据集

- 空表；
- 单记录；
- 大表；
- 多字段；
- NULL/default；
- Unicode；
- 日期/时间；
- GUID/GlobalID；
- binary/blob；
- 32-bit/64-bit integer。

### 8.2 几何

- Point/MultiPoint；
- Polyline multipart；
- Polygon holes/islands/nested；
- Z/M/ZM；
- empty/NULL；
- invalid geometry；
- CircularArc/Bezier/EllipticArc；
- MultiPatch；
- 极值坐标和 precision grid。

### 8.3 FID/ObjectID

- 连续 OID；
- 删除孔洞；
- 更新后 holes；
- REPACK 前后；
- 大 OID；
- sparse 64-bit OID；
- 随机抽样和全扫描一致。

### 8.4 索引

- 无索引；
- 单字段 `.atx`；
- 多种字段类型；
- `.spx`；
- 删除/更新后索引；
- 损坏索引；
- index query vs forced scan FID 集合一致；
- ArcGIS/GDAL/fast-gdb 三方对照。

### 8.5 高级对象 capability scan

至少准备包含以下对象的 GDB，确认 strict/permissive 策略：

- relationship class；
- attachments；
- domain/subtype；
- feature dataset；
- topology；
- network/utility network；
- annotation/dimension；
- raster/mosaic；
- compressed data。

未支持时测试必须证明：

- strict profile 明确拒绝；
- permissive profile 明确 warning；
- 不会静默报告“全面兼容”。

### 8.6 GDAL 版本矩阵

至少记录：

- 项目最低 GDAL 版本；
- GDAL 3.11+；
- OpenFileGDB driver metadata；
- FileGDB alias/delegation行为；
- transaction support；
- 创建/更新后的 ArcGIS 可打开性。

## 9. L6：生产与运维验收

### 9.1 性能

数据规模建议：

- 1 GB；
- 10 GB；
- 100 GB（环境允许时）；
- 小文件多 vs 大表少；
- CoW 与 FullCopy。

采集：

- clone duration；
- editor duration；
- validator duration；
- sync duration；
- manifest duration；
- GC duration；
- peak disk；
- publish P50/P95/P99；
- Reader latency during publish。

### 9.2 容量

- 长 Reader 阻塞 10/100 次发布；
- 磁盘阈值告警；
- FullCopy 最坏峰值；
- quota；
- GC 失败；
- 恢复保留新旧 generation 的额外空间。

### 9.3 运维演练

- uncertain recovery；
- CURRENT 损坏；
- 手工 rollback；
- 外部误改 generation；
- 多进程 Writer 检测；
- ENOSPC 扩容恢复；
- stale work quarantine；
- backup/restore 整个 Store。

### 9.4 可观测性

CI/生产必须能证明日志包含：

- transaction/generation id；
- copy mode/fallback；
- publish phase；
- publish state；
- validator rule；
- filesystem；
- active leases；
- GC reason/error；
- recovery result。

## 10. CI 工作流要求

每个平台 workflow 至少包括：

1. configure；
2. build；
3. unit tests；
4. sanitizer（适用平台）；
5. install；
6. positive consumer；
7. negative public-surface assertions；
8. upload CTest/JUnit/logs；
9. upload installed tree manifest；
10. 输出 compiler、OS、filesystem、GDAL version。

当前 Actions 若在任何 step 前失败、无 logs/steps/artifacts，只能标记为基础设施阻塞，不能算代码失败，也不能算验收通过。

## 11. 证据格式

每个正式验收项必须记录：

```text
Test ID
Commit SHA
OS/version
Filesystem/mount options
Compiler/version
GDAL/version/driver
Input GDB provenance
Command
Expected result
Actual result
Logs/artifact URL
Pass/Fail/Blocked
Known deviations
```

本地手工输出不能替代 CI artifact；CI 绿灯也不能替代真实文件系统和 FileGDB 语义测试。

## 12. 发布门禁

### 12.1 Constrained Acceptance

必须：

- L0 全部；
- L1 全部；
- L2 核心并发；
- L3 三平台本地文件系统；
- L4 CURRENT 前后关键故障；
- L5 基础 vector/geometry/index；
- 明确不支持清单已进入 README/ADR/usage。

### 12.2 Production Acceptance

在 Constrained Acceptance 基础上还必须：

- 长 Reader/容量压力；
- 真实复杂 GDB capability policy；
- 多进程 fail-fast；
- 网络/远程文件系统拒绝；
- uncertainty/rollback 运维演练；
- 可观测性和告警；
- 可重复、可审计 artifacts。

## 13. 当前差距

当前已有：

- 严格 C++17 语法；
- 本地 smoke；
- 多线程 Reader marker；
- path/symlink gate；
- ASan/UBSan；
- validator 接口检查；
- latest-only package consumer；
- 核心实现三轮自检。

当前仍缺：

- 完整 repo CMake/CTest；
- 实际 macOS/Windows；
- Linux reflink/no-reflink；
- ENOSPC/EIO/crash phase；
- 外部 GDAL Dataset 生命周期；
- 高级 FileGDB capability；
- 长 Reader/磁盘压力；
- 可用 Actions logs/artifacts。

因此当前状态继续保持：

```text
Implemented
Formal acceptance blocked
```
