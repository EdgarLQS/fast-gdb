# 项目状态与规划

## 当前状态

fast-gdb 正式定位为 FileGDB Reader only：

- `fast_gdb::linear`：纯 C++ Reader；
- `fast_gdb::hybrid`：Reader + GDAL fallback；
- 不提供 Writer target、Writer API 或 Writer ABI。

FileGDB 编辑统一由 GDAL/OpenFileGDB 或 ArcGIS 完成。

## 当前架构目标

```text
FileGDB
  → catalog / system tables
  → table / tablx / indexes
  → query planning
  → FeatureCursor
  → FeatureRecord + GeometryValue
  → ISO WKB
```

## 当前优先级

### P0：正确性

- 真实 FileGDB parity；
- FID、删除槽和零长度记录；
- `.spx/.atx` 损坏检测和安全回退；
- WKB-first 几何；
- GDAL 写后完整重开验证。

### P1：性能

- 顺序扫描；
- FID 随机访问；
- 属性和空间索引选择性；
- SpatialWhere 融合路径；
- mmap、缓存和内存分配。

### P1：生命周期

- cursor/engine/table/catalog 所有权；
- 外部写入前 Reader drain；
- 写后全量重开；
- 禁止同目录读写重叠。

### P2：兼容性

- Windows/Linux/macOS；
- GDAL 稳定版本矩阵；
- ArcGIS 创建的复杂 GDB；
- MultiPatch、关系、域、层级、栅格和 64-bit ObjectID profile。

## 不再规划

- 自研 FileGDB Writer；
- Append/Update/Delete API；
- Writer transaction/recovery；
- VersionedGdbStore；
- Writer benchmark；
- Writer package target；
- Reader 内建在线发布。

## GDAL 集成路线

GDAL 作为：

1. 测试数据生成器；
2. FileGDB 编辑器；
3. 正确性对照；
4. Hybrid fallback。

受支持流程：

```text
close Readers → GDAL edit → GDALClose → reopen Readers
```

## 验收门禁

- pure Reader 三平台构建；
- install surface 不含 Writer；
- linear/hybrid consumer；
- focused GDAL boundary tests；
- Reader regression；
- 真实数据和性能 artifact；
- 文档无 Writer 支持暗示。
