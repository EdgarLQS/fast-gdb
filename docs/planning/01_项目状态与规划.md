## 4. 已知限制

### 4.1 OpenFileGDB 驱动限制

| 限制 | 表现 | 应对 |
|------|------|------|
| 不支持原生事务 | StartTransaction 返回失败 | 组件不封装 begin()，BatchWriter 不调用事务 |
| 自动转换线/面几何 | wkbLineString→wkbMultiLineString | 测试中接受两种类型 |
| Integer64 存为 Float64 | 读取时类型不匹配 | 用 Real 字段 + 容差比较 |
| 属性过滤有限 | SetAttributeFilter 支持程度有限 | 复杂条件在内存中过滤 |
| SQL CREATE INDEX 不支持 | SQL 错误是装饰性的 | gdb_index_creator 已处理回退逻辑 |

### 4.2 OGRLayer 共享状态

- **滤镜持久化**：SetAttributeFilter/SetSpatialFilter 设置在 Layer 上，不因新 Recordset 清除
- **共享游标**：GetNextFeature 推进 Layer 级游标
- **应对**：组件已在 getRecordset() 和 query() 内部调用 ResetReading()

### 4.3 Phase C 直写器

- ⚠️ **系统表未更新**：a00000000.gdbtable 未更新，GDAL 无法读取正确要素计数
- 当前验证路径：explorgdb 读回 → 正确 ✅
- 待实现：GDAL OpenFileGDB 驱动兼容 → 需要系统表更新

### 4.4 跨进程并发

- OpenFileGDB 不支持跨进程写锁
- 多进程并发写同一 .gdb 文件可能导致数据损坏
- 需业务层保证互斥

## 5. 关键发现

### 5.1 两种不同的坐标解码公式

FileGDB 几何 blob 中有两种不同的 varuint 解码方式：

1. **点坐标**：`real_coord = (raw_varint_cumulative) / scale + origin`
2. **包围盒坐标**：`real_coord = raw_varuint / scale + origin`

这是 GDAL `filegdbtable.cpp` 中的实现方式。

### 5.2 损坏的 field descriptor

测试数据中几何字段 descriptor 存储了 `xorig = yorig = -2147483647`（INT_MIN sentinel 值）。需要 clamp 为 0.0 才能正确计算 cell 坐标，但几何坐标解码需要使用原始值。

### 5.3 .gdbtable 文件布局

两种布局模式：
1. **小表**：`[Header] [Field Section] [Record Data]`
2. **大表**：`[Header] [Record Data] [Field Section]`

无论哪种布局，字段区大小 = `4 + section_length`。
