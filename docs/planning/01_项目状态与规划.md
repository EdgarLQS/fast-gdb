## 2. 当前发布边界

| 能力 | 状态 | 边界 |
|---|:---:|---|
| Point/MultiPoint/Polyline/Polygon、Z/M/ZM | ✅ | 在声明数据和自动化范围内完成读取、WKB 和空间判断验收 |
| CircularArc / Bezier / EllipticArc | ✅ | 纯 C++ 默认线性化，Hybrid 可显式 GDAL 回退 |
| 原生 curve WKB | ⚠️ | 仅 GDAL Hybrid 显式模式，不是默认契约 |
| MultiPatch / GeneralMultiPatch | ⚠️ | 不保留完整 part type 和表面拓扑 |
| DateTimeWithOffset | ✅ | 日期值与 offset 独立暴露并覆盖读写回归 |
| Raster、Annotation、Dimension | ❌ | 当前不支持 |
| 完整 SQL / JOIN / 聚合 / 重投影 | ❌ | 不在 Reader 当前范围 |
| Writer 空 schema、Append、Update、Delete、Transaction/Recovery | ✅/⚠️ | 实现已进入 `main`；仅单 Writer、单源 GDB、单图层事务，正式验收仍缺当前 macOS workflow/artifact |
| 35GB/5 亿级真实性能 | 未验收 | 现有结果是受控 1K–10M 基准，不构成生产承诺 |

普通几何使用纯 C++ 主路径；正式输出和精确空间判断共享 `GeometryModel`。不能可靠表达的记录必须返回明确状态，或由显式 Hybrid 策略回退 GDAL。详细能力差异见 [02_GDAL功能对比矩阵.md](02_GDAL功能对比矩阵.md)。

## 3. 当前未完成事项

1. **M18 正式收口**：补齐 GDAL ON/OFF Release、完整 CTest、五套功能合同各三次、性能合同、三类 package consumer、六个 macOS workflow/artifact 及故障注入证据；证据齐全前保持 `Code accepted / Formal acceptance blocked`。
2. **Reader 规模化验收**：后续独立分支处理 Point、MultiPoint、Polyline 的 macOS 10M fresh-open 性能失败档；50M 阶梯暂缓。
3. **真实超大数据**：获得 35GB/5 亿级生产 FileGDB 后，单独验证读取、过滤、索引、内存和磁盘行为。
4. **跨平台 Writer**：Linux、Windows 的安装消费、锁、排他发布和自动化仍 Deferred。
5. **MultiPatch/原生曲线写入**：完整 part type、表面拓扑和原生曲线写入需要独立立项。

完整 OGRLayer/SQL、Raster 和未知未来编码不在当前 Reader 路线中提前承诺。
