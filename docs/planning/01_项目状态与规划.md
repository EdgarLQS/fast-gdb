# 01 — 项目状态与规划

**更新日期**：2026-07-15
**文档状态**：当前权威状态
**状态入口**：[00_规划文档状态索引.md](00_规划文档状态索引.md)

## 1. 当前结论

| 模块/产物 | 状态 | 当前结论 |
|---|:---:|---|
| `usegdal` 高层组件 | ✅ | 既定 Phase 1A–3 已实现 |
| `fast_gdb_linear` | ✅ | 支持范围内的纯 C++ Reader、统一几何模型、ISO WKB、内置曲线和查询已完成验收 |
| `fast_gdb_hybrid` | ✅ | 支持范围内的 fast-gdb 主路径、缓存式 GDAL FID 回退和产品验证已完成 |
| 空间查询 1K–10M | ✅ | 全几何 steady-state 和 10M Polygon fresh-open 已通过当前门槛 |
| `explorgdb writer` | ⚠️ | GDAL 空 schema 的批量直写已有合成测试；非空追加、系统表、完整编辑和生产级索引同步未完成 |
| MultiPatch | ⚠️ | 有限坐标/WKT 兼容；完整 part type 和表面拓扑未实现 |

当前版本在最终验收报告声明的支持范围内可以发布。新增几何类型、真实数据或更大规模性能结论必须重新建立证据，不能由现有结果自动外推。

## 2. 当前发布边界

| 能力 | 状态 | 边界 |
|---|:---:|---|
| Point/MultiPoint/Polyline/Polygon、Z/M/ZM | ✅ | 在声明数据和自动化范围内完成读取、WKB 和空间判断验收 |
| CircularArc / Bezier / EllipticArc | ✅ | 纯 C++ 默认线性化，Hybrid 可显式 GDAL 回退 |
| 原生 curve WKB | ⚠️ | 仅 GDAL Hybrid 显式模式，不是默认契约 |
| MultiPatch / GeneralMultiPatch | ⚠️ | 不保留完整 part type 和表面拓扑 |
| DateTimeWithOffset | ⚠️ | 物理读取安全；offset 未独立暴露 |
| Raster、Annotation、Dimension | ❌ | 当前不支持 |
| 完整 SQL / JOIN / 聚合 / 重投影 | ❌ | 不在 Reader 当前范围 |
| Writer 系统表同步 | ⚠️ | 主数据写入已实现，完整生产写入仍待推进 |
| 35GB/5 亿级真实性能 | 未验收 | 现有结果是受控 1K–10M 基准，不构成生产承诺 |

普通几何使用纯 C++ 主路径；正式输出和精确空间判断共享 `GeometryModel`。不能可靠表达的记录必须返回明确状态，或由显式 Hybrid 策略回退 GDAL。详细能力差异见 [02_GDAL功能对比矩阵.md](02_GDAL功能对比矩阵.md)。

## 3. 当前未完成事项

1. **Reader 规模化验收**：补齐 10M fresh-open 几何矩阵，建立可复用 50M 阶梯，并按真实触发条件处理 `.gdbtablx` 扩展和执行规划问题。
2. **真实超大数据**：获得 35GB/5 亿级生产 FileGDB 后，单独验证读取、过滤、索引、内存和磁盘行为。
3. **Writer**：先完成安全空表批量写、字段/几何三方回读和大文件支持，再推进系统表、索引工作流和高级编辑。
4. **MultiPatch**：完整 part type、表面拓扑和正式输出需要独立立项。

完整 OGRLayer/SQL、Raster 和未知未来编码不在当前 Reader 路线中提前承诺。
