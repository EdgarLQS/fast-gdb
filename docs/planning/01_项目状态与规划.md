# 01 — 项目状态与规划

**更新日期**：2026-07-11  
**文档状态**：当前权威状态  
**状态入口**：[00_规划文档状态索引.md](00_规划文档状态索引.md)

## 1. 当前结论

| 模块/产物 | 当前状态 | 结论 |
|---|:---:|---|
| `usegdal` 高层组件 | ✅ | 既定 Phase 1A-3 已实现 |
| `fast_gdb_linear` | 🧪 | 纯 C++ Reader、统一几何模型、ISO WKB、内置曲线和查询已实现，跨平台 CI 收口中 |
| `fast_gdb_hybrid` | 🧪 | fast-gdb 优先、缓存式 GDAL FID 回退已实现，Linux Hybrid CI 收口中 |
| `explorgdb writer` | ⚠️ | 主数据直写已实现；系统表同步未完成；GDAL 索引助手为可选依赖 |
| MultiPatch | ⚠️ | 有限坐标/WKT 兼容；完整 part type 和表面拓扑未实现 |

当前 Reader 原则：

> 普通几何使用纯 C++ 主路径；所有正式输出和精确空间判断共享 `GeometryModel`；不能可靠表达的记录必须返回明确状态，或由显式 Hybrid 策略回退 GDAL。

## 2. 当前几何架构

```text
FileGDB geometry blob
  -> GeometryModel（整数网格 XY + Z/M）
  -> PolygonTopologyBuilder / BuiltinCurveBackend
  -> ISO WKB（正式）
     WKT（兼容/调试）
     SpatialPredicate（精确查询）
```

实现结果：

- Point、MultiPoint、Polyline、Polygon 与 Z/M/ZM；
- Polygon 外环、洞、多面和岛中岛；
- 环顺序/方向无关；
- 自交、重复、退化和相切拓扑有明确状态；
- CircularArc、Cubic Bezier、EllipticArc、完整圆/椭圆和混合 part；
- `.spx` 候选后复用同一个模型做精确判断；
- `GeometryValue::wkb` 为 ISO WKB-first API；
- WKT 旧接口保留兼容期。

## 3. 两个 Reader 产品

### 3.1 fast_gdb_linear

- 无 GDAL 运行时依赖；
- 普通几何和曲线均走纯 C++；
- 曲线默认按误差参数折线化；
- 适合轻量部署、服务端批量读取和可控依赖环境。

### 3.2 fast_gdb_hybrid

- 普通几何仍走 fast-gdb；
- 曲线拒绝、不支持类型或不可靠 Polygon 拓扑可按策略回退 GDAL；
- Dataset/Layer 使用线程本地缓存；
- 默认 `GDAL FID = fast-gdb FID + 1`，可配置但必须用目标数据验证；
- 支持默认线性 ISO WKB，原生 curve WKB 仅显式 opt-in。

## 4. Reader 已完成能力

- `.gdbtable` / `.gdbtablx`、`.gdbindexes`、`.spx`、`.atx` 读取；
- nullable bitmap 旧记录兼容；
- DateTimeWithOffset 10 字节物理读取；
- CatalogResolver、SRS、domain、Metadata item、Feature Dataset、relationship metadata；
- QueryEngine：FID、顺序扫描、bbox、属性索引和 WHERE 子集；
- GeneralPoint / GeneralMultiPoint / GeneralPolyline / GeneralPolygon；
- Curve flag + `nCurves == 0` 普通 General 几何；
- WKB、WKT 和空间判断统一模型；
- Windows 无共享游标 positional I/O 兼容路径；
- Raster degraded 标记；
- MultiPatch degraded 标记。

## 5. 自动化状态

当前 CI 矩阵：

- Windows/Linux/macOS 纯 C++完整构建与测试；
- Linux GDAL Hybrid 构建与测试；
- `FAST_GDB_CURVE_BACKEND=GDAL` 独立产品构建；
- ASan/UBSan 几何核心；
- build/test 日志作为 Actions artifact 保留。

本轮 CI 已经实际暴露并修复：

- 连续查询框头/实现类型不一致；
- 曲线 `SIZE_MAX` 安全索引重载歧义；
- Writer GDAL include/link 边界；
- 编译器特定 `__int128` 的 Windows 兼容问题。

最终通过结果以 [11_fast-gdb几何正确性与曲线支持实施报告.md](11_fast-gdb几何正确性与曲线支持实施报告.md) 第 6 节为准，不在本页提前声明未完成的运行。

## 6. 发布边界

| 能力 | 状态 | 当前边界 |
|---|:---:|---|
| 常规 Point/MultiPoint/Polyline/Polygon | ✅/🧪 | 自动化和普通样本；复杂真实 Polygon 继续扩充 |
| General 类型 | 🧪 | 合成契约完整，专门真实样本继续扩充 |
| CircularArc / Bezier / EllipticArc | 🧪 | 内置实现和合成测试完成；ArcGIS Pro 真实曲线仍是发布门禁 |
| 原生 curve WKB | 🧪 | 仅 GDAL Hybrid 显式模式 |
| MultiPatch / GeneralMultiPatch | ⚠️ | 纯 C++ 不保留完整 part type/表面拓扑 |
| DateTimeWithOffset | ⚠️ | 物理读取安全；offset 未独立暴露 |
| Raster 像素、Annotation、Dimension | ❌ | 当前不支持 |
| 完整 SQL / JOIN / 聚合 / 重投影 | ❌ | 不在 Reader 当前范围 |
| Writer 系统表同步 | ⚠️ | 主数据写入已实现，完整生产写入仍需继续完善 |

## 7. 真实数据发布门禁

必须由数据而不是合成断言完成：

1. ArcGIS Pro 原生 CircularArc、Bezier、Ellipse、完整圆/椭圆；
2. 2D/Z/M/ZM、多 part 和曲线 Polygon 洞；
3. fast-gdb 与 GDAL 类型、点数、bbox、长度、面积、点包含和空间查询对比；
4. ObjectID/GDAL FID 映射抽样；
5. 复杂 Polygon、坏拓扑和 MultiPatch 样本；
6. 普通几何与曲线几何性能基线。

没有真实曲线样本时，只能声明“代码与合成契约完成”，不能声明 ArcGIS/GDAL 全量等价验收通过。

## 8. 后续范围

- 真实曲线与复杂 Polygon 数据集持续纳入回归；
- MultiPatch 完整 part type/表面模型单独立项；
- Writer 系统表更新和完整 GDAL 兼容写入；
- 覆盖率和性能基线；
- 完整 OGRLayer/SQL 兼容仍不是当前目标。
