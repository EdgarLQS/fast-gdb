## 5. 维护原则

- active 文档不得把计划项写成已通过证据；
- 合成测试、真实数据和历史推算必须分开记录；
- 当前支持范围内的发布结论以对应验收报告为准；
- `.spx` 只生成候选，不能代替精确空间判断；
- GDAL fallback 必须记录后端、原因和 FID 映射；
- MultiPatch 在完整拓扑实现前保持 degraded；
- 35GB/5 亿级真实性能和任何新增能力必须重新验收，不能从 10M 结果外推；
- `SKIPPED` 只表示条件缺失，不能计入通过数量；
- 性能结论必须绑定数据、平台、缓存状态和计时范围，不能概括为所有场景全面优于 GDAL；
- 本地门禁与 GitHub Actions 正式 artifact 必须分别表述；
- 未完成任务完成后必须在清单中改为 `Completed`，并附当前 SHA、命令、日志或 artifact 路径。
