## 2. 当前性能状态

Phase A–H 的空间查询实现已合入 `main`。全几何 1K–10M steady-state 和 10M Polygon fresh-open 已通过历史门禁；Point、MultiPoint、Polyline 的 macOS 10M fresh-open 正确性已通过，但性能存在失败档，见 [2026-07-15 验收记录](../evidence/reader-fresh-open-macos-2026-07-15.md)。50M 阶梯和 35GB/5 亿级真实生产数据仍未完成独立验收。

Phase H 计划已经归档。Point、MultiPoint、Polyline 的 10M fresh-open 已完成 macOS 测量并触发性能后续；50M 阶梯和 35GB/5 亿级
真实生产数据等遗留验证已转入计划 18。只有新增矩阵触发门槛时，才继续实施按需 `.gdbtablx`、
分布感知规划或并行扫描。

## 4. 维护原则

- active 文档不得把计划项写成已通过证据；
- 合成测试、真实数据和历史推算必须分开记录；
- 当前支持范围内的发布结论以最终验收报告为准；
- `.spx` 只生成候选，不能代替精确空间判断；
- GDAL fallback 必须记录后端、原因和 FID 映射；
- MultiPatch 在完整拓扑实现前保持 degraded；
- 35GB/5 亿级真实性能和任何新增能力必须重新验收，不能从 10M 结果外推。
- `SKIPPED` 只表示条件缺失，不能计入通过数量。
- 性能结论必须绑定数据、平台、缓存状态和计时范围，不能概括为所有场景全面优于 GDAL。
