## 1. 目标与成功标准

在 `QueryEngine` 中提供单次空间与属性联合查询入口。调用方只提供 bbox 和现有 WHERE 子集，不再自行执行空间查询、属性查询并求 FID 交集。

成功标准：

1. 最终结果等于“精确空间相交 FID 集 ∩ 完整 WHERE 命中 FID 集”。
2. Point、MultiPoint、Polyline、Polygon 以及 Z/M/ZM 保持既有精确空间语义。
3. 单个安全可索引比较同时利用 `.spx` 和 `.atx`；复合 WHERE、缺索引或不安全索引编码只在精确空间命中行上求值。
4. `.atx` 仅产生候选，不无条件等同最终属性结果；最终必须执行完整 WHERE 复核。
5. 最终 FID 升序、唯一，并与 GDAL `SetSpatialFilterRect + SetAttributeFilter` 完整 FID 向量一致。
6. 既有 `SpatialBbox`、`AttributeDouble`、`AttributeString`、`WhereClause` 和安装面保持兼容。
7. GDAL ON/OFF Release、完整 CTest、package consumer 和性能门禁有实际证据后才可 Accepted。

## 2. GDAL OpenFileGDB 官方实现研究

### 2.1 官方执行方式

GDAL OpenFileGDB 驱动不是在调用方物化两套结果后求交。其核心流程为：

1. `SetSpatialFilterRect()` 构建空间索引迭代器。
2. `SetAttributeFilter()` 将 OGR SQL 表达式转换为属性索引迭代器。
3. 两种迭代器同时可用时，通过 `FileGDBIterator::BuildAnd()` 组合为联合候选迭代器。
4. 联合迭代器按 FID 有序推进，执行流式集合交集。
5. 候选 Feature 仍经过精确几何过滤。
6. 当属性索引不足以完整证明表达式时，仍执行完整属性表达式复核。

对应源码入口：

- `ogr/ogrsf_frmts/openfilegdb/ogropenfilegdblayer.cpp`
  - `SetAttributeFilter()`
  - `BuildIteratorFromExprNode()`
  - `BuildCombinedIterator()`
  - `GetNextFeature()`
- `ogr/ogrsf_frmts/openfilegdb/filegdbindex.cpp`
  - `FileGDBIterator::BuildAnd()`
  - `FileGDBIterator::BuildOr()`

### 2.2 对 fast-gdb 的约束

GDAL 对字符串 `.atx` 不无条件信任。FileGDB 字符串索引存在 UTF-16 定长、空格填充和截断行为，因此索引命中可能只是候选超集。

fast-gdb 首版采用更保守规则：

- 所有 `.atx` 路径都执行完整 WHERE 复核。
- 字符串首版只对 `=` 和 `>=` 使用 `.atx` 候选。
- 当前 `.atx` 解码器不能安全还原 UTF-16 surrogate pair，非 BMP 字符串直接回退到空间候选求值，避免假阴性。
- Int16、Float32、Int64 等当前无法由 trailer 唯一确定物理语义的数值编码不进入快速路径。
- 复合 `AND`、`OR`、`IN` 首版不构造布尔索引计划。

## 3. 公开接口

`SpatialWhere` 只追加到枚举末尾，保持既有枚举源码兼容顺序：

```cpp
enum class QueryKind {
    ReadByFid,
    SequentialScan,
    SpatialBbox,
    AttributeDouble,
    AttributeString,
    WhereClause,
    SpatialWhere
};
```

请求复用已有 bbox 和 `where_clause` 字段：

```cpp
QueryRequest request;
request.kind = QueryKind::SpatialWhere;
request.xmin = 0.0;
request.ymin = 0.0;
request.xmax = 10.0;
request.ymax = 10.0;
request.where_clause = "population >= 1000 AND category = 'A'";

QueryResult result = engine.query(request);
```

不增加数值、字符串各自的组合方法。

### 3.1 执行路径

- `spatial-where:spx+atx`：空间和属性索引均参与候选缩小，随后完整 WHERE 复核。
- `spatial-where:spatial-candidates`：空间索引可用，但属性索引缺失、不安全或表达式不可索引。
- `spatial-where:sequential`：空间索引不可用，复用现有精确空间顺序路径后评估属性。
- `spatial-where:invalid`：bbox 或 WHERE 非法，不执行查询。

### 3.2 联合指标

`QueryResult` 增加 `CombinedQueryMetrics`：

```cpp
struct CombinedQueryMetrics {
    size_t spatial_candidate_count = 0;
    size_t spatial_match_count = 0;
    size_t attribute_candidate_count = 0;
    size_t attribute_tested = 0;
    size_t final_match_count = 0;
    double spatial_ms = 0.0;
    double attribute_ms = 0.0;
    double intersection_ms = 0.0;
    double total_ms = 0.0;
    bool used_spatial_index = false;
    bool used_attribute_index = false;
};
```

指标只用于诊断与性能证据，不改变查询语义。

## 4. 实际实现

### 4.1 WHERE 内部模块

已新增：

- `query_where_internal.h`
- `query_where_internal.cpp`

职责：

- tokenizer、parser、AST 和字段绑定；
- 数值、字符串比较；
- `AND`、`OR`、`IN` 和括号；
- 字段名大小写不敏感；
- SQL 单引号转义 `''`；
- 空 WHERE、语法错误、未知字段和非有限数字诊断；
- 单个类型兼容比较的 `.atx` 候选识别；
- 有序 FID 线性交集。

该头文件属于 Reader 内部实现，安装规则已明确排除，不泄露 AST 或 parser 类型。

### 4.2 字段到 `.atx` 的解析

已在 `GdbCatalog` 增加 `.gdbindexes` 查找入口。

联合规划器通过：

```text
WHERE 字段名
  -> .gdbindexes 的 IndexEntry.column_name
  -> IndexEntry.name
  -> aXXXXXXXX.<index-name>.atx
```

不猜测索引名等于字段名。

### 4.3 候选字段扫描

已新增 `GdbTableParser::scan_field_candidates()`：

- 根据 `.gdbtablx` 解析候选 FID 物理偏移；
- 按物理偏移读取，降低随机 I/O；
- mmap 路径提供零拷贝 `FieldRef`；
- fd 路径复用行缓冲；
- 完整校验字段物理布局和 nullable 位图；
- 扫描不可用时回退 `read_record_by_fid()`；
- QueryEngine 最终恢复 FID 数值升序。

### 4.4 联合执行

`QueryEngine::query_spatial_where()` 当前流程：

1. 校验 bbox。
2. 编译并绑定 WHERE。
3. 调用 `query_bbox_unified()` 得到经过精确几何判断的空间命中。
4. 空间空集直接返回，不打开 `.atx`。
5. 单个安全比较解析 `.gdbindexes` 与 `.atx`。
6. `.atx` 候选显式排序、去重。
7. 空间 FID 和属性候选 FID 线性交集。
8. 对交集候选执行完整 WHERE 复核。
9. 缺失或损坏 `.atx`、不安全编码、复合表达式均回退到空间候选求值。
10. 最终 FID 排序、去重并写入联合指标。

- **可提交**：GDAL ON/OFF Release、完整 CTest、GDAL 完整 FID 对照、package consumer、100K/10M 性能矩阵和回归门禁全部通过。
