## 1. 目标与成功标准

本分支提供两个相互兼容的入口：

1. `QueryEngine::query()`：继续返回最终零基 FID 集，既有调用方无需迁移；
2. `QueryEngine::open_cursor()`：逐条返回 FID、完整 `FeatureRecord` 和规范化
   `GeometryValue`，不一次性保存全部完整 Feature。

成功标准：

1. 联合结果等于“精确空间相交 FID 集 ∩ 完整 WHERE 命中 FID 集”；
2. `.spx` 和 `.atx` 都只提供候选，最终保持精确几何和完整 WHERE；
3. Point、MultiPoint、Polyline、Polygon、Z/M/ZM 保持既有语义；
4. `query()` 仍返回升序、唯一、零基 FID；
5. cursor 每次只物化单个完整对象；候选模式允许保存最终 FID vector；
6. SequentialScan cursor 不先生成全表 FID；
7. 正常 EOF、Failed 和 moved-from 可以区分；
8. `move_to(fid)` 支持向前、向后和跳跃；
9. 字段、NULL、Binary、DateTimeWithOffset 和 GeometryValue 复用成熟 Reader 语义；
10. 旧查询 execution path、fallback 和安装面保持兼容；
11. 实际构建、CTest、consumer 和性能证据齐全后才能 Accepted。

## 2. 空间属性联合查询

公开请求继续复用 bbox 和 WHERE：

```cpp
explorgdb::QueryRequest request;
request.kind = explorgdb::QueryKind::SpatialWhere;
request.xmin = 0.0;
request.ymin = 0.0;
request.xmax = 10.0;
request.ymax = 10.0;
request.where_clause = "population >= 1000";

explorgdb::QueryResult result = engine.query(request);
```

执行路径：

- `spatial-where:spx+atx`；
- `spatial-where:spatial-candidates`；
- `spatial-where:sequential`；
- `spatial-where:invalid`。

联合查询当前实现：

1. 校验 bbox；
2. 编译并绑定 WHERE；
3. 调用 `query_bbox_unified()` 得到精确空间命中；
4. 单个安全比较解析 `.gdbindexes` 和 `.atx`；
5. 属性候选排序、去重；
6. 与精确空间 FID 线性交集；
7. 对交集候选执行完整 WHERE；
8. 缺失、损坏或不安全索引回退；
9. 最终排序、去重并记录 `CombinedQueryMetrics`。

安全边界：

- 字符串当前只对可证明安全的 `=` 和 `>=` 使用 `.atx`；
- 非 BMP 回退；
- `!=` 回退，避免 NaN 候选不完备；
- 函数索引只关联字段，不进入直接比较快速路径；
- 不明确的 Int16、Float32、Int64 trailer 语义回退；
- `.atx` 文件、页面、页链、计数和 FID 任一损坏均 fail closed。

## 3. 完整 Feature 流式接口

公开接口：

```cpp
struct QueryFeature {
    uint32_t fid = 0;
    FeatureRecord record;
    GeometryValue geometry;
};

class FeatureCursor {
public:
    FeatureCursor(FeatureCursor&&) noexcept;
    FeatureCursor& operator=(FeatureCursor&&) noexcept;
    FeatureCursor(const FeatureCursor&) = delete;
    FeatureCursor& operator=(const FeatureCursor&) = delete;
    ~FeatureCursor();

    bool next(QueryFeature& feature);
    bool move_to(uint32_t fid);
    bool done() const noexcept;
    const QueryResult& query_result() const noexcept;
    const std::string& error() const noexcept;
};

class QueryEngine {
public:
    FeatureCursor open_cursor(const QueryRequest& request);
};
```

实现位于：

- `query_engine.h`：公开声明；
- `feature_cursor.cpp`：PImpl、状态机、执行模式和完整对象组装；
- `query_engine.cpp`：活动游标守卫、open generation 和 cursor generation；
- `query_engine_geometry.cpp`：直接空间查询活动游标守卫。

内部 parser、`FieldRef` 和 WHERE AST 未进入公开安装面。

## 4. `move_to(fid)` 定位语义

`move_to()` 参数是零基 FID，不是结果序号。

固定行为：

```text
move_to(target)
  -> 下一次 next() 返回当前查询结果中第一个 FID >= target 的对象
```

因此：

- 支持向前移动；
- 支持向后移动；
- 支持任意 FID 跳跃；
- `move_to(0)` 等价于 rewind；
- 指定 FID 被删除时，顺序模式跳到下一个 live FID；
- 指定 FID 不满足过滤时，候选模式跳到下一个匹配 FID；
- 目标后没有结果时返回 `false`，进入正常 Exhausted；
- Exhausted 游标可在 engine 未重开且无其他活动游标时重新定位；
- Failed 或 moved-from 游标不能重新定位。

实现：

- 候选 FID 模式使用 `std::lower_bound`；
- SequentialScan 模式重设待扫描 FID，并用 `has_feature()` 跳过删除槽；
- 任何 tablx 访问前必须先取得 engine lease；
- engine 重开后旧 cursor 进入 Failed，不能复用旧计划。

## 5. 两种执行模式

### 5.1 候选 FID 模式

适用于：

- `ReadByFid`；
- `SpatialBbox`；
- `AttributeDouble`；
- `AttributeString`；
- `WhereClause`；
- `SpatialWhere`。

步骤：

1. 先调用既有 `query(request)`；
2. 保留 execution path、fallback 和 metrics；
3. 最终 FID 排序、去重；
4. 清除 `QueryResult::record`，避免 ReadByFid 重复保存完整对象；
5. `next()` 按 FID 逐条完整读取。

只保存 `vector<uint32_t>`，不保存完整 Feature vector。

### 5.2 真正顺序流模式

适用于 `SequentialScan`：

- 不调用 `query_sequential_scan()`；
- 不物化全表 FID；
- 只保存 `feature_limit` 和下一个待查槽；
- 依据 `.gdbtablx` 的 `has_feature()` 跳过删除槽；
- 每次 `next()` 只构造一条完整 Feature；
- `query_result().matched_fids` 保持为空。

## 6. 完整对象语义

`QueryFeature` 保证：

- `feature.fid == feature.record.fid`；
- `record.field_values` 与 table fields 顺序一致；
- ObjectID 使用 fast-gdb 既有 `fid + 1`；
- NULL 和 nullable bitmap 保持 Reader 语义；
- Binary 保持原始字节；
- DateTimeWithOffset 保持 `DateTimeOffsetValue`；
- Geometry 槽位保持既有兼容 WKT；
- `geometry` 使用同一行的规范化 ISO WKB-first `GeometryValue`；
- Raster 仍按既有 NULL 占位，不增加像素解码。

特殊情况：

- 无几何字段：成功返回，`UnsupportedType`，diagnostic 为
  `table has no geometry field`；
- NULL geometry：成功返回 `Empty`；
- 非 NULL 空几何：由既有 GeometryModel/WkbWriter 返回 `Empty`；
- 损坏或不支持且无法安全处理的几何：当前 Feature 失败，cursor 进入 Failed；
- ObjectID-only 零长度合法行：cursor 物化 ObjectID 和 nullable NULL；
- 无法从零字节恢复的非空字段：Failed。

`next()` 总是先构造局部 candidate，全部成功后才覆盖调用方输出。失败不会留下半更新对象。

## 7. 状态机和生命周期

状态：

| 状态 | `next()` | `done()` | `error()` |
|---|---|---:|---|
| Ready | 返回下一条或转 Exhausted/Failed | false | 空 |
| Exhausted | false | true | 空 |
| Failed | false | false | 首次错误 |
| MovedFrom | false | true | 空 |

生命周期规则：

- cursor 可移动、不可复制；
- QueryEngine 不可复制或移动，确保 cursor 持有地址稳定；
- QueryEngine、GdbCatalog 和 ResolvedTable 必须比 cursor 活得更久；
- 同一个 engine 同时只允许一个活动 cursor；
- 第二次 `open_cursor()` 返回 Failed：`another feature cursor is active`；
- 正常耗尽、失败、析构或 move 赋值会释放 lease；
- lease 使用单调 cursor generation，旧析构不能清除新 cursor；
- `open()` 使用 open generation，engine 重开后旧 cursor 不能 reacquire；
- 活动 cursor 期间 `open/query/read_by_fid/scan/query_bbox_unified` 按固定规则拒绝；
- 不引入隐式锁，不声明同一 engine 线程安全。

## 8. 调用示例

```cpp
explorgdb::QueryRequest request;
request.kind = explorgdb::QueryKind::SpatialWhere;
request.xmin = 0.0;
request.ymin = 0.0;
request.xmax = 10.0;
request.ymax = 10.0;
request.where_clause = "population >= 1000";

auto cursor = engine.open_cursor(request);

// 可以先定位；下一条是第一个匹配且 FID >= 500 的对象。
cursor.move_to(500);

explorgdb::QueryFeature feature;
while (cursor.next(feature)) {
    consume(feature.fid,
            feature.record.field_values,
            feature.geometry.wkb);
}

if (!cursor.done()) {
    report_error(cursor.error());
}
```

循环结束后必须检查 `done()`；只检查 `next() == false` 会把失败误当 EOF。
