## 1. 目标

本分支保留 FID-only 查询，同时新增完整对象流式读取：

```cpp
QueryResult QueryEngine::query(const QueryRequest& request);
FeatureCursor QueryEngine::open_cursor(const QueryRequest& request);
```

目标：

1. `SpatialWhere` 等于精确空间结果与完整 WHERE 结果的交集；
2. `.spx/.atx` 只提供候选，不能替代最终判断；
3. `query()` 继续返回升序、唯一、零基 FID；
4. cursor 每次只物化一个完整 Feature；
5. SequentialScan 不先物化全表 FID；
6. EOF 与失败明确区分；
7. `move_to(fid)` 支持前后和跳跃；
8. 完整对象对同一 FID 只定位一次、只解码一次 GeometryModel；
9. 从同一 GeometryModel 生成 ISO WKB，需要 WKT 时由 `GeometryValue::to_wkt()` 按需转换；
10. 旧查询、安装面和 Reader 字段语义保持兼容。

## 2. 公开接口

```cpp
struct QueryFeature {
    uint32_t fid = 0;
    FeatureRecord record;
    GeometryValue geometry;
};

class FeatureCursor {
public:
    FeatureCursor(FeatureCursor&&) noexcept;
    FeatureCursor& operator=(FeatureCursor&&) noexcept;
    FeatureCursor(const FeatureCursor&) = delete;
    FeatureCursor& operator=(const FeatureCursor&) = delete;
    ~FeatureCursor();

    bool next(QueryFeature& feature);
    bool move_to(uint32_t fid);
    bool done() const noexcept;
    const QueryResult& query_result() const noexcept;
    const std::string& error() const noexcept;
};
```

`QueryEngine` 不可复制、可移动构造但不可移动赋值。cursor 使用稳定的堆控制块和 table 对象，engine 移动后 cursor 继续有效，源 engine 安全不可用。

one-pass profile 为请求级 opt-in：

```cpp
QueryRequest request;
request.profile_feature_reads = true;
```

默认 `false`；普通读取不调用 profile clock。阶段结果写入
`QueryResult::feature_cursor_metrics`。

## 3. 联合查询

流程：

1. 校验 bbox 和 WHERE；
2. `query_bbox_unified()` 得到精确空间命中；
3. 单个安全比较解析 `.gdbindexes` 和 `.atx`；
4. 属性候选排序、去重；
5. 与精确空间 FID 线性交集；
6. 对交集执行完整 WHERE；
7. 缺失、损坏或不安全索引回退；
8. 最终 FID 排序、去重并记录指标。

执行路径：

- `spatial-where:spx+atx`；
- `spatial-where:spatial-candidates`；
- `spatial-where:sequential`；
- `spatial-where:invalid`。

安全回退包括非 BMP、`!=`、函数索引、不明确数值编码和任意 `.atx` 结构损坏。

## 4. Cursor 执行模式

### 4.1 候选 FID 模式

适用于 ReadByFid、SpatialBbox、两类属性查询、WhereClause 和 SpatialWhere：

- 调用既有 `query(request)`；
- 保存 execution path、fallback 和 metrics；
- FID 排序、去重；
- 清除 ReadByFid 的重复完整 record；
- 按 FID 逐条读取完整对象。

只保存 FID vector，不保存完整 Feature vector。

### 4.2 SequentialScan 流模式

- 不调用全表 `query_sequential_scan()`；
- 只保存 feature limit 和下一个槽位；
- 用 `.gdbtablx` `has_feature()` 跳过删除槽；
- 每次 `next()` 只构造一条完整对象；
- `query_result().matched_fids` 保持为空。

## 5. `move_to(fid)`

参数是 fast-gdb 零基 FID，不是结果序号。

```text
move_to(target)
  -> 下一次 next() 返回当前查询结果中第一个 FID >= target 的对象
```

- 支持向前、向后、rewind 和任意跳跃；
- 候选模式使用 `lower_bound`；
- 顺序模式从 target 槽开始并跳过删除槽；
- target 不匹配时跳到下一个匹配结果；
- target 后无结果时进入正常 Exhausted；
- Exhausted cursor 可在 engine 未改变且无其他 cursor 活动时重新定位；
- Failed、moved-from 或 engine 已重开时不能重新定位；
- reacquire 必须在任何 parser/tablx 访问前完成。

## 6. one-pass 完整对象语义

WKB-first 改造前 cursor 对每个命中 FID 依次调用：

```text
read_record_by_fid()       -> 字段 + eager WKT
read_geometry_value()      -> 再次定位 + GeometryModel + ISO WKB
```

优化后调用：

```cpp
read_feature_by_fid(fid, record, geometry, optional_metrics);
```

单行流程：

1. 一次通过 `.gdbtablx` 定位记录；
2. 一次读取或取得 mmap row view；
3. 探索 nullable bitmap/layout，选定唯一 winning layout；
4. 物化 ObjectID、标量、String/XML、Binary、Raster 占位和 NULL；
5. 保存 winning geometry slice；
6. 一次生成 `GeometryModel`；
7. 从同一模型写 ISO WKB；
8. Geometry 字段槽归一化为空字符串占位；
9. 全部成功后才 move 到调用方对象；需要 WKT 时显式调用 `to_wkt()`。

支持：

- ObjectID、标量、String/XML；
- NULL 和 nullable bitmap；
- Binary 原始字节；
- DateTimeWithOffset 既有表示；
- Geometry 空占位和独立的规范化 ISO WKB；
- 无几何表：成功 `UnsupportedType`；
- NULL/Empty geometry：成功 `Empty`；
- ObjectID-only 零长度行：生成 ObjectID 和 nullable NULL；
- 损坏、geometry slice 缺失或无法恢复的非空对象：Failed。

`read_record_by_fid()` 与 `read_geometry_value()` 保留为 WKB-first 独立入口，也是当前
benchmark 的 record+geometry 对照路径。

## 7. 生命周期和状态

| 状态 | `next()` | `done()` | `error()` |
|---|---|---:|---|
| Ready | 下一条或转 EOF/Failed | false | 空 |
| Exhausted | false | true | 空 |
| Failed | false | false | 首次错误 |
| MovedFrom | false | true | 空 |

规则：

- 同一 engine 同时一个活动 cursor；
- cursor generation 防迟到析构；
- open generation 防 engine 重开后旧计划复用；
- `open()` 重置 parser、空间索引缓存和 capability 状态；
- capability 判定失败时不保留可用 parser；
- 活动 cursor 期间 engine 读入口拒绝；
- QueryEngine、Catalog 和 ResolvedTable 必须比 cursor 活得更久；
- 不声明同一 QueryEngine 线程安全。

## 10. 性能与证据方法

优化前基线保留在技术文档第 1.10 节：

```text
721f186 / Release / GDAL 3.13.0 / 100K Point / 1,000 results
FeatureCursor median 3.869 ms
legacy median        3.899 ms
GDAL median          1.366 ms
```

这些数字是 one-pass 优化前的对照，不代表当前结果。

Full-feature schema-v3 runner 显式开启：

```bash
FAST_GDB_RUN_FEATURE_CURSOR_BENCHMARKS=1 \
FAST_GDB_BENCHMARK_OUTPUT_DIR=<external-dir> \
ctest --test-dir build-on --output-on-failure \
  -R FeatureCursorBenchmarkTest.Point100KWkbFirstEvidence
```

每个样本分别打开 cursor engine、record+geometry engine 和 GDAL dataset，计时范围为：

```text
engine-or-dataset-open-through-last-feature
```

方法：

- Cursor、record+geometry、GDAL 各 5 个样本；
- 使用五样本轮换顺序，不再让 GDAL 固定最后；
- 三方进入相同 checksum sink；
- 完整 FID、Int32、Binary、ISO WKB、count 和 output bytes 必须一致；
- profile 样本独立，不计入 median/p95；
- profile 记录查询规划、row lookup、field materialization、GeometryModel、WKB、checksum；
- `GeometryValue::to_wkt()` 独立计时，不进入三条 full-feature 中位数；
- evidence 声明 `fresh-open-not-strict-cold`；
- 未配置输出目录时写系统临时目录，不写仓库。

### 10.1 one-pass 复测结果与下一轮优化方向

`8f23001` 上连续执行 5 轮独立 benchmark，每轮包含 Cursor、legacy、
GDAL 各 5 个轮换顺序样本。五轮中位数的中位数为：

| 路径 | 中位数 | 相对 Cursor |
|---|---:|---:|
| FeatureCursor | 3.852 ms | 1.00× |
| legacy | 3.857 ms | 1.00× |
| GDAL `GetNextFeature()` | 1.306 ms | 0.34× |

5 轮均为 1,000 个结果，三条路径的 count 和 checksum 一致，
`correct=true`。Cursor 相对 legacy 快约 0.13%，属于持平；耗时约为
GDAL 的 2.95 倍。该结论只适用于 100K Point、1% 最终命中率和
fresh-open 缓存语义。

profile 显示查询阶段约为 3.16–3.44 ms，其中属性候选阶段约为
2.61–2.86 ms，空间候选阶段约为 0.52–0.56 ms。row lookup、字段物化、
几何解码、WKT、WKB 和 checksum 合计约 0.37 ms。因此下一轮不继续优化
`FeatureCursor::next()` 对象构造，优先缩短 `.atx` 属性候选获取和联合查询规划。

优化顺序：

1. 细分 `.atx` profile：分别记录索引元数据解析、B+ 树页导航、候选读取、
   排序去重和最终 WHERE 复核，先确认 2.6 ms 的真实归属；
2. 优先实现请求内的索引元数据和页缓存复用，避免 SpatialWhere 在同一次
   查询中重复打开、解析或读取 `.atx`；
3. 若 profile 证明排序去重或交集为主要热点，再改为保序候选输出和单次
   线性交集；不在没有 profile 证据时重写索引解析器；
4. 每次改动使用 schema-v3 runner 进行 current/record+geometry/GDAL 交替采样，
   current 相对 `8f23001` 的中位数必须改善且不得出现超过 5% 回退；
5. FID 顺序、结果数、字段、Binary、ISO WKB 和 checksum 必须与 legacy/GDAL
   一致，正确性失败时性能数字无效。

仍需 strict-cold、peak RSS、1%/30%/100%、10M 多几何、current/main/GDAL 和 5% 门禁。

## 13. 验收判定

- **Blocked**：错误被当 EOF、`move_to` 返回错误 FID、one-pass 与 legacy/GDAL 完整对象不一致、生命周期破坏 engine、顺序流物化全表、旧查询回归、损坏索引假空集或安装面泄露；
- **Fix then re-review**：独立审核发现 P0/P1；
- **Ready for formal validation**：代码审核无阻断项但证据未齐；
- **Accepted**：构建、CTest、consumer、完整对象对等、100K/10M、strict-cold、peak RSS 和门禁全通过。
