## 1. 目标与成功标准

在 `QueryEngine` 中提供单次空间与属性联合查询入口。调用方只提供 bbox 和现有 WHERE 子集，不再自行执行空间查询、属性查询并求 FID 交集。

成功标准：

1. 最终结果等于“精确空间相交 FID 集 ∩ 完整 WHERE 命中 FID 集”。
2. Point、MultiPoint、Polyline、Polygon 以及 Z/M/ZM 保持既有精确空间语义。
3. 单个可证明安全的比较同时利用 `.spx` 和 `.atx`。
4. 复合 WHERE、缺索引、损坏索引或不安全索引编码只在精确空间命中行上求值。
5. `.atx` 仅产生候选，最终必须执行完整 WHERE 复核。
6. 最终 FID 升序、唯一，并与 GDAL `SetSpatialFilterRect + SetAttributeFilter` 完整 FID 向量一致。
7. 既有 `SpatialBbox`、`AttributeDouble`、`AttributeString`、`WhereClause` 和安装面保持兼容。
8. GDAL ON/OFF Release、完整 CTest、package consumer 和性能门禁有实际证据后才可 Accepted。

## 2. GDAL OpenFileGDB 参考实现

GDAL OpenFileGDB 的联合查询核心流程：

1. 空间过滤构建空间索引迭代器；
2. 属性表达式尝试构建属性索引迭代器；
3. 两种迭代器同时可用时执行有序 FID 交集；
4. 候选仍经过精确几何判断；
5. 属性索引不足以证明完整表达式时仍执行属性表达式复核。

参考入口：

- `ogr/ogrsf_frmts/openfilegdb/ogropenfilegdblayer.cpp`
  - `SetAttributeFilter()`
  - `BuildIteratorFromExprNode()`
  - `BuildCombinedIterator()`
  - `GetNextFeature()`
- `ogr/ogrsf_frmts/openfilegdb/filegdbindex.cpp`
  - `FileGDBIterator::BuildAnd()`
  - `FileGDBIterator::BuildOr()`

fast-gdb 首版采用更保守的候选规则：

- 所有 `.atx` 路径都执行完整 WHERE 复核；
- 字符串只对 `=` 和 `>=` 使用候选；
- 非 BMP 字符串回退，避免当前 UTF-16 decoder 对 surrogate pair 产生假阴性；
- `!=` 回退，避免 NaN 比较导致候选不完备；
- Int16、Float32、Int64 等不能由当前 trailer 唯一确定物理语义的编码不进入快速路径；
- `LOWER(field)` 和其他函数索引只用于字段关联，不用于直接比较快速路径；
- 复合 `AND`、`OR`、`IN` 首版不构造布尔索引计划。

## 3. 公开接口

`SpatialWhere` 追加到枚举末尾：

```cpp
enum class QueryKind {
    ReadByFid,
    SequentialScan,
    SpatialBbox,
    AttributeDouble,
    AttributeString,
    WhereClause,
    SpatialWhere
};
```

请求复用已有 bbox 和 `where_clause`：

```cpp
QueryRequest request;
request.kind = QueryKind::SpatialWhere;
request.xmin = 0.0;
request.ymin = 0.0;
request.xmax = 10.0;
request.ymax = 10.0;
request.where_clause = "population >= 1000 AND category = 'A'";

QueryResult result = engine.query(request);
```

不增加数值、字符串各自的组合方法。

### 3.1 执行路径

- `spatial-where:spx+atx`：空间和属性索引均参与候选缩小，随后完整 WHERE 复核；
- `spatial-where:spatial-candidates`：空间索引可用，但属性索引缺失、损坏、不安全或表达式不可索引；
- `spatial-where:sequential`：空间索引不可用，复用既有精确空间顺序路径后评估属性；
- `spatial-where:invalid`：bbox 或 WHERE 非法，不执行查询。

### 3.2 联合指标

`QueryResult` 增加 `CombinedQueryMetrics`：

```cpp
struct CombinedQueryMetrics {
    size_t spatial_candidate_count = 0;
    size_t spatial_match_count = 0;
    size_t attribute_candidate_count = 0;
    size_t attribute_tested = 0;
    size_t final_match_count = 0;
    double spatial_ms = 0.0;
    double attribute_ms = 0.0;
    double intersection_ms = 0.0;
    double total_ms = 0.0;
    bool used_spatial_index = false;
    bool used_attribute_index = false;
};
```

指标只用于诊断与性能证据，不改变查询语义。

## 4. 当前实现

### 4.1 WHERE 内部模块

已新增：

- `query_where_internal.h`
- `query_where_internal.cpp`

职责：

- tokenizer、parser、AST 和字段绑定；
- 数值、字符串比较；
- `AND`、`OR`、`IN` 和括号；
- 字段名大小写不敏感；
- SQL 单引号转义 `''`；
- 空 WHERE、语法错误、未知字段和非有限数字诊断；
- 单个类型兼容比较的 `.atx` 候选识别；
- 有序 FID 线性交集。

内部头已从安装规则排除。

### 4.2 字段到 `.atx` 的映射

联合规划器使用：

```text
WHERE 字段名
  -> .gdbindexes 原始索引表达式
  -> 字段关联及直接表达式判定
  -> IndexEntry.name
  -> aXXXXXXXX.<index-name>.atx
```

不猜测索引名等于字段名，也不把函数索引误当作直接字段索引。

### 4.3 候选字段扫描

新增 `GdbTableParser::scan_field_candidates()`：

- 根据 `.gdbtablx` 获取候选 FID 物理偏移；
- 按物理偏移读取，降低随机 I/O；
- mmap 路径提供零拷贝 `FieldRef`；
- fd 路径复用行缓冲；
- 完整校验字段物理布局和 nullable 位图；
- 能穿过 Geometry、Raster、UUID、Binary 和 DateTimeWithOffset 等非目标列；
- 扫描不可用时回退 `read_record_by_fid()`；
- 最终恢复 FID 数值升序。

### 4.4 联合执行

`QueryEngine::query_spatial_where()` 当前流程：

1. 校验 bbox；
2. 编译并绑定 WHERE；
3. 调用 `query_bbox_unified()` 得到精确空间命中；
4. 空间空集直接返回；
5. 单个安全比较解析 `.gdbindexes` 与 `.atx`；
6. `.atx` 候选排序、去重；
7. 空间 FID 与属性候选 FID 线性交集；
8. 对交集候选执行完整 WHERE 复核；
9. 缺失、损坏或不安全 `.atx` 回退到空间候选求值；
10. 最终 FID 排序、去重并写入联合指标。

### 4.5 `.atx` fail-closed 安全边界

三轮自审后增加：

- 文件长度、`streamoff`、`size_t` 和 `streamsize` 边界校验；
- 页面区必须为 4096 字节整数倍；
- tree depth、页号、页容量和 FID 校验；
- 叶页链访问预算，阻止循环页链；
- 实际条目数必须等于 trailer `total_value_count`；
- 任一结构错误均返回解析失败，联合查询不得使用不完整候选集。
