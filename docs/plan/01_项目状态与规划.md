# 项目状态与规划

## 当前状态

fast-gdb 正式定位为 FileGDB Reader only：

- `fast_gdb::linear`：纯 C++ Reader；
- `fast_gdb::hybrid`：Reader + GDAL 复杂几何 fallback；
- `fast_gdb::unified`：统一 Dataset/Group/Layer/Cursor 与后端路由；
- 不提供 Writer target、Writer API 或 Writer ABI。

/

FileGDB 编辑统一由 GDAL/OpenFileGDB 或 ArcGIS 完成。

当前唯一正式支持的编辑边界仍是：

```text
close Readers → GDAL edit → GDALClose → reopen Readers
```

Adaptive Reader 已实现为可选 target，覆盖同进程写入协调、Busy、Reader 过期和 fresh GDAL 只读回退；未知外部 Writer、跨平台、压力、性能和多 GDAL 版本证据仍待补齐。

/

统一访问与 GDAL/S3 路由已作为 v0.2.0 安装 target 实现：

```text
fast_gdb::unified::Dataset::open(uri, Auto)
  → 本地 .gdb：fast-gdb
  → s3://... / /vsis3/...：GDAL OpenFileGDB
  → fast-gdb 不支持的只读能力：GDAL OpenFileGDB
```

该实现不改变 `linear/hybrid/adaptive` 的合同，也不引入 fast-gdb 原生 S3 Reader、
/

Writer 或在线对象存储发布能力。S3 路由仍为 Experimental / Unverified。

## 当前架构目标

```text
FileGDB
/

  → catalog / system tables
  → table / tablx / indexes
  → query planning
  → FeatureCursor
  → FeatureRecord + GeometryValue
  → ISO WKB
```

计划中的可选编排层：

```text
stable source
  → fast-gdb fast path
  → validated materialized result

/

writer active / source changed
  → fail closed: SourceBusy or ReaderExpired

source stable + fast unsupported
  → fresh GDAL read-only fallback
```

## 当前优先级

### P0：正确性

- 真实 FileGDB parity；
- FID、删除槽和零长度记录；
/

- `.spx/.atx` 损坏检测和安全回退；
- WKB-first 几何；
- GDAL 写后完整重开验证；
- Adaptive Reader 读取前后源状态验证和结果丢弃规则。

### P0：Adaptive Reader 生命周期设计

/

- 协调模式 `writer_active/generation` 探针；
- 写入期间确定性返回 `SourceBusy`；
- generation 变化使旧 Reader 返回 `ReaderExpired`；
- fast-gdb 读取期间源变化时丢弃结果；
- 源稳定后使用 fresh GDALDataset 只读恢复；
- 无协调外部 Writer 检测明确限定为 best-effort；
- 任何读取结果必须完整物化并通过后置验证后才发布。

### P1：性能

- 顺序扫描；
- FID 随机访问；
- 属性和空间索引选择性；
- SpatialWhere 融合路径；
- mmap、缓存和内存分配；
- Adaptive 快路径的文件状态检查预算。

### P1：生命周期

- cursor/engine/table/catalog 所有权；
- 外部写入前 Reader drain；
- 写后全量重开；
- 禁止同目录读写重叠；
- 源变化后的 catalog/table/index/mmap 全量失效；
- fresh GDAL fallback 禁止复用旧 Dataset。

### P2：兼容性

- Windows/Linux/macOS；
- GDAL 稳定版本矩阵；
- ArcGIS 创建的复杂 GDB；
- MultiPatch、关系、域、层级、栅格和 64-bit ObjectID profile；
- 本地盘和网络盘的外部写入检测 profile。
- 统一 `Dataset/Layer/Feature/Cursor` facade、`Auto/FastOnly/GdalOnly` 路由和
  `BackendReport`；
/

- `FastFileGDB` 只读 GDAL/OGR 兼容入口；
- S3/`/vsis3/` 的 GDAL 真实环境 characterization。

## 不再规划

- 自研 FileGDB Writer；
- Append/Update/Delete API；
/

- Writer transaction/recovery；
- VersionedGdbStore；
- Writer benchmark；
- Writer package target；
- Reader 内建在线发布；
- fast-gdb 创建或删除 Writer activity marker；
- 对任意外部 Writer 的绝对检测保证；
- Writer 活动期间强行通过 GDAL 返回数据。

## GDAL 集成路线

GDAL 作为：

1. 测试数据生成器；
2. FileGDB 编辑器；
3. 正确性对照；
4. Hybrid 复杂几何 fallback；
5. 可选 Adaptive Reader fresh read-only recovery backend。

### 已实现：统一只读访问入口

source-neutral facade 将 GDAL 和 fast-gdb 放到同一个外部 seam 后面。稳定的
本地源进入 fast-gdb，S3 或 fast-gdb 能力缺口进入 GDAL；路由必须在 Cursor 开始输出前
确定，不能中途静默切换。

/

已有 GDAL/OGR 程序可以通过独立名称的 `FastFileGDB` 只读驱动使用 fast-gdb；该驱动
不替换 `OpenFileGDB`、不提供 Writer，也不代表完整 GDAL ABI 兼容。

/

详细实施顺序见 [统一访问与 GDAL/S3 路由计划](../gdal/03_fast-gdb统一访问与GDAL_S3路由计划.md)。

当前受支持流程：

```text
close Readers → GDAL edit → GDALClose → reopen Readers
```

Adaptive 流程：

```text
writer active
  → SourceBusy

source changed during fast read
  → discard fast result
  → expire old Reader

writer ended and source stable
  → fresh GDAL read-only open
  → materialize
  → GDALClose
  → verify source unchanged
  → return GDAL result
```

## 验收门禁

- pure Reader 三平台构建；
- install surface 不含 Writer；
/

- linear/hybrid consumer；
- focused GDAL boundary tests；
- Reader regression；
- 真实数据和性能 artifact；
- 文档无 Writer 支持暗示；
- Adaptive 协调模式只能返回完整旧、完整新或 Busy；
- Adaptive 无协调模式不得宣称绝对检测；
- fresh GDAL fallback 不复用旧 Dataset；
- ADR-008 已 Accepted；跨平台、压力、性能和多 GDAL 版本 artifact 仍决定是否扩大独立发布承诺。
- ADR-009 已 Accepted；本地统一入口与 `FastFileGDB` 属于 v0.2.0，S3 必须完成真实
  AWS 验收后才能扩大支持声明。
