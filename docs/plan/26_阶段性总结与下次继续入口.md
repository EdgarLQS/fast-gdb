## 二、本轮（2026-11-08 → 11-12）完成的工作

### 1. SPX 源覆盖证明整链路（11-08）
把"用源几何包络与 FID 覆盖证明空间索引完整性"从方案落成产品路径：有界源目录、固定句柄 SPX I/O、实际表包络回调、Catalog 同代缓存、普通/融合查询接入、候选预算与失败回退；错键/错误分隔键可恢复，缺项/NULL 假覆盖/无效 FID 完整回退。见[查询接入记录](evidence/2026-11-08-spx-query-source-proof.md)与[SPX 源目录方案](25_SPX源几何验证目录实施方案.md)。

### 2. 规模、隔离 RSS 与超大候选预算（11-09）
1K–10M 冷建/暖查矩阵、分进程 RSS、10M 25% 窗口超预算回退（2,501,007 FID 与 GDAL 一致）。见[规模与预算记录](evidence/2026-11-09-spx-source-proof-scale-budget.md)。

### 3. 曲线保守原包络（11-10）
Bezier 凸包、圆弧极值、旋转椭圆保守范围进入 `GeometryModel`；`source_bounds` 对曲线优先使用包络。几何全套 120/120。见[曲线包络记录](evidence/2026-11-10-curve-source-bounds.md)。

### 4. 重复索引名歧义 fail-closed（11-10）
同名索引绑定不同字段返回 `Unsupported`；融合查询在同字段多个直接索引名中选择实际存在 `.atx` 的一个。新增 `AttributeIndexBindingTest` 3/3。见[绑定记录](evidence/2026-11-10-index-name-binding.md)。

### 5. 3 个 CRS 图层根因结案（11-11）
不是 Reader 缺陷：三个 `.spx` 都是空索引（`total_entries=0`、整页零字节），而表内各有 1 条活动要素；11-08 同路径清单已记录 `entries=0`，属原始语料。同语料共 9 个单要素图层空索引。源证明 fail-closed 与完整回退均正确，未改产品代码。见[根因记录](evidence/2026-11-10-crs-empty-spx-root-cause.md)。

### 6. 真实多级 SPX 矩阵，并修正基准 oracle（11-11）
- 纠正旧结论：用户语料并非"全为 level 0"，`Perf_Point_100k` 是 depth 2、`Perf_Point_1M` 是 depth 3。
- 100k：冷建 11.4 ms、暖查 0.19–0.48 ms、295 叶、目录 18 KB。
- 1M：冷建 160.4 ms、暖查 0.28–2.02 ms、2,942 叶 + 15 内部页、目录 167 KB。
- 5 个窗口的 Fast FID 与**几何全扫真值**完全一致；GDAL 自身的空间过滤在该语料上返回 0/111（真值 2,536/10,209），已改为几何真值作 oracle，过滤仅作计时。
见[真实多级矩阵](evidence/2026-11-11-real-multilevel-spx-matrix.md)。

### 7. 真实 200 万行属性索引：矩阵、缺索引回退与首查优化（11-11）
- 新增门禁基准 `AttributePlanBenchmark.ConfiguredPredicate`：数值/字符串/Int64，冷路径/暖路径、候选/页读/目录状态、GDAL 全扫 FID 核对、WHERE 顺序对照（见 [tests/INDEX.md](../../tests/INDEX.md)）。
- `bsm`（INT32，depth 3、200 万条目）6 档选择性全部与 GDAL 真值一致；暖查 0.10–9.82 ms；25% 起按设计切 `attribute:sequential`。
- `dlbz` 声明索引但缺 `.atx`：`attribute:sequential` + `attribute index missing`，133,346 命中正确（含 NULL）。
- 首查成本定位：读 3,931 页仅 4.9 ms；逐行随机校验 463–508 ms；第二次全表计数扫描 433 ms。
- **单遍校验优化**：数值/时间域（`value_size ≤ 8`）改为遍历索引收集 `(FID, 键)` + 一次顺序扫描完成双向核对、非空计数与命中；失败结果仍按同代缓存。等值首查 **907 → 622 ms（-31%）**，非选择性 1,209 → 931 ms，与全表扫描差距由 2.1–2.8 倍降到约 1.44 倍。
见[大索引矩阵与优化记录](evidence/2026-11-11-large-attribute-index.md)。

## 五、下次从哪里继续

按优先级：

1. **字符串/GUID 大索引首查**：先测量（现有基准已支持字符串），再决定是否做"受限内存键存储"的单遍化。这是 S4.2 剩余最明确的一块。
2. **类型矩阵**：拿到 Float/Date/Int64 索引语料后，用 `AttributePlanBenchmark` 直接跑 6 档选择性。
3. **压缩剩余编码开销**：目标把首查从约 1.44 倍全表扫描降到接近 1.0。
4. **旧格式（S3.5）**：恢复 92/93 样本后继续 v9 布局调查；不做猜测式解析。
5. **环境到位后的验收**：Windows/ArcGIS（S5.1）、附件/高级对象/MultiPatch/高位稀疏 v4（S2.5/S2.6/S3.3/S3.4）、大字符串索引。
6. **复验**：启动 colima 后重跑 Linux Release + sanitizer；重新构建安装 consumer。

## 七、范围与表述边界

1. 全部结论是 **Reader-only**；写入、Schema 编辑、事务、发布均不在范围。
2. 未勾选项不因"代码已有实现"而算完成；本文不把合成语料等同于 ArcGIS 验收。
3. 性能数字均为本机 macOS、OS 缓存未清、指定 `trials` 的中位数，不是跨平台承诺。
4. 旧记录中的性能/口径（例如"125 个 SPX 全为 level 0"）以最新证据为准；该说法来自叶条目层级统计，不代表树深度。
