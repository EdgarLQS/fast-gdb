# Reader-only 状态与后续任务

后续升级按 [完整只读能力与 GDAL 对照升级计划](22_完整只读能力与GDAL对照升级计划.md) 的 S0～S5 顺序执行；本文继续记录当前实现与证据缺口，不将规划能力视为已实现。

本文只记录当前 Reader 产品边界内的状态。`[x]` 表示本地代码和测试已有证据，
不表示 Linux、Windows 或其它 GDAL 版本已经验收；`[ ]` 表示仍需补证据或补能力。

## 已实现并有本地证据


- [x] `Reader → Layer → Query/Cursor` 公共只读入口，以及结构化 `ReaderError`、
  `QueryResult` 和 `MetadataReadResult`。

- [x] FID、顺序、空间、属性、WHERE、SpatialWhere、投影、分页/限制、取消和
  单活动 Cursor 合同；当前公共 FID 是零基 `uint32_t`，超出范围时 fail closed。
- [x] `Layer::read_metadata()` 统一返回元数据快照和结构化错误；
  `metadata_snapshot()` 保留为兼容入口。
- [x] 独立 Reader/Layer/QueryEngine 对象图可并发；共享同一对象图仍明确不支持。
  2/4/8 线程 digest 覆盖 FID、字段值、NULL、WKB、查询和 Cursor。
- [x] Adaptive 同进程 `WriterPending → drain → WriterActive → close → generation+1`、

  Busy、租约排空、旧 Cursor 过期、token 丢失/关闭失败和 fresh GDAL 未验证标记。
- [x] fast query 读取前后 generation 诊断；generation 或 source verification 不一致时
  丢弃物化结果。已获租约的查询可完成，但记录 `writer_pending_seen`。
- [x] GDAL 写后完整重开门禁：Set/Create/Delete Feature、Create/DeleteField、属性索引、
  extent、REPACK；重叠读写只做 old/new/mixed/error characterization。
- [x] `.gdbtable`、`.gdbtablx`、`.spx`、`.gdbindexes` 截断和损坏系统目录 fail closed；

  `.atx` 错误链、几何/WKB 和字段类型已有独立安全测试。
- [x] 安装目标为 `linear`、可选 `hybrid` 和可选 `adaptive`；`linear` 不依赖 GDAL，
  安装面不导出 Writer。

### 真实 ArcGIS Pro 验收数据（2026-07-29）

`test_data/gdb/acceptance_metadata.gdb` 已生成，但首次运行暴露出一个真实兼容性缺口：
`all_field_types` 在 Binary 字段后无法继续解析字段。原因是 ArcGIS Pro 的 Binary
字段描述包含 `width + flag` 两个字节，旧代码只消费了 `flag`，造成后续字段描述错位。
该缺口已修复，并已由真实数据回归测试覆盖。`all_field_types` 的 BigInteger、DateOnly、

TimeOnly、TimestampOffset 已完成物理读取验证；这不等同于所有历史/未来 ArcGIS 版本均已验收。

## 明确非目标

- fast-gdb Writer、自研事务、Recovery、VersionedGdbStore 或在线副本切换。
- 对未协调外部 Writer 的强安全检测、强一致性或自动路由；文件快照和 `.lock`
  只能是 best-effort 诊断。

- 共享 Reader/QueryEngine 的线程安全语义或 Feature 热路径全局锁。
- 完整栅格读取、完整 MultiPatch 表面拓扑和将 degraded 结果伪装为完整支持。

以上非目标保留为边界记录，不作为待实现功能。FileGDB 编辑继续由

GDAL/OpenFileGDB 或业务服务层承担。
