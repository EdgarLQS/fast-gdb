# fast-gdb 根目录结构与工具整理计划

## 1. 目标

统一根目录、测试工具、脚本、构建目录和安装目录的职责，减少 `build-*`、`install-*`、脚本和测试数据生成器分散造成的混乱。

核心职责固定为：

```text
src/       写代码
include/   给外部调用的接口
tests/     验证代码
tools/     执行流程和辅助工具
docs/      说明项目
build/     编译产物
install/   安装产物
```

本计划只整理目录、脚本归属、构建产物和文档引用，不修改 fast-gdb 功能代码和公共 API。

## 2. 目标根目录

```text
fast-gdb/
├── .github/              # GitHub Actions CI
├── .agents/              # Agent 技能配置
├── .codex/               # Codex 配置
├── cmake/                # CMake 模块
├── docs/                 # 项目文档
├── include/              # 公共接口
├── src/                  # 核心源码
├── tests/                # 测试和测试数据
├── tools/                # CI、验收和辅助工具
├── build/                # 本地构建产物，不提交 Git
├── install/              # 本地安装产物，不提交 Git
├── CMakeLists.txt
├── README.md
├── CHANGELOG.md
├── CLAUDE.md
├── AGENTS.md
├── LICENSE
├── .gitignore
└── skills-lock.json
```

`CHANGELOG.md` 保留在根目录并继续随安装包发布；`CLAUDE.md` 保留在根目录，便于 Claude/AI 工具自动发现。

## 3. `tests/` 职责

```text
tests/
├── createdata/          # 生成测试 GDB 和验收数据
├── scripts/             # 测试脚本本身
├── tools/               # 测试辅助验证程序
├── package_consumer/    # 安装包消费者测试
├── usegdal/             # GDAL 对照和边界测试
├── edgar/               # fast-gdb 测试代码
└── INDEX.md
```

测试数据生成器统一归入 `tests/createdata/`：

```text
tests/createdata/
├── python/
├── powershell/
└── cpp/
```

计划迁移：

```text
tests/createdata/cpp/generate_wide_50_gdb.cpp
  → tests/createdata/cpp/generate_wide_50_gdb.cpp

tests/createdata/cpp/generate_large_gdb.cpp
  → tests/createdata/cpp/generate_large_gdb.cpp
```

迁移前必须检查旧路径、CMake target、默认输出路径和危险删除命令，确保生成器不会误删非测试目录。

## 4. `tools/` 职责

```text
tools/
├── ci/
│   ├── cleanup_temp.sh
│   ├── coverage.sh
│   ├── run_spatial_regression.py
│   ├── run_test_contract.py
│   └── windows/
├── data/
└── README.md
```

- `tools/ci/`：CI、覆盖率、空间回归和验收执行脚本；
- `tools/data/`：不属于测试 target 的独立数据工具；
- `tests/tools/`：保留测试构建出来的索引和数据验证程序；
- `tests/scripts/`：只保留脚本自身的测试。

移动 `scripts/` 后，必须同步更新 GitHub Actions、README 和文档中的脚本路径。历史 `archive/` 文档可以保留旧路径，但必须标记为历史资料。

## 5. 构建和安装目录

统一采用按配置隔离的目录：

```text
build/
├── dev/
├── release/
├── nogdal/
├── asan/
├── tsan/
├── gdal39/
└── package/

install/
├── dev/
├── release/
├── nogdal/
└── package/
```

不同 GDAL 版本、Sanitizer、GDAL 开关和安装前缀不得共用 CMake cache 或安装目录。

删除范围为项目根目录下明确的旧生成目录：

```text
build*
install-accept-*
```

只删除本地生成物，不触碰源码、测试数据和外部临时目录。

## 6. 执行顺序

1. 记录根目录现状和所有脚本/构建目录引用；
2. 清理 `__pycache__`、`.DS_Store` 等本地垃圾文件并补充 `.gitignore`；
3. 移动测试数据生成器到 `tests/createdata/`；
4. 移动 CI/验收脚本到 `tools/ci/`，更新工作流和文档路径；
5. 清理旧 `build*` 和 `install-accept-*` 生成目录；
6. 更新 `README.md`、`docs/`、`tests/INDEX.md` 和工具 README；
7. 使用新的 `build/<profile>` 和 `install/<profile>` 完成配置、构建、安装和消费者验证。

## 7. 验收标准

```bash
find . -maxdepth 1 -type d | sort
git status --short
git diff --check
```

必须满足：

- 根目录不再保留旧 `build-*` 或 `install-*` 目录；
- 当前脚本和测试数据生成器都有明确唯一归属；
- GitHub Actions 中的脚本路径全部有效；
- Markdown 内部链接全部有效；
- `.gitignore` 忽略 `build/`、`install/`、`__pycache__/` 和 `.DS_Store`；
- `build/dev`、`build/nogdal` 和 `build/release` 能分别配置；
- package consumer 能使用 `install/package`；
- 代码功能、CMake target 名称和公共 API 不发生非计划变化。
