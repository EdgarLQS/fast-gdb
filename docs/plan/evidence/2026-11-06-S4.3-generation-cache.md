# S4.3 Generation-scoped cache reuse

## Implementation

- `Unified::DatasetState` retains one FastGdb `Reader`, whose state owns the
  parsed catalog/resolver and the shared query-preparation cache.
- The Dataset layer cache is keyed by resolved layer name and canonical path.
  It retains up to 64 least-recently-used immutable snapshots, while live
  `LayerState` objects remain weakly held. Reopening a released Layer in the
  same Dataset reuses the same shared `LayerSchema` object without reopening
  and freezing the layer schema. The bound is per Dataset generation.
- The Reader query-preparation cache is a mutex-protected 128-entry LRU. Its
  key includes table id, field names/types, and WHERE text. Keys larger than
  64 KiB compile without entering the cache. Query reports expose whether the
  current WHERE preparation hit the cache.
- `Dataset::refresh()` creates a fresh Reader and Dataset state, so its catalog,
  schema, and query-preparation caches do not reuse the prior generation.
  Source snapshot checks run before cached layer snapshots are returned.

## Environment

- macOS arm64, Apple clang 21.0.0
- GDAL 3.13.0 / OpenFileGDB, GEOS 3.14.1
- Fixture: packaged ArcGIS GDB test data

## Verification

Build:

```bash
cmake --build build-open-source-hybrid \
  --target gdb_tutorial_test_runner fast_gdb_unified_test_runner -j4
```

Generation/cache and refresh tests:

```bash
./build-open-source-hybrid/bin/fast_gdb_unified_test_runner \
  --gtest_filter='UnifiedFastFacadeTest.ReusesCatalogSchemaAndQueryPreparationWithinGeneration:UnifiedFastFacadeTest.RefreshBlocksActiveCursorAndExpiresOldHandles:UnifiedFastFacadeTest.FailedRefreshLeavesDatasetExpired' \
  --gtest_brief=1
```

Result: 3/3 passed. The cache test releases the first Layer before reopening,
then checks the Schema address is shared, the repeated WHERE is a cache hit,
and the same WHERE after refresh is a cache miss.

Reader/query regression:

```bash
./build-open-source-hybrid/bin/gdb_tutorial_test_runner \
  --gtest_filter='QueryEngineIntegrationTest.*:SpatialWhere*.*' \
  --gtest_brief=1
```

Result: 30 passed, 1 benchmark skipped because
`FAST_GDB_RUN_SPATIAL_WHERE_BENCHMARKS=1` was not set. `git diff --check`
passed.

## Limits

This validates cache lifecycle and query correctness, not latency or peak RSS.
The 64-entry layer cache is count-bounded; S4.5 still needs cold/hot timing,
memory, and I/O distributions. The source-mutation behavior is covered by the
separate refresh/source-snapshot contract tests, not by this focused cache
test.
