- Added real-data tests for M-curve comparison, sparse 32-bit FID mapping, and bad-topology/null-geometry behavior.
- The sparse FID test compares all four records' names and point geometries against GDAL and verifies their logical row slots.

Fixed the WKB-first `read_geometry_value` path to expose that as `GeometryStatus::Null`; previously `peek_geometry_blob` returned false and the caller reported `InvalidEncoding`. Existing callers that request only a non-null blob retain the previous false result.
- Added a real CRS comparison for the three sample layers. The geometry-field WKT parses in GDAL, and its CRS name, semi-major axis, inverse flattening and angular unit match GDAL's layer SRS. The supplied `GDB_SpatialRefs` uses legacy `ID`/`SRTEXT` fields; the existing `MetadataReader::read_spatial_reference(wkid)` path requires a `wkid` field and cannot resolve these records by EPSG code. Strict datum/axis-order equivalence remains unproven.

## Remaining boundaries

- The provided directory has no accompanying ArcGIS Pro version, creation procedure or independent expected-value manifest; its creator/provenance is unknown. Capture these before using it as a permanent semantic oracle.
- All tables are version 3, so this sample does not validate v4 sparse/high-bit ObjectIDs or their index mapping.
- The MultiPatch layer is empty. Nonempty ArcGIS MultiPatch binary and semantic parity remains open.
- Other bad-topology layers, all curve kinds, Z/M coordinate values, and per-layer SRS/WKT/axis-order parity still need direct assertions and source ground truth.
- The legacy `GDB_SpatialRefs` schema needs a separate source-ID/WKT resolution path before WKID-based spatial-reference lookup can cover this sample.
- Linux/Windows behavior remains open; this local Release result does not replace those platform runs.

## 2026-11-07 directory header compatibility

- The supplied `gdb` control file is exactly 4 bytes and contains the little-endian directory version `5`. The parser previously required 8 bytes, left the header at its default values, and the CLI reported `UNEXPECTED`, although GDAL and the feature reader opened the database.
