# S3.5：GDAL 官方历史参考库的字段与 FID 对照

执行源码：`0facd48`（此后 `4670414` 只添加 sanitizer 文档）。环境 Debian 13.4 ARM64 / GCC 14.2 / GDAL OpenFileGDB 3.10.3 / Release。

## 来源与完整性

固定来源为 [GDAL v3.10.3 FileGDB 测试语料](https://github.com/OSGeo/gdal/tree/v3.10.3/autotest/ogr/data/filegdb)。[同版本测试源码](https://github.com/OSGeo/gdal/blob/v3.10.3/autotest/ogr/ogr_openfilegdb.py) 将现代、92、93 三份压缩包列为参数化读取输入；现代样本的生成函数使用 FileGDB SDK 驱动。92/93 文件命名及上游测试分类是版本来源线索，未取得独立 ArcGIS 创建日志、导出真值或升级前后对照，因此不标为 ArcGIS-authored 真实样本完全验收。

压缩包 SHA-256、字节数和解压后每个文件的完整清单见 [manifest](2026-11-07-gdal-historical-fixtures-manifest.json)。压缩包仅下载到临时目录，未将第三方 GDB 二进制纳入版本管理；可按 manifest 中固定 URL 下载并校验后重现。现代样本 198 文件、44 张 v3 表；92/93 样本各 122 文件、31 张 v3 表。

## 已执行的字段验收

复用现有 `RealDataReleaseContractTest.SuppliedGdbEveryFeatureRowAndAttributeMatchesGdal`，仅将 `FAST_GDB_CURVE_DATASET` 指向对应完整解压目录。该合同逐层核对字段名称/类型/数量、活动行数、完整活动 FID 顺序和每个标量/Binary 字段值，不依赖 testcurve 固定行数。没有修改 Reader 或测试断言来适配这些样本。

各样本的原始日志及 gtest XML 位于 [结果目录](2026-11-07-gdal-historical-attributes)。执行方式（每个样本分别设置路径）：

```sh
FAST_GDB_CURVE_DATASET=/tmp/gdal-historical/testopenfilegdb92.gdb \
  /tmp/fast-gdb-linux-s52/bin/gdb_tutorial_test_runner \
  --gtest_filter=RealDataReleaseContractTest.SuppliedGdbEveryFeatureRowAndAttributeMatchesGdal \
  --gtest_output=xml:/tmp/historical-attributes/testopenfilegdb92.xml
```

## 未完成与排除

探索时还运行了现有 `SuppliedGdbEveryNonCurveGeometryMatchesGdal`，结果失败。源码核查发现该合同专用于 testcurve：硬编码 27 条曲线及 1 条自交面预期，且未区分无几何字段的非空间表与空间表 NULL 几何。因此这些输出不能作为历史样本几何验收结果，也不能仅据首个失败判定解析器错误；尚未建立适用于这些历史样本的几何合同。

本次只证明所列参考库在已执行环境下的完整 schema/FID/字段对照，不证明几何、空间/属性索引查询、外部更新刷新、ArcGIS 原始真值或所有 9.x 格式。S3.5 保持未完成；ArcGIS 分层语料、v4 高位稀疏 ID、SDC/CDF、存储关键字和大载荷配置仍待补齐。
