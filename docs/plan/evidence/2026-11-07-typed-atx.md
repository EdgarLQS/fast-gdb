# INT16 / FLOAT32 属性索引修复与历史库验收

调查基线 `8f9a5f1`。本阶段提交包括索引解码、QueryEngine 字段类型传递、SpatialWhere 候选支持、回归测试及本文证据；不代表完整只读计划完成。

## 计划与复现

使用固定 GDAL v3.10.3 官方参考库，逐记录读取 GDAL 字段生成期望 FID 集合，不调用 GDAL 属性索引查询作为真值。样本哈希见 [manifest](2026-11-07-gdal-historical-fixtures-manifest.json)。[修复前日志](2026-11-07-typed-atx/before-modern.log) 显示 `idx_smallint = -13` 应命中 5 条却返回空，`idx_float = 1.5` 同样不一致；日志还包含 GUID 差异，该项尚未修复。

## 执行范围

- 2 字节 INT16 键按有符号整数解码，物化和分页查询保持一致。
- 4 字节键无法只凭长度区分 INT32/FLOAT32；解析器增加源 `FieldType` 参数，QueryEngine 从直接字段索引元数据和表 schema 传递。低层解析器兼容默认 INT32，直接使用 FLOAT32 的调用方必须传 `FieldType::Float32`。
- SpatialWhere 为 INT16/FLOAT32 启用类型正确的 ATX 候选，保留现有精度门槛；新合同要求诊断实际使用属性索引。
- ATX 文件存在而无法确定直接字段类型时，结构化查询返回 `Unsupported` 和错误原因。旧的 vector 返回接口复用该实现，但无法表达状态，需要错误诊断的调用方应使用结构化 `query()`；可识别字段的损坏索引仍走已有顺序回退。
- 最小真实布局合成单叶页分别覆盖 INT16 正负极值和 FLOAT32 小数，物化/分页六种运算符均验证。
