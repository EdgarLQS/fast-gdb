# S3.4 dense v4 baseline and logical block mapping

## Result

The Reader parses v4 table headers and the v4 16-byte `.gdbtablx` fixed header.
For a no-bitmap table it verifies a contiguous nonzero offset prefix. It also
recognizes the fixed v4 bitmap section used by GDAL and maps logical 1024-row
blocks to compact physical offset blocks. The v3 compressed block map now uses
the same logical-to-physical mapping model. GdbTableParser and the v3 TablxCache
preserve that mapping, so direct row lookup and scans use logical row slots.
Unknown bitmap layouts and deleted-record v4 tables remain fail-closed.

This is still not complete 64-bit ObjectID support. The implementation now
distinguishes the zero-based logical `RowSlot` from the positive, one-based
`ObjectId`, checks conversions within the signed OGR FID range, and resolves
logical slots through the sparse block map before accessing compact offsets.
Table reads, scans, query candidates, feature cursors, and ObjectID field values
now carry 64-bit row slots. SPX/ATX v1 and v2 layouts are parsed. V2 uses
65,536-byte pages, 8-byte page IDs/ObjectIDs, widened value counts, versioned
30-byte trailers, and 12-byte internal / 20-byte leaf headers. Synthetic v2
tests cover materialized ATX parsing, direct indexed querying, and SPX traversal
through a branch page with ObjectIDs above `UINT32_MAX`. No ArcGIS-authored
sparse v4 table with high ObjectIDs is available for end-to-end verification;
mapping an external ObjectID to its logical table row slot remains open.

The fixture at
`test_data/gdb/synthetic_v4_dense_gdal_reference.gdb` contains four rows with
ObjectIDs 1–4, Point geometry, a string field, and an Integer64 field. GDAL's
OpenFileGDB writer produced the data, then the fixture generator converted only
the target table and tablx headers/trailer to dense v4. GDAL 3.13.3 and 3.13.0
both read all four rows. This is a synthetic GDAL-reader reference, not an
ArcGIS-authored dataset; it covers dense v4 only, not sparse/high external
ObjectIDs or deleted rows.

The format handling follows GDAL's [v3 tablx reader](https://github.com/OSGeo/gdal/blob/master/ogr/ogrsf_frmts/openfilegdb/filegdbtable.cpp#L3265-L3395),
[v4 tablx reader](https://github.com/OSGeo/gdal/blob/master/ogr/ogrsf_frmts/openfilegdb/filegdbtable.cpp#L3410-L3566),
and [table header reader](https://github.com/OSGeo/gdal/blob/master/ogr/ogrsf_frmts/openfilegdb/filegdbtable.cpp#L793-L919).
GDAL obtains the v4 logical row count from the trailer and uses a recognized
bitmap to map logical blocks to compact physical blocks. Unknown v4 bitmap
layouts are marked unreliable upstream; fast-gdb rejects them instead of
assigning guessed IDs.

## Changed

- `TableHeader` parsing reads v4 valid-record count at byte offset 16, file
  size at 24, and field-description offset at 32.
- `GdbTablxParser` reads the v4 block count as uint64, the logical row count,
  and bitmap-section size; it recognizes GDAL's fixed v4 bitmap markers,
  validates physical block count against bitmap popcount, and rejects unknown
  bitmap sizes or markers. V3 bitmap metadata is checked against physical block
  count as well.
- `GdbTableParser::load_tablx()` stores compact physical offsets with logical
  block rank mapping. The v3 offset cache now includes its logical row count and
  bitmap, while v4 remains uncached.
- Row reads, ordinary scans, geometry scans, candidate scans, and batch record
  materialization resolve through logical row slots rather than indexing the
  compact physical offset vector directly. Full-table scans, metadata table
  scans, and sequential feature cursors iterate active row slots, avoiding a
  walk across large missing ranges.
- Unified regression coverage reads FIDs 1–4 and runs a spatial query against
  the synthetic layer.
- The CLI reports v4 feature counts using the v4 header field.
- Reproducible fixture generator: `tests/createdata/python/generate_v4_dense_gdal_reference.py`.
- `RowSlot` and `ObjectId` are separate uint64 types. Checked conversion maps an
  ObjectID to its zero-based logical row slot and materializes the ObjectID
  field as Int64 above the Int32 boundary. Unified direct-FID reads use the
  checked conversion; query and cursor collections no longer narrow row slots
  to uint32.
- Tablx logical block-count validation uses the platform `size_t` capacity
  rather than a uint32 row-count ceiling. A valid caller/resource limit remains
  separate from the on-disk integer width.
- `intersect_sorted_fids()` compares RowSlot values as uint64, including across
  the 32-bit boundary.
- SPX/ATX page parsing detects the version in the trailer and uses versioned
  page sizes, headers, page-number/ObjectID widths, and value-count widths.
  GDAL's `ReadTrailer()` defines v1 as 4,096-byte pages with 4-byte IDs and a
  22-byte trailer, and v2 as 65,536-byte pages with 8-byte IDs and a 30-byte
  trailer ([GDAL source](https://github.com/OSGeo/gdal/blob/master/ogr/ogrsf_frmts/openfilegdb/filegdbindex.cpp#L3459-L3624)).
- The v2 tests use small synthetic page IDs encoded in 8 bytes and a high
  ObjectID; they validate format handling, not ArcGIS writer behavior or sparse
  ID-to-row-slot mapping.

candidates, scans, and query results independently with GDAL. Deleted-record
behavior and sparse-ID mapping remain unverified.
