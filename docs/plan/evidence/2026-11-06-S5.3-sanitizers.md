# S5.3 macOS Sanitizer 与并发验证

## ASan/UBSan

- AppleClang 21.0.0；Debug；GDAL-free Reader 配置；`-fsanitize=address,undefined -fno-omit-frame-pointer`。
- 重建当前源码：`cmake --build build-security-sanitize --target gdb_tutorial_test_runner -j4`。
- 完整运行：`ASAN_OPTIONS=strict_string_checks=1 UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 build-security-sanitize/bin/gdb_tutorial_test_runner --gtest_brief=1`。
- 结果：240 tests / 35 suites，240 通过。包含截断/损坏输入、Reader 资源生命周期、Tablx 缓存文件变化、Cursor 与字段布局用例。
- 测试会向 stderr 输出不存在路径、截断表头和未知 tablx 版本诊断；对应负向断言通过，不属于 sanitizer 报告。

## TSan

- AppleClang 21.0.0；Debug；GDAL-free Reader；`-fsanitize=thread -fno-omit-frame-pointer`。
- 当前源码在 `/private/tmp/fast-gdb-s4-tsan` 构建。
- 运行 `ReaderConcurrencyTest.IndependentReadersReturnIdenticalFeatureDigests` 与 `TablxCacheTest.ConcurrentAccess`：2/2 通过，无 TSan 报告。

## 限制

- macOS 的 AddressSanitizer runtime 不支持 `ASAN_OPTIONS=detect_leaks=1`，该选项会在测试启动时退出。本记录不宣称已由 LeakSanitizer 验证泄漏；ASan/UBSan 与 TSan 本身均成功运行。
- 这是 macOS 本机证据；Windows 文件映射实现及 Windows sanitizer 结果仍待 Windows runner。
