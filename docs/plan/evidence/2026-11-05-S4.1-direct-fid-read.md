# S4.1 Direct FID reads

## Environment

- macOS arm64, Apple clang 21.0.0
- GDAL 3.13.0 with OpenFileGDB and GEOS 3.14.1
- Dataset: `test_data/gdb/acceptance_metadata.gdb`, layer `parcels`
- The packaged layer contains active FIDs 1–8 and 20–29; deleted FIDs 9–19 are absent.

## Implementation

The unified `Layer::read_by_fid()` path previously opened an unfiltered cursor and
walked features until it reached the requested FID. It now sends `ReadByFid` to
the native Reader, whose tablx lookup uses the FID slot directly, then reads the
full feature from that slot. This keeps deleted slots distinguishable from
active rows and avoids scanning preceding features.

The read holds a Dataset operation registration and the existing FastReader
lease, validates the frozen schema and source generation, and checks the source
snapshot again before returning. IDs outside the native 32-bit row-slot range
keep the existing explicit GDAL fallback or `Unsupported` behavior.

## Verification

GDAL 3.13.0 `ogrinfo -ro -al -geom=NO -fields=YES` confirmed the sparse FID
layout. The unified regression checks active FIDs at both sides of the gap and
after it, and confirms deleted/nonexistent IDs return `FeatureNotFound`.

Command:

```bash
cmake --build build-open-source-hybrid --target fast_gdb_unified_test_runner -j4
./build-open-source-hybrid/bin/fast_gdb_unified_test_runner \
  --gtest_filter='UnifiedFastFacadeTest.ReadByFidHandlesSparseAndDeletedRows:UnifiedFastFacadeTest.RejectsInvalidPublicFid:UnifiedFastFacadeTest.NativeExtensionsAreFastOnlyAndBounded:UnifiedGdalFacadeTest.GdalOnlyUsesOfficialOpenFileGdb' \
  --gtest_brief=1
```

Result: 4/4 passed. This verifies behavior and code-path routing; latency and
throughput distributions belong to S4.5 and are not claimed here.
