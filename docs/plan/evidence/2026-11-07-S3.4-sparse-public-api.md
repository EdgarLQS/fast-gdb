# S3.4 real sparse FID through the Unified public API

## Dataset and expected mapping

The user-provided `/Users/edgarlqs/Downloads/testcurve.gdb` contains a v3
`Point_FIDGap` feature class. GDAL OpenFileGDB reports active FIDs `1, 2, 6, 7`;
FID values `3, 4, 5` are absent. The source GDB is opened read-only.

## Contract added

`UnifiedGdalFacadeTest.SuppliedSparseObjectIdsMapThroughPublicApi` captures the
GDAL FID and `Name` values, then opens the same layer through Unified with the
`FastOnly` backend. It verifies:

- direct `read_by_fid()` returns the same FID and `Name` for all four active
  features;
- direct reads for the three FID gaps return `FeatureNotFound`;
- ordered `read_all()` returns the same active FID/value sequence;
- an ordered `FeatureCursor` returns the same sequence and terminates after
  the fourth feature;
- tight spatial bbox queries around each point return the same FID/value set as
  a full-scan geometry-envelope reference built from GDAL's sequential rows.

The point windows deliberately use full-scan geometry as their reference.
GDAL 3.13.0's spatial filter on `(59.99, 59.99) - (60.01, 60.01)` returns no
feature, while its full scan contains `FID=6`, `POINT (60 60)`. This sample's
spatial-filter output therefore cannot serve as the sole truth for this case.
The reproducible reference commands are:

```sh
ogrinfo -ro -al -geom=NO -spat 59.99 59.99 60.01 60.01 \
  /Users/edgarlqs/Downloads/testcurve.gdb Point_FIDGap
ogrinfo -ro -al -geom=YES /Users/edgarlqs/Downloads/testcurve.gdb Point_FIDGap
```

The first command reports zero features; the second includes FID 6 at
`POINT (60 60)`. The [OpenFileGDB documentation](https://gdal.org/en/stable/drivers/vector/openfilegdb.html)
notes that the driver can use native `.spx` indexes for filtering. This is an
observed driver result; its exact cause is not inferred here.

This closes the public API parity check for ordinary v3 sparse FIDs. It does
not establish the external-ID to logical-row mapping for native v4 tables,
high-bit 64-bit ObjectIDs, deleted v4 records, or attribute/spatial index
queries; those still require ArcGIS-authored v4 reference data.
