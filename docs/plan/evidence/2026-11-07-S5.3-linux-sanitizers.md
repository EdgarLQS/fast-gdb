# S5.3 Linux sanitizer 验证

源码：`0facd48`。Debian 13.4 aarch64 / GCC 14.2 / CMake 3.31.6 / Colima 容器，源码与用户 testcurve 均只读挂载。

## ASan、UBSan 与 LeakSanitizer

独立 Debug 构建目录 `/tmp/fast-gdb-linux-asan`：GDAL OFF、Unified ON、full tests ON、tools OFF。编译参数 `-fsanitize=address,undefined -fno-omit-frame-pointer`，executable/shared linker 参数 `-fsanitize=address,undefined`。`ldd` 确认完整测试程序链接 `libasan.so.8` 与 `libubsan.so.1`。

使用现有 googletest 源目录，无需重新下载依赖。完整构建 99 项通过。执行：

```sh
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 \
UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 \
FAST_GDB_CURVE_DATASET=/data/testcurve.gdb \
ctest --test-dir /tmp/fast-gdb-linux-asan --output-on-failure
```

409 项发现，404 PASS / 5 SKIP / 0 FAIL，14.84 秒。无 ASan、UBSan 或 LeakSanitizer 报告。跳过项为两条需专用 ArcGIS 附件样本的合同，以及三条 opt-in 性能基准。真实 testcurve 独立 Reader digest 并发合同执行并通过。

原始结果见 [完整 CTest 日志](2026-11-07-linux-asan-ubsan-ctest.log)。这证明当前 Linux GDAL-free 配置的已执行测试通过，不代替 GDAL ON、Windows 映射实现或所有潜在输入的验证。

## TSan 环境探针：未完成项目验收

先用只有一个 `std::thread`、在 `join()` 后读取结果的无竞态程序探测运行环境。GCC `-fsanitize=thread` 编译成功，但程序执行返回 66：

```text
FATAL: ThreadSanitizer: unexpected memory mapping 0xc13145ec0000-0xc13145ec3000
```

使用 `-fno-pie -no-pie` 重新构建后仍返回相同类别错误。未在此环境构建/宣称通过项目 TSan 套件；Linux TSan 仍待支持该 runtime 地址布局的主机或 CI。既有 macOS TSan 证据继续独立保留。
