# ATX 最后子页下探及布局校验

继续 S4.2 查询与性能自查，总计划仍未完成。

## 来源与问题

核对 [GDAL 3.10.3 索引 Writer 源码](https://github.com/OSGeo/gdal/blob/v3.10.3/ogr/ogrsf_frmts/openfilegdb/filegdbindex_write.cpp) 的 `WriteRootPageNonLeaf` / `WriteLastTwoLevelPages`：普通内部页存储分隔键数，子指针多一个。强制单子页根的计数仍为 1，仅有一个指针，是需要保留的例外。

旧查询将计数当作子页数，超出最后分隔键的查询下探到倒数第二个子页，靠叶链读到末端。真实 GDAL 万行索引已经复现：树深 2 的最大值等值/范围查询读取 3 页。[修复前日志](2026-11-08-atx-last-child/before.log) 中结果仍正确，性能边界断言失败；本次没有将此问题描述为已复现漏行。

## 修改

- 原始分页查询将最后子页纳入选择及指针范围校验，超出全部分隔键时直接选末端子页。
- 物化解析与绑定值目录构建采用相同子指针数量规则，补齐最后指针的检查。
- 保留单子页且后续指针为零的布局。计数大于 1 时，末端指针为零明确失败；计数为 1 时无法仅凭零指针区分合法单子页与损坏的双子页，不宣称消除了该歧义。
- 修正数值及 GUID 合成双叶 fixture 的内部页计数，GUID v1/v2 六操作符仍核对完整 FID。
- 真实 GDAL 数值规模测试增加最大值的 `= / >= / >` 断言，要求末端查询页数不超过树深，结果与独立完整字段读取一致。

本次原始入口性能变化不等于绑定目录查询整体提速，后者仍有首次 O(N) 完整性验证和源身份检查。未覆盖所有 ArcGIS 内部页变体。

## 验证

Linux ARM64 GDAL 3.10.3 完整回归 649 项：630 PASS / 19 SKIP / 0 FAIL，35.64 秒；macOS GDAL 3.13.0 完整回归 608 项：590 PASS / 18 SKIP / 0 FAIL。完整测试配置用户曲线、固定元数据和历史参考库，见 [Linux](2026-11-08-atx-last-child/linux-release.log)及 [macOS](2026-11-08-atx-last-child/macos-release.log)。

百万及千万行真实 GDAL 数值索引均通过完整值对照与最大值末端三操作符页数断言，分别覆盖更大的多层树。63 个普通探针的原始分页路径：

| 行数 | 页访问合计 | 键访问合计 | median / p95 / p99 ms |
|---|---:|---:|---|
| 1M | 189 | 10,586 | .012875 / .015833 / .018124 |
| 10M | 189 | 10,710 | .015169 / .017795 / .020670 |

见 [1M](2026-11-08-atx-last-child/linux-1m.log)和 [10M](2026-11-08-atx-last-child/linux-10m.log)。此前相同百万 fixture 的记录为 405 页/84,026 次键访问；千万 fixture 恰好原先也是 189 页，不能宣称该组继续减少。单次耗时受环境影响，不当作通用性能承诺。绑定目录的冷热指标也保留在日志中。

Windows、真实 ArcGIS 大型索引、百万长键等原计划门禁继续保持未完成；未沿用前次 sanitizer 结果作为当前源码通过结论。
