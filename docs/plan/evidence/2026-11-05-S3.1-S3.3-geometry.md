## S3.1 and S3.2 result

Reader and Unified cursors default to `PreserveSource`. Curves are returned as
unsupported geometry plus the exact FileGDB geometry blob, subject to a 64 MiB
default budget. The cursor continues returning the feature attributes when the
geometry cannot be represented by the native linear WKB model. A payload over
budget is reported as `LimitExceeded` and is not copied.

Callers can explicitly select built-in `Linearize`; the resulting value records
`source_was_curve`, `linearized`, the chord-error, angle-step and segment-limit
parameters, and (within budget) the original payload. Unified's GDAL-only route
preserves OGR curve WKB. Its linearization honors the requested angle step; it
returns `Unsupported` when a chord-error or segment-count constraint is
requested because the OGR method used here cannot enforce those constraints.
The query result never marks a linearized geometry as unmodified source data.

`CurvePolicyPreservesAndLinearizesWithProvenance` found a real curve using GDAL
in the parameterized fixture and verified FastGdb raw-source return, payload
budget failure, explicit native linearization, GDAL-only curve WKB and explicit
GDAL linearization. `CurveFileGdbUsesBuiltinWkbFirstPath` compared the native
cursor's preserved payload byte-for-byte with the parser's source geometry
blob. The synthetic geometry suite covers all three curve segment kinds.

## S3.3 status

MultiPatch remains a degraded geometry type, but Reader/Unified now expose an
immutable structured model alongside the bounded raw source payload. The model
contains the raw format marker and bbox header values, decoded real-world
vertices, each raw and normalized part type, its contiguous vertex range, and
triangle count/index access for TriangleStrip, TriangleFan, and Triangles.
OuterRing/InnerRing and FirstRing/Ring are grouped according to their encoded
sequence; FirstRing groups deliberately retain that source convention rather
than guessing an exterior ring from orientation. Unknown part codes remain
available as raw codes. Uninterpreted trailing bytes are counted and remain
available in the original payload.

For complete known structures with no opaque tail, the decoder now emits ISO
WKB following GDAL's MultiPatch mapping: each strip/fan/triangle part becomes a
TIN, connected groups of 4-point OuterRing triangles use GDAL's TIN heuristic,
other encoded ring groups become one MultiPolygon, and mixed components become
a GeometryCollection. The writer preserves Z and M and appends a first ring
coordinate only when needed to close a ring.
Unknown part codes and opaque tails remain `UnsupportedType` with no normalized
WKB; invalid triangle groups and broken ring grouping return
`InvalidTopology`. The Unified value shares the immutable part model rather
than copying its vertex arrays again. The legacy `GdbGeometry::wkt` field
remains a compatibility view and is not evidence of surface-semantic parity.

Synthetic tests cover the six traditional part codes plus the `Triangles`
extension, high-nibble part flags, Z/M decoding, triangle indices and winding,
both ring grouping encodings, unknown type retention, invalid triangle count,
and payload preservation. ISO WKB output tests cover TIN, connected OuterRing
TIN detection, MultiPolygon, GeometryCollection, PolyhedralSurface read-back,
Z/M, and ring closure. The
group/fan/strip semantics follow the [ArcGIS Patch class](https://pro.arcgis.com/en/pro-app/3.6/sdk/api-reference/topic27403.html)
and [PatchType enumeration](https://pro.arcgis.com/en/pro-app/3.0/sdk/api-reference/topic75895.html).
GDAL's current [MultiPatch decoder](https://github.com/OSGeo/gdal/blob/master/ogr/ogrpgeogeometry.cpp)
uses low-nibble part type normalization and maps triangle patches to TIN and
ring patches to polygons; [RFC 64](https://gdal.org/en/stable/development/rfc/rfc64_triangle_polyhedralsurface_tin.html)
defines the OGR TIN and PolyhedralSurface types. These source references define
the implementation comparison target, but they do not replace a real-data
result comparison. No real ArcGIS MultiPatch GDB is available in the current
fixtures, so binary-layout and semantic parity remain pending.

## 2026-11-06 legacy MultiPatch WKT normalization

The compatibility `GdbGeometry::wkt` path previously parsed MultiPatch a
second time and guessed `POLYGON` from each part's vertex count. That ignored
whether the source part was a TriangleStrip, TriangleFan, Triangles, or Ring,
and it could emit a polygon for unknown part types or opaque trailing data.
The legacy path now uses the already-decoded `GeometryModel`, serializes it
through `WkbWriter`, and derives WKT from that normalized ISO WKB. The duplicate
MultiPatch WKT parser and its unused helpers were removed.

- Complete known triangle strips now produce TIN WKT, while encoded ring groups
  produce MultiPolygon WKT; both match `GeometryValue::to_wkt()` and preserve
  Z/M ordinates.
- Unknown part types and opaque tails report `UNSUPPORTED_MULTIPATCH`; invalid
  triangle topology reports `INVALID_GEOMETRY`. Neither path fabricates a
  polygon WKT.
- TDD check: the new assertions failed on the old implementation, then passed
  after the compatibility path was unified.
- Geometry suite: **114/114 passed** with GDAL enabled and **114/114 passed**
  in the pure C++ GDAL-free build. GDAL 3.13.0 accepted the synthetic
  MultiPatch WKB/WKT mapping (**1/1 targeted test passed**).
- Full current-worktree suites: GDAL ON **521 discovered, 511 passed, 10
  skipped, 0 failed**; GDAL OFF **395/395 passed**.

This makes the synthetic legacy-output contract consistent with normalized
WKB. It does not make WKT a lossless representation of ArcGIS part labels;
the immutable part model and preserved source payload remain the lossless
read-only representation. The user-provided `testcurve.gdb` MultiPatch layer
is empty, so an ArcGIS-authored nonempty MultiPatch and part-by-part parity
remain required before S3.3 can be marked complete.
