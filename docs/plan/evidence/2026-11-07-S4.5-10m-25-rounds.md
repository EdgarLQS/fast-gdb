# S4.5 10M random-read and scan follow-up

## Environment and method

- macOS arm64, Release, GDAL/OpenFileGDB 3.13.3.
- Read-only fixture: `/private/tmp/fast-gdb-s4-10m.gdb`, `features` Point,
  10,000,000 rows, `feat_id` field.
- Ran `ReaderRuntimeBenchmarkTest.ReadOnlyRuntimeProfileConfigured` twice in
  separate processes, 25 trials per run. Each trial reads the same 256 random
  FIDs and scans all 10M rows with both Fast and GDAL. The random and full-scan
  digests matched in both batches.
- Each batch passed 1/1. Raw JSON: [batch 1](2026-11-07-S4.5-10m-runtime-25-batch1.json),
  [batch 2](2026-11-07-S4.5-10m-runtime-25-batch2.json).

## Timing summary

Values are median / p95 / p99 in milliseconds, nearest-rank percentiles.

| Operation | Fast batch 1 | GDAL batch 1 | Fast batch 2 | GDAL batch 2 |
|---|---:|---:|---:|---:|
| 256 random FIDs | 0.108 / 0.238 / 18.843 | 0.540 / 1.079 / 5.190 | 0.110 / 0.228 / 0.258 | 0.529 / 1.102 / 1.129 |
| Full 10M scan | 1,479.425 / 1,524.927 / 1,674.599 | 1,660.604 / 2,067.529 / 2,263.258 | 1,444.640 / 1,457.493 / 1,464.626 | 1,511.708 / 1,565.170 / 1,566.137 |

Fast full scans were faster than GDAL in both batches. Random-read median and
p95 were also lower in both batches. Batch 1 had one large Fast random-read
tail sample: its p99 is the maximum of 25 trials and did not recur in batch 2.
Treat 25-sample p99 as an observed maximum, not a stable estimate.

## Resource and cache limits

- Whole-process peak RSS was 869,400,576 bytes in batch 1 and 869,416,960 bytes
  in batch 2. It includes both backends and shared process state; it is not a
  Fast-only or GDAL-only memory measurement.
- The benchmark ran steady-state and did not clear the OS file cache. Physical
  read counters varied between batches and do not represent cold-start I/O.
- This run compares the current Fast implementation with GDAL. It does not
  compare against the pre-optimization source baseline.

Reproduce either batch with:

```bash
FAST_GDB_RUN_RUNTIME_BENCHMARKS=1 \
FAST_GDB_RUNTIME_BENCHMARK_PATH=/private/tmp/fast-gdb-s4-10m.gdb \
FAST_GDB_RUNTIME_BENCHMARK_LAYER=features \
FAST_GDB_RUNTIME_BENCHMARK_FIELD=feat_id \
FAST_GDB_RUNTIME_BENCHMARK_TRIALS=25 \
FAST_GDB_BENCHMARK_OUTPUT_DIR=/private/tmp/fast-gdb-s4.5-runtime-25 \
  /private/tmp/fast-gdb-gdal-3.13.3-build/bin/gdb_tutorial_test_runner \
  '--gtest_filter=ReaderRuntimeBenchmarkTest.ReadOnlyRuntimeProfileConfigured' \
  --gtest_brief=1
```

The second batch used a distinct output directory. More independent batches,
backend-isolated RSS, and cold-start I/O remain open.
