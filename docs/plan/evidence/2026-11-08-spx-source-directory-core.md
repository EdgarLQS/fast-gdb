# SPX 源包络目录核心组件

状态：核心组件已实现并单独测试，尚未接入查询引擎；SPX 有效缺项/错键的产品缺口仍未关闭。总计划未完成。

## 已实现内容

新增私有 `SpatialSourceDirectoryBuilder` / 不可变 `SpatialSourceDirectory`。调用方逐叶提供 FID 与规范源几何包络，构建器累积叶页真实范围；物理网格键不作为包络输入。最后逐活动源行检查覆盖，只有下列条件全部满足才发布：

- 索引条目总数与预期一致；页号在界内且不重复，每叶最多 4096 项；FID 在逻辑槽位范围内。
- 源扫描恰好包含预期数量的不重复活动 FID，短扫描、重复回调、删除/非活动索引 FID 均失败。
- 每个非空源几何均在至少一个带真实源包络的叶项中出现；重复 FID 不能弥补遗漏，NULL 叶项不能证明非空几何覆盖。
- 包络有限且有序；确认的 NULL/Empty 可以没有索引项，不生成有范围的叶页。

发布后按 xmin 排序并保存 prefix-max-x。查询先排除不可能相交的 X 区间，再核对 Y 范围，返回按物理页号排列的页索引。宽包络不因后续窄区间出现而被错误跳过。选择结果允许额外候选，最终精确空间谓词仍由后续查询接入负责。发布后重复 finish 返回同一不可变对象，构建器不能再追加或破坏它。

## 输入前提与尚未实现部分

所有包络必须从同一稳定快照、同一规范几何解释取得；`nullopt` 只能表示确认的 NULL/Empty，不能掩盖读取/解码失败。构建器不读取表文件，也不能识别调用方提供的虚假/变代包络；源扫描坐标与叶页包络的一致性依赖该输入合同。

尚未接入 SPX 叶读取、批量源几何解码、完整文件身份和 transform 绑定、目录缓存/失效、普通及融合查询选择、回退诊断。也没有证明源行损坏时可以建立安全包络。后续必须落实这些前提，不能只因核心单元测试通过就启用未验证候选。

## 资源边界

单目录计费载荷最多 16 MiB，包含预留叶数组与 prefix 数组容量。最多 16M 逻辑槽位；索引出现、非空覆盖及源扫描去重三个位图各最多 2 MiB，合计 6 MiB，另有页访问位图。超过容量在分配大数组前拒绝，后续接入应完整扫描回退。

这不是整体 RSS 上限，不包含调用方源行/页缓冲、输入向量、输出候选、共享指针管理对象或未来缓存中多个目录。尚未实现全局 LRU 预算。失败会释放构建状态，不发布部分目录。

## 验证

新增 8 项独立核心测试：100 个稀疏源槽位与 500 个随机窗口逐项核对无漏候选，包含跨窗口宽包络；非单调物理页顺序、X 区间重叠/边界、合法 NULL/Empty、重复网格 FID、遗漏、假 NULL 证明、删除槽位、短源扫描、错误总数、重复页/源行、越界 FID、非有限包络、资源上限及发布不可变性。macOS 定向 8/8，见[日志](2026-11-08-spx-source-directory-core/macos-focused.log)。

最终 macOS GDAL 3.13.0 完整回归 621 项：603 PASS / 18 SKIP / 0 FAIL，77.28 秒；Linux ARM64 GDAL 3.10.3 完整回归 662 项：643 PASS / 19 SKIP / 0 FAIL，32.68 秒，均配置用户曲线、固定元数据和历史参考库。见 [macOS](2026-11-08-spx-source-directory-core/macos-release.log)及 [Linux](2026-11-08-spx-source-directory-core/linux-release.log)。

Linux GDAL-free Debug ASan/UBSan/LSan 完整回归 452 项：447 PASS / 5 SKIP / 0 FAIL，16.84 秒，新核心测试实际执行。单线程重建，开启 `detect_leaks=1:halt_on_error=1`、`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`，无 sanitizer 诊断。见[构建](2026-11-08-spx-source-directory-core/asan-build.log)及[测试](2026-11-08-spx-source-directory-core/asan-ctest.log)。未重跑 TSan 或安装 consumer，跳过项不记验收。

没有索引接入和性能测量，不将这些核心测试称为已修复真实损坏 SPX。
