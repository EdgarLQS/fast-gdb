# S4.2 ATX paged query

## Scope

- ATX direct queries read the trailer and requested pages instead of loading the
  whole file into `file_data_`.
- Internal pages descend by the query key for equality and lower-bound queries;
  range scans stop once sorted keys pass the requested range.
- Each direct query uses a fixed 16-page (64 KiB) LRU. Candidate FIDs remain
  output-sized; cross-query/generation cache reuse is reserved for S4.3.
- `QueryEngine` attribute queries use the direct API. A failed index query uses
  a sequential predicate scan only when `.gdbindexes` identifies a direct field
  expression that can be compiled safely. Combined spatial/attribute queries
  retain spatial candidates on ATX failure and evaluate the full WHERE
  predicate before publishing results.

## Verification

Environment: macOS arm64, Apple clang 21.0.0, GDAL 3.13.0 / OpenFileGDB,
GEOS 3.14.1.

Build:

```bash
cmake --build build-open-source-hybrid --target gdb_tutorial_test_runner -j4
```

Focused regression:

```bash
./build-open-source-hybrid/bin/gdb_tutorial_test_runner \
  --gtest_filter='SpatialWhereIndexFallbackTest.*:SpatialWhereNullTest.*:QueryEngineIntegrationTest.*:AttributeIndexTest.*:AttributeIndexSafetyTest.*' \
  --gtest_brief=1
```

Result: 32/32 passed. This includes a synthetic two-leaf B+ tree covering
`Eq/Lt/Le/Gt/Ge/Ne`, page and entry counts, comparison with the materialized
API, and transactional failure for an invalid child page. A damaged ATX also
falls back to a direct-field sequential scan in `QueryKind::AttributeDouble`
when the ATX is either missing or damaged.

Broader spatial/query regression:

```bash
./build-open-source-hybrid/bin/gdb_tutorial_test_runner \
  --gtest_filter='SpatialWhere*.*:QueryEngineTest.*:QueryEngineIntegrationTest.*:AttributeIndexTest.*:AttributeIndexSafetyTest.*' \
  --gtest_brief=1
```

Result: 53 passed, 1 benchmark skipped because
`FAST_GDB_RUN_SPATIAL_WHERE_BENCHMARKS=1` was not set. The suite covers missing,
truncated, inconsistent-count, and cyclic ATX fallback; spatial candidates are
rechecked against the compiled WHERE expression. `git diff --check` passed.

## Limits

The multi-page descent fixture is synthetic; this run does not establish
large-scale throughput or prove every historical ArcGIS ATX layout. Page
validation is limited to the descent path and pages inspected by the requested
range so the query can stop early. Cache reuse between queries and performance
distributions remain S4.3 and S4.5 work.
