# S1.3 GDAL NULL comparison difference

## Contract

FastGdb follows SQL three-valued logic: a comparison on NULL evaluates to
UNKNOWN, and a filter publishes only rows evaluating to TRUE. Thus `value != 5`
does not include a NULL-valued row.

## Observed GDAL behavior

Environment: macOS arm64, GDAL 3.13.0, OpenFileGDB. The regression creates a
FileGDB layer with values `5`, `10`, `NULL`, and `30`, adds a spatial filter,
and evaluates `value != 5` through both implementations.

- FastGdb returns zero-based FIDs `{1, 3}`.
- OpenFileGDB `SetAttributeFilter()` returns zero-based FIDs `{1, 2, 3}` and
  includes the NULL row.

This is recorded as a known compatibility difference. The FastGdb SQL contract
remains authoritative; the test asserts each result independently rather than
requiring parity for this predicate.

Regression:

```bash
./build-open-source-hybrid/bin/gdb_tutorial_test_runner \
  --gtest_filter='SpatialWhereNullTest.NullNotEqualUsesSqlThreeValuedLogicAndRecordsGdalDifference' \
  --gtest_brief=1
```

The test passed as part of the 53-pass spatial/query regression recorded in
[S4.2 evidence](2026-11-06-S4.2-atx-paged-query.md).
