# S4.5 TablxCache 命中竞争与读锁优化

## 实现

`TablxCache::get()` 原先为每次命中移动 LRU 链表节点而持独占锁，因此不同 Reader 的缓存命中也会串行。现在读命中持共享锁，使用原子单调访问序号记录每个条目的最近访问顺序；写入时缓存容量最多 16 项，扫描访问序号找淘汰项。数据仍由 `shared_ptr<const ...>` 提供不可变偏移数组。新增淘汰顺序回归，覆盖普通 LRU 淘汰与命中后刷新最近使用顺序。

代码自审另修复了 `put_shared()` 替换已有大缓存项时的字节预算边界：更新后若超过 256 MiB，会继续按 LRU 淘汰旧项。插入和替换现在共用同一淘汰逻辑。

## 方法

- 只读枚举 `/Users/edgarlqs/Downloads/testcurve.gdb` 的 `.gdbtablx` 文件，以 16 个实际 sidecar 文件身份作为缓存键；计时期间不读取或修改 GDB 文件。
- 缓存值为单个合成偏移项，基准直接调用 `TablxCache::get()`，隔离测量共享缓存命中锁，不计入解析器、字段或几何读取。
- 测 1/2/4/8 个线程及三种键访问模式：所有线程命中同一键、每个线程命中独立键、所有线程轮转共享的 16 键集合。
- 每个线程每种配置执行 200,000 次命中；吞吐与延迟分两阶段测量。延迟阶段每 64 次操作采样一次，报告 nearest-rank p50/p95/p99。
- 优化前基线为一次运行；最终实现重复运行三次。基线 `distributed_keys` 与最终 `shared_key_set` 使用相同轮转键公式；单次基线只适合方向性比较。

### 真实 Reader open + FID 读取

另用同一 testcurve 的三个 CRS Point 图层，每次操作创建新的 Reader、打开一个图层并读取预先确定的首个活动 FID；每次记录的字段 digest 必须与顺序基线一致。测 1/2/4/8 线程、单图层热点和三图层轮转两种模式，每线程 25 次操作，缓存开启与 `FAST_GDB_TABLX_CACHE=0` 绕过缓存分别运行三轮。每轮均为 0 次读取差异。

8 线程下缓存开启与绕过缓存的整体结果接近：单图层热点中位数约 125.1 次 open+read/s、p99 74.1 ms；绕过缓存约 125.0 次/s、p99 73.2 ms。三图层轮转中位数约 125.1 次/s、p99 73.9 ms；绕过缓存约 125.1 次/s、p99 73.8 ms。该路径包含每次 Reader 构造和整库源快照，说明这些成本遮住了缓存锁的局部改进；仍保留直连缓存基准来定位该锁本身。

## 8 线程结果

| 模式 | 优化前吞吐 / p99 | 最终三轮中位吞吐 / p99 | 变化 |
|---|---:|---:|---:|
| 单热点键 | 7.91 M/s / 60.2 µs | 15.63 M/s / 23.5 µs | 吞吐约 1.98×；p99 降约 61% |
| 每线程独立键 | 无基线 | 17.01 M/s / 27.1 µs | 仅报告最终观测 |
| 共享 16 键集 | 4.76 M/s / 84.5 µs | 7.90 M/s / 26.1 µs | 吞吐约 1.66×；p99 降约 69% |

4 线程共享键集的最终吞吐中位数为 13.08 M/s，低于单次基线 13.42 M/s 约 2.6%；p99 从 14.3 µs 降至 9.3 µs。由于基线只跑一轮，这个小幅吞吐差异仍需多轮同配置比较。

## 验证边界

- `TablxCacheTest.*` 16/16 通过，包括 8 线程并发读写和 LRU 顺序合同。
- 真实 Reader 竞争测试三个缓存开启进程和三个绕过缓存进程均通过；每个配置的所有 FID 字段 digest 与顺序期望值一致。
- 字节预算修复后，GDAL ON Release 定向缓存、独立 Reader 并发和真实 testcurve 合同共 34 项：33 通过、1 个 REJECT 后端专用曲线用例按设计跳过。随后全量 CTest 为 538 项：524 通过、14 个已配置跳过、0 失败，用时 61.27 秒；再后的全量 Release CTest 为 540 项：526 通过、14 个已配置跳过、0 失败，用时 61.71 秒；最新加入 Unified 稀疏 FID 及空间窗口合同后的全量 CTest 为 541 项：527 通过、14 个已配置跳过、0 失败，用时 61.36 秒。
- 物理冷启动 I/O 仍未完成。所有轮次运行于 macOS 热文件系统缓存；没有清理 OS 文件缓存。
- 基准直接走已预热内存缓存，未清理 OS 文件缓存；结果不代表磁盘 I/O 或整库读取速度。
