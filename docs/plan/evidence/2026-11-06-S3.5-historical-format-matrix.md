# S3.5 historical version and compression matrix: initial evidence

## Scope

This records the current repository evidence used to build the [S3.5 matrix](../23_FileGDB历史版本与压缩格式验收矩阵.md). It is a partial audit, not acceptance of all historical FileGDB formats.

## Repository evidence

- `GdbTableParser` accepts table header versions 3 and 4; other values are rejected. `GdbTablxParser` likewise accepts versions 3 and 4. Its v3 block bitmap and recognized v4 bitmap are distinct from SDC/CDF payload compression.
- The local real-data scan recorded in [the S3.4 boundary note](2026-11-06-S3.4-objectid-boundary.md) found 301 `.gdbtable` files and 304 `.gdbtablx` files, all version 3. This is evidence about the checked local corpus only.
- The [dense v4 reference note](2026-11-06-S3.4-dense-v4-baseline.md) documents the four-row fixture: GDAL-generated data with the target table/index headers changed to dense v4; GDAL 3.13.0 and 3.13.3 read it. It is not ArcGIS-authored.
- SPX/ATX v2 and high 64-bit index-key coverage is synthetic; the existing S3.4 evidence records its test cases and current sparse ObjectID mapping limitation.
- No complete SDC, CDF, ArcGIS 9.x, ArcGIS-authored v4 sparse-ID, or out-of-row configuration fixture is present for this audit.

## Verification

Build targets were current in `build-s4-release`:

```sh
cmake --build build-s4-release --target fast_gdb_geometry_test_runner fast_gdb_unified_test_runner gdb_tutorial_test_runner --parallel 4
```

The focused parser/index regression command passed 68/68:

```sh
./build-s4-release/bin/gdb_tutorial_test_runner '--gtest_filter=GdbTableTest.*:GdbTablxTest.*:GdbAttributeIndexTest.*:AttributeIndexTest.*:AttributeIndexSafetyTest.*:SpatialIndexTest.*:SpatialIndexMergeTest.*' --gtest_brief=1
```

The `Unknown .gdbtablx version: 99` diagnostic was emitted by an expected negative test and the suite passed. These tests verify the current supported branches and fail-closed cases; they do not establish ArcGIS writer parity for missing formats.

## External support boundary

The official [OpenFileGDB documentation](https://gdal.org/en/stable/drivers/vector/openfilegdb.html) says it reads ArcGIS 9.x and 10+ geodatabases, does not read SDC/CDF, and has incomplete read-only support for sparse 64-bit ObjectIDs. The official [FileGDB SDK driver documentation](https://gdal.org/en/stable/drivers/vector/filegdb.html) says SDC is unsupported and CDF requires SDK 1.4 or later. These document GDAL driver behavior, not a byte-level Esri format specification.

## Remaining acceptance

S3.5 stays **Partial** until the matrix rows requiring ArcGIS-authored historical/compressed samples have either been tested or explicitly left unsupported in the product contract. Do not infer a passing result from unavailable fixtures, GDAL limitations, or synthetic layouts.
