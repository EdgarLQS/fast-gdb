# S2.4 GDB_Items inventory and UUID read evidence

## Public behavior

- `Reader::read_workspace_metadata()` returns a `GDB_Items` inventory with
  physical row slots, active rows, decoded rows, summaries and row-level issues.
- `Reader::read_catalog_object_by_uuid()` returns a single object's source
  attributes as typed `FieldValue`s and the exact source `Definition` string.
- UUID lookup ignores ASCII case, braces and hyphens. A duplicate UUID is
  reported as ambiguous. A missing UUID is reported only when the inventory is
  complete; an unreadable row makes an absent lookup unavailable.
- The Unified API exposes inventory summaries through `Dataset::metadata()`
  and a full object read through `Dataset::catalog_object_by_uuid()`.
- GDAL-only reports the complete `GDB_Items` raw-attribute capability as
  `Unsupported` because OpenFileGDB's OGR layer does not provide those complete
  source rows and raw definitions.

## Independent source comparison

Command:

```sh
ogrinfo -ro -so test_data/gdb/acceptance_metadata.gdb GDB_Items
```

Observed with the local OpenFileGDB driver: `Feature Count: 19`. The inventory
reports 19 active objects. `ogrinfo -ro -al -geom=NO -where "Name = 'roads'"
test_data/gdb/acceptance_metadata.gdb GDB_Items` reports Roads UUID
`{E32B8E0E-76FF-4792-A874-31FD8B282224}` and path `\TransportFD\roads`;
Reader and Unified resolve that same object and preserve its Definition XML.

## Corrupt-row behavior

`ReaderContractTest.ReportsCatalogRowsThatFailToDecode` copies the checked-in
ArcGIS sample to a temporary directory, overwrites the length prefix of one
active `GDB_Items` row with an invalid value, and opens the copy. The inventory
returns `Partial`, counts 19 active rows and 18 decoded rows, retains the 18
valid summaries, and reports the failed row slot. The source fixture remains
unchanged.

## Limits

This inventory covers active `GDB_Items` rows and preserves their typed
attributes. Deleted tablx slots are counted as inactive, not reported as parse
failures. It does not yet interpret every item type's application semantics;
that is S2.6. Attachment payload access and resource limits are S2.5.
