# S5.3 Tablx 共享偏移存储复验

## ASan/UBSan

- macOS AppleClang Debug、GDAL-free Reader，`-fsanitize=address,undefined -fno-omit-frame-pointer`。
- 复用 `build-security-sanitize` 重建当前源码，并按 CI 同一筛选运行
  `ctest --test-dir build-security-sanitize -R '^(geometry|full)\.'`。
- 结果：360 项中 359 通过、1 个大 bitmap 性能基准跳过、0 失败。覆盖新增的
  Tablx 计数模式、不可变偏移共享、稀疏 FID 和密集扫描路径。
- 本机 AddressSanitizer runtime 不支持 `detect_leaks=1`。启用它会使所有测试子进程
  在运行用例前退出；正式复验使用 `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1`，并且
  不宣称完成 LeakSanitizer 检查。

## TSan

- macOS AppleClang Debug、GDAL-free Reader，`-fsanitize=thread -fno-omit-frame-pointer`。
- 重建 `/private/tmp/fast-gdb-s4-tsan` 后运行独立 Reader digest 与
  `TablxCacheTest.ConcurrentAccess`。
- 结果：2/2 通过，无 TSan 报告。

## 共享锁优化复验

- 更新 `TablxCache::get()` 为共享锁并发读后，使用 `build-s4-tsan` 的 GDAL-free
  TSan 配置，重跑 `TablxCacheTest.ConcurrentAccess`、`TablxCacheTest.HitRefreshesLruOrder`
  和 testcurve 三 CRS 图层的 `ReaderConcurrencyTest.IndependentReadersReturnIdenticalFeatureDigests`：3/3 通过，无 TSan 报告。
- 同一源码下使用 `build-security-sanitize` 重建 ASan/UBSan 测试程序；关闭本机不支持的
  LeakSanitizer 选项后，运行全部 16 个 `TablxCacheTest` 与真实数据 Reader 并发合同：17/17 通过。
- 可选竞争基准未在 sanitizer 下运行，性能数据来自 Release 构建。

## 边界

- ASan/UBSan 覆盖的是本机 GDAL-free 测试集；真实 `testcurve.gdb` 对照另由 GDAL ON
  Release 测试验证。
- Windows 文件映射实现和 Linux/Windows sanitizer 结果仍需相应 CI 或主机证据。
