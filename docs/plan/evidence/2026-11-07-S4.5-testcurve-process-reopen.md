# S4.5 testcurve 多图层并发与跨进程重开

## 样本与方法

- 只读使用 `/Users/edgarlqs/Downloads/testcurve.gdb`，没有复制或修改源目录。
- `ReaderConcurrencyTest.IndependentReadersReturnIdenticalFeatureDigests` 现在显式覆盖该库中的 `CRS_CGCS2000_Point_FC`、`CRS_WGS84_Point_FC` 和 `CRS_Xian80_Point_FC`，并保留两个版本库 fixture。每个 worker 建立独立 Reader 对象图，对照顺序读取所得 digest；线程数为 2、4、8。
- `benchmark_cross_process_reader_open.py` 启动 25 个独立测试进程。每个进程运行上述 Reader 并发合同后退出，确认进程边界上的重复打开/关闭稳定。
- 每轮时间包含测试进程启动、测试初始化、顺序基线和并发读；不应解释成单次 Reader open latency。

## 结果

- 多图层并发 Reader 合同：2/4/8 线程下，实际 testcurve CRS 图层 digest 与顺序基线一致；首次定向测试 1/1 通过，约 0.399 秒；最终源码复验 1/1 通过，约 0.406 秒。
- 跨进程合同：25/25 个独立进程通过。全轮时间 median 567.180 ms、p95 578.733 ms、p99 587.036 ms、范围 557.311–587.036 ms。
- 最终源码全量 Release CTest：535 项中 523 通过、12 跳过、0 失败，用时 60.79 秒；同时设置 `FAST_GDB_CURVE_DATASET` 指向本样本、`FAST_GDB_REAL_DATASET` 指向仓库验收样本。
- 原始样本见 [JSON 结果](2026-11-07-S4.5-testcurve-process-reopen.json)。复测命令：

```sh
python3 tests/createdata/python/benchmark_cross_process_reader_open.py \
  --runner build-s4-release/bin/gdb_tutorial_test_runner \
  --dataset /Users/edgarlqs/Downloads/testcurve.gdb \
  --gtest-filter ReaderConcurrencyTest.IndependentReadersReturnIdenticalFeatureDigests \
  --rounds 25 \
  --output docs/plan/evidence/2026-11-07-S4.5-testcurve-process-reopen.json
```

## 边界

- 进程之间退出并重开，但没有清理 macOS 文件缓存；本结果不证明物理冷启动 I/O，也不提供共享缓存竞争的吞吐或尾延迟分布。
- `TablxCacheTest.ConcurrentAccess` 的 8 线程/TSan 检查仍只证明当前访问安全性，不等于缓存竞争性能验收。
- 真实大型 ArcGIS `.atx`、ArcGIS 语料和 Linux/Windows 证据仍待补。
