# S4.4 Projection, lazy output geometry, and fused spatial/attribute scan

## Implementation

- FastGDB row decoding still validates nullable layout and record boundaries.
  For projected-out fixed-width attributes it advances over the physical width
  without constructing a `FieldValue`. Existing variable-width String/XML and
  Binary projection paths validate lengths and skip payload bytes without
  copying them.
- `QueryRequest::include_geometry` and unified `Query::include_geometry` default
  to `true`. When `false`, returned features carry the explicit
  `GeometryStatus::NotRequested` / `GeometryState::NotRequested`; the row
  geometry blob is structurally skipped without model decoding or WKB writing.
  Geometry needed to evaluate a spatial predicate remains decoded in the
  query-planning path.
- For GDAL-backed cursors, requested attribute names and `OGR_GEOMETRY` are
  passed to `SetIgnoredFields()` only when there is no attribute or spatial
  filter and the layer advertises `OLCIgnoreFields`. With filters, the driver
  receives all potential filter inputs; projection is applied when returned
  fields are mapped. GDAL documents `OGR_GEOMETRY` as the special ignored-field
  name and the capability check as the way to know whether fetching can be
  reduced ([OGRLayer::SetIgnoredFields](https://gdal.org/en/stable/api/ogrlayer_cpp.html)).
- The existing selective SPX candidate plus WHERE path parses each candidate
  row once as `FieldRef`, evaluates the spatial predicate and WHERE before
  publishing FIDs, and retains transactional fallback if candidate scanning
  fails. The focused fused-scan tests compare result FIDs with GDAL and assert
  fused path metrics.

## Limits

The GDAL filter path deliberately avoids `SetIgnoredFields()` while filtering;
the mapping layer still gives callers the requested field projection, but the
driver may fetch additional attribute values. The current feature model returns
geometry eagerly when requested; this change avoids geometry decoding only
when the caller opts out. Large-scale latency, throughput, and RSS distributions
remain S4.5 work.
