# S2.5 attachment metadata and bounded Binary evidence

## Implemented contract

- FastGdb identifies relationship definitions marked
  `IsAttachmentRelationship=true`, exposes the origin class, attachment table,
  endpoint UUIDs and paths, cardinality, key roles and original relationship
  XML through Reader and Unified workspace/layer metadata.
- A table name ending in `__ATTACH` identifies the attachment endpoint. When
  the suffix is absent, the destination endpoint is reported as inferred; the
  metadata also reports whether the table resolves in `GDB_SystemCatalog`.
- Reader and Unified can read one Binary field by FID with a caller byte limit.
  NULL and a non-NULL zero-length payload are distinct. Oversized data reports
  its byte length without copying the payload. The parser skips variable-width
  fields by their encoded lengths and only reads the requested Binary bytes
  after it verifies the limit.
- GDAL-only reports the detailed ArcGIS attachment section and bounded Binary
  read as `Unsupported`; generic OGR relationships do not preserve the full
  ArcGIS attachment definition contract in this adapter.

## Fixture coverage and remaining acceptance gap

The checked-in `acceptance_metadata.gdb` has no `__ATTACH` table or attachment
relationship. Therefore the implementation is covered by synthetic attachment
metadata, but real ArcGIS attachment relationship naming, schema, payloads,
parent GlobalID linkage and end-to-end attachment retrieval remain unverified.
S2.5 stays unchecked until a representative ArcGIS-produced attachment GDB is
available and compared with ArcGIS and GDAL.

## 2026-11-07 follow-up: reproducible ArcGIS attachment fixture

Added `tests/createdata/python/generate_attachment_fixture.py`. In an ArcGIS Pro
Python environment it creates a separate FileGDB, enables attachments on a
GlobalID feature class, adds four files across two parent features, and leaves a
third parent without attachments. The payloads include binary NUL/high bytes, a
Unicode filename, multiple attachments on one parent and a 131073-byte value
for caller-limit checks. ArcPy reads the resulting `__ATTACH` table and verifies
the stored bytes against each source file before it writes the row-slot oracle
TSV and JSON manifest.

Added `ReaderContractTest.ReadsArcGisAttachmentFixtureWhenConfigured` and
`UnifiedFastFacadeTest.ReadsArcGisAttachmentPayloadsWhenConfigured`. With
`FAST_GDB_ATTACHMENT_DATASET` and `FAST_GDB_ATTACHMENT_EXPECTED_TSV`, the tests
check the resolved attachment relationship and keys, read every row through
Reader and Unified, compare the `DATA` field byte for byte against its source
file, and verify size-limit responses. They are skipped when either variable
is unset. This container has no ArcPy and no ArcGIS-produced attachment GDB, so
the generator and real-data contracts still require execution on ArcGIS Pro;
the synthetic tests do not satisfy the remaining S2.5 acceptance gate.

The fixture follows Esri's documented [Enable Attachments](https://pro.arcgis.com/en/pro-app/3.4/help/data/relationships/enable-attachments.htm)
and [Add Attachments](https://pro.arcgis.com/en/pro-app/3.6/tool-reference/data-management/add-attachments.htm)
workflow. Those docs define the expected construction, while the generated
ArcPy `SearchCursor` output remains the row-level oracle.

Local preparation verification on macOS / GDAL 3.13.0 Release:

- Python AST parsing and generator `--help` passed without importing ArcPy.
- `gdb_tutorial_test_runner` and `fast_gdb_unified_test_runner` rebuilt in both
  GDAL ON (`build-s4-release`) and GDAL OFF (`/private/tmp/fast-gdb-s2.2-no-gdal`)
  configurations.
- GDAL ON Reader/metadata filter: 3 passed, 1 skipped; GDAL OFF Reader/metadata
  filter: 2 passed, 1 skipped. Unified Binary filter in both configurations:
  1 passed, 1 skipped. Each skip is the optional real ArcGIS fixture test
  because its two environment variables are unset.
- These results verify compilation, CLI discoverability and existing synthetic
  contracts only; they do not verify ArcPy generation or real attachment data.

GDAL documents relationship support and listing system tables through
`LIST_ALL_TABLES=YES` in the [OpenFileGDB driver documentation](https://gdal.org/en/stable/drivers/vector/openfilegdb.html).
Esri documents attachments as a separate attachment table and one-to-many
relationship in [Enable attachments](https://pro.arcgis.com/en/pro-app/3.4/help/data/relationships/enable-attachments.htm).
The local sample has no such relationship, so these documents establish the
expected model, not sample-level conformance.

## Limits

The attachment summary currently resolves a single origin endpoint and one
attachment table endpoint, matching the documented ArcGIS attachment model.
Unusual custom endpoint layouts are retained as inferred metadata and require
real samples before stronger interpretation. The bounded Binary reader is a
single-field primitive; attachment rows and relationship joins remain explicit
caller work, with field projection available through the existing query API.

## 2026-11-06 follow-up: Definition XML contract

Added a non-GDAL-dependent test that parses an actual `IsAttachmentRelationship=true`
Definition XML and checks cardinality, origin/destination names, primary/foreign
key roles and byte-for-byte raw XML preservation. The GDAL ON integration test
also feeds the parsed relationship through endpoint resolution and attachment
summary generation. This strengthens the synthetic contract but does not add
ArcGIS-produced attachment table or payload evidence.

```sh
cmake --build build-s4-release --target gdb_tutorial_test_runner -j4
./build-s4-release/bin/gdb_tutorial_test_runner \
  --gtest_filter='MetadataContractTest.*:MetadataReaderTest.SummarizesAttachmentRelationshipAndTableResolution:MetadataReaderTest.ClassifiesAdvancedObjectKindsWithoutClaimingSemantics' \
  --gtest_brief=1
cmake --build /private/tmp/fast-gdb-s2.2-no-gdal \
  --target gdb_tutorial_test_runner -j4
/private/tmp/fast-gdb-s2.2-no-gdal/bin/gdb_tutorial_test_runner \
  --gtest_filter='MetadataContractTest.*' --gtest_brief=1
```

Results: GDAL ON 4/4 and GDAL OFF 2/2 passed. The broader GDAL OFF target
deliberately excludes `test_metadata_reader.cpp`, whose remaining fixture tests
depend on GDAL-generated datasets; the new parser/classifier contract tests are
compiled and run in both configurations.
