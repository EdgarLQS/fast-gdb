# S1.6 external record and geometry refresh

## Contract checked

An external writer finishes and closes its update; the old snapshot fails closed;
`Dataset::refresh()` creates a new snapshot that reads the changed feature.

## Procedure

- Source: `/Users/edgarlqs/Downloads/testcurve.gdb`, opened and copied read-only.
- Mutation target: temporary copy, layer `Point_FIDGap`, FID 6.
- GDAL OpenFileGDB changes `Name` from `Feature_6` to `ExternalUpdate_6` and
  changes point coordinates to `(123456.75, 654321.25)`, then closes the
  dataset. A separate GDAL read-only reopen confirms both updated values before
  fast-gdb reads again. The same update creates a non-spatial layer with one
  integer record; GDAL read-back confirms that record too.
- Fast-gdb opens the copy with `BackendPreference::FastOnly`. Before refresh,
  the old Layer rejects the read with `SchemaMismatch`; GDAL's update also
  normalizes the geometry-field WKT descriptor, so the frozen field descriptor
  no longer matches. After `refresh()` and reopening, the unified API reads the
  changed attribute/point coordinates, lists and reads the newly created layer,
  and reports its refreshed metadata.
- GDAL marks `Point_FIDGap` as `HasSpatialIndex=false` while an `.spx` sidecar
  exists. After the external geometry update, GDAL's spatial filter finds FID
  6 but using the sidecar in fast-gdb returned no candidate. Reader now parses
  the optional declaration from `GDB_Items`; explicit false bypasses `.spx` and
  uses sequential geometry filtering. The test checks that path and confirms
  the same new-coordinate window returns FID 6.
- The test removes its temporary GDB with scope cleanup. The supplied source
  directory is never opened for update.
