# S4.5 Fast/GDAL 分进程 RSS 与 10M 读取对照

## 环境与方法

- macOS arm64、Release、GDAL/OpenFileGDB 3.13.0。
- 只读基准数据：`/private/tmp/fast-gdb-s4-10m.gdb`，`features` 点图层、
  10,000,000 条记录、`feat_id` 字段。
- Fast 和 GDAL 分别在独立测试进程中运行 25 轮。每轮使用固定种子生成相同的
  256 个随机 FID，并完整扫描 10M 条记录；两个后端各自的随机读取与全扫 digest
  均在轮次间保持一致，Fast 与 GDAL 的摘要也完全一致。
- 该流程没有清理操作系统文件缓存。RSS 是进程级峰值，包含 Fast 映射文件中驻留
  的文件页；测试二进制仍链接 Fast 和 GDAL，但每次只打开一个数据后端。
- 原始 JSON：[Fast 25 轮](2026-11-07-S4.5-backend-isolated-fast.json)、
  [GDAL 25 轮](2026-11-07-S4.5-backend-isolated-gdal.json)。

## 结果

时间单位为毫秒，分位数使用 nearest-rank。RSS 采用字节计量，括号中为 MiB。

| 指标 | Fast | GDAL |
|---|---:|---:|
| 256 FID 随机读取 median / p95 / p99 | 0.106 / 0.152 / 19.235 | 0.515 / 0.546 / 18.488 |
| 10M 全扫 median / p95 / p99 | 1,473.201 / 1,494.509 / 1,614.038 | 1,584.043 / 1,617.883 / 1,672.781 |
| 进程峰值 RSS | 419,463,168 (400.0 MiB) | 48,316,416 (46.1 MiB) |
| 随机读取 digest | `4937596482607270455` | `4937596482607270455` |
| 全扫 digest | `3811699590460810184` | `3811699590460810184` |

Fast 全扫 median 约低 7%，随机读取 median 约低 79%。25 样本 p99 是观测最大值，
不应视作稳定尾延迟估计。Fast RSS 仍约为 GDAL 的 8.7 倍；本项关闭的是后端混跑
造成的归因歧义，不消除 mmap 文件页与 GDAL 流式读取模式的差异。

## 内存改动

- `GdbTablxParser` 在图层打开路径只计数，不再构造临时有效 FID 向量；默认解析 API
  仍会按原合同物化 `valid_fids()`。
- 密集图层用行槽序号直接得到 FID；只有调用列表 API 时才物化兼容用向量。稀疏图层
  仍保留显式活动 FID 列表。
- Tablx 偏移数组现在由解析器、图层和全局缓存共享为不可变数据，避免各自持有大型
  副本。
- 第一阶段只读试跑（活动 FID 去冗余、共享偏移尚未完成）峰值 RSS 为
  579,584,000 bytes；最终 25 轮为 419,463,168 bytes，低约 27.6%。前者 5 轮、后者
  25 轮，RSS 高水位主要发生在打开阶段，此比较用于估算改动方向，不是严格配对的
  独立重复基线。[第一阶段原始 JSON](2026-11-07-S4.5-backend-isolated-fast-pilot.json)

## 复现

在仓库根目录分别设置 `FAST_GDB_RUNTIME_BENCHMARK_BACKEND=fast` 和 `gdal`，并使用
独立输出目录运行：

```bash
FAST_GDB_RUN_RUNTIME_BENCHMARKS=1 \
FAST_GDB_RUNTIME_BENCHMARK_PATH=/private/tmp/fast-gdb-s4-10m.gdb \
FAST_GDB_RUNTIME_BENCHMARK_LAYER=features \
FAST_GDB_RUNTIME_BENCHMARK_FIELD=feat_id \
FAST_GDB_RUNTIME_BENCHMARK_TRIALS=25 \
FAST_GDB_RUNTIME_BENCHMARK_BACKEND=fast \
FAST_GDB_BENCHMARK_OUTPUT_DIR=/private/tmp/fast-gdb-s4.5-isolated-fast \
  ./build-s4-release/bin/gdb_tutorial_test_runner \
  '--gtest_filter=ReaderRuntimeBenchmarkTest.ReadOnlyRuntimeProfileBackendIsolated' \
  --gtest_brief=1
```

GDAL 运行将 backend 改为 `gdal`，输出目录改为另一目录。

## 边界

该证据只覆盖本机、一个 10M 点图层和当前 GDAL 版本。OS 文件缓存未清，不能代替
冷启动 I/O；RSS 包含映射文件驻留页，不能解释为 Fast 的私有堆内存。Linux/Windows、
多图层并发、重复打开关闭及真实大型属性索引仍需独立验收。

2026-11-07 尝试以当前 macOS 用户运行 `/usr/sbin/purge`，系统返回
`Unable to purge disk buffers: Operation not permitted`。缓存未清理，因此本轮没有
生成或声称获得物理冷启动 I/O 数据；该项需要有权限清理缓存的主机或测试环境。
