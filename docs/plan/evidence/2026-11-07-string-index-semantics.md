# 字符串索引：空格、Unicode、截断及原值复核

基线 `660c785`。本阶段修复字符串索引查询漏行与误命中。正确性已补充验证，字符串快速路径优化仍未完成，整体计划保持执行中。

## 计划与可复现问题

GDAL 创建真实 GDB，写入内部/尾部空格、空字符串、控制字符、BMP 私用区、emoji、超过 80 个索引单元的文本和 NULL；期望 FID 集合来自 GDAL 无属性/空间过滤的逐行字段扫描，按现有 WHERE UTF-8 比较语义独立计算六运算符。[修复前日志](2026-11-07-string-index-semantics/before.log) 显示空格文本和关系比较漏行/误命中。

原解码器遇到第一个空格就结束，未组合 UTF-16 代理对；查询字符串也在首个空格停止。普通属性请求把截断/填充索引命中直接作为结果，没有最终原字段复核。

[实际物理键诊断](2026-11-07-string-index-semantics/physical-key-diagnosis.log) 又确认两种不能忽略的情况：

- Linux GDAL 3.10.3 生成的最小 emoji 索引键保存 U+F600，而字段原值是 U+1F600；这是本次实际观察，不推断全部 GDAL/ArcGIS 版本都相同。
- `a` 填充后的键在 `a`+U+0001 之前，物理 UTF-16 比较却应反序；不能对该叶序直接按固定填充键提前终止。GDAL 的固定版本 [读取比较实现](https://github.com/OSGeo/gdal/blob/v3.10.3/ogr/ogrsf_frmts/openfilegdb/filegdbindex.cpp#L1198-L1220) 逐 UTF-16 单元比较，但这不能证明所有写出的键满足查询所需单调性。

## 执行

- 共用 UTF-16 解码保留内部空格，正确处理代理对；支持既有 NUL 尾部填充，完整宽度末尾被截断的高代理以替代字符显示。原始键字节仍保留在物化解析器的文件缓冲区，用偏移比较，避免从解码视图反推丢失的键。
- 增加严格 UTF-8 查询转换，非法输入不更改输出；普通替换式转换合同保留。
- 低层 `query_string/query_string_direct` 按物理 UTF-16 键比较，不能等同完整字段语义。字符串页按链读取，不使用尚未证明单调的降树/提前终止；仍使用固定 16 页缓存，不整份物化索引。
- 新的完整值候选路径等值比较同时考虑 UTF-16 和已观察到的 UCS-2 低位折叠；关系比较按已知前缀及折叠的保守上下界保留可能命中。NULL 不来自索引。无法安全解释的键失败后回退字段扫描。
- QueryEngine 普通字符串属性查询现在用原始字段复核候选，排除尾空格、长前缀和 U+F600/emoji 编码碰撞；联合查询使用同一候选语义并继续复核。字符串 `!=` 联合查询保留原有空间候选策略。
- GDB 级 CLI `query ... attr` 使用完整字符串查询；独立 `query-atx` 仍是物理键诊断接口，文档明确两者边界。

## 验证

新增 18 个非 NULL 字符串、1 个 NULL、19 个探针的真实 GDAL GDB 合同：各 114 次直接/SpatialWhere 查询完整 FID 对照通过，直接路径要求实际使用 ATX，联合非 `!=` 路径也要求索引使用。额外探针 U+F700 检查折叠后错误的大小关系；U+F600 与 emoji 具有相同物理键，最终复核区分完整值。

合成 UTF-16 原生键测试独立覆盖内部空格、真正的代理对、物理顺序与 UTF-8 顺序差异、80 单元截断在高代理处、物化与分页一致性；既有中文 NUL 填充回归保留通过。严格 UTF-8 验证输出失败不变。

最终结果见 [原始日志/XML](2026-11-07-string-index-semantics)：

- Linux ARM64 / GCC 14.2 / GDAL 3.10.3 Release：621 项，602 PASS / 19 SKIP / 0 FAIL，23.11 秒。
- GDAL-free ASan/UBSan/LeakSanitizer：424 项，419 PASS / 5 SKIP / 0 FAIL，20.69 秒，无 sanitizer 报告；不含 GDAL 集成测试。
- macOS UTF-16、ATX 安全、字符串集成及原有中文回归：36/36。
- CLI：Linux 68 / macOS 65 个进程检查通过，包括物理 UTF-16 顺序、带空格 dump 和固定 ArcGIS `Parcel Alpha` 的完整值查询；111 个固定样本文件内容哈希不变。
- 自审检查替代/严格转换兼容、原始偏移生命周期、保守范围不排除可能命中、候选原值复核和失败不发布部分索引结果。临时诊断代码和两个生成副本已清理；`git diff --check` 通过，未新增依赖。

## 未完成条件和性能限制

字符串当前每次查询需要扫描索引叶页，时间与键数量相关；它保留有界内存和准确结果，但不能宣称字符串已达到二分范围检索性能。数值与 GUID 的降树及范围终止路径保持原有实现。S4.2 必须继续补排序/编码验证、随源身份失效的有界验证缓存、安全快路径，以及大型字符串索引 p95/p99 与 I/O 证据；不能把这次正确性回归当成优化验收。

本证据也不代替全部 ArcGIS Unicode 写入版本、v9 元数据、压缩格式、高位稀疏 v4 或 Windows 验收。非有限数值键和其它尚未核对的输入仍按计划继续检查。用户原始 testcurve 没有修改。
