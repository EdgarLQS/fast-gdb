# FileGDB 全面学习体系优化计划（v2）

## 目标与当前状态

课程面向“会使用 C++ 和 AI，但对 FileGDB 从零开始”的学习者。目标不是手写完整解析器，而是建立足以解释格式、判断证据、指导 AI 和审核 Reader 的完整心智模型。

当前状态：

- M01–M18 已升级为本地混合学习实验室；
- 每个模块均有题目映射、可展开标准答案、只读证据实验、AI 口试和间隔复习；
- 课程按掌握状态推进，不再以 18 周日历作为完成标准；
- fast-gdb 产品范围仍是 Reader-only，课程工具不修改公共 API。

## 统一学习闭环

每个已交付模块必须包含：

1. 5–8 道课前诊断题；
2. 3–5 个 10–15 分钟微型知识单元；
3. 每个关键知识点都有默认收起、点击展开的标准答案图/表、标准结论、证据、边界、常见误解和来源；每道题必须通过清单映射到一个标准答案；
4. 一个真实数据实验或高级数据集证据任务；
5. 证据等级和“不能证明什么”判断；
6. 当前 Codex 对话可使用的 AI 口试包；
7. D+2、D+7、D+21 间隔复习。

状态固定为：

```text
Locked → NotStarted → Learning → Provisional → Mastered
```

`Provisional` 要求测验不低于 85%、关键题全部正确、实验完成且产物校验通过、证据等级作品通过 SHA-256 校验、匹配待处理会话的 AI 口试总分不低于 10/12 且每项不低于 2。标准答案查看会记录但不作为门禁。三次间隔复习完成后才进入 `Mastered`。

## 第一阶段实现

学习台使用浏览器原生 HTML/CSS/JavaScript 和 Python 标准库服务：

- `course.py doctor/serve/status/lab/review-export/review-import/export-record` 提供稳定入口；
- 服务只监听 `127.0.0.1`，固定地址直接访问，并保留来源检查和白名单 API；
- 进度、实验产物、口试结果和备份只能保存在 `build/learning/`；
- 同进程读改写事务串行执行，跨进程锁在异常退出后由操作系统释放；
- 实验按版本化清单校验文件哈希、前缀哈希或文件家族数量，不评分自由文本；
- 证据作品校验必需等级和边界表达，口试导入校验一次性待处理会话与结果结构；
- 诊断只调整建议学习深度，标准答案默认收起但可随时点击查看；
- 核心 ArcGIS 数据包附来源、大小、文件数量和树 SHA-256；
- 网页不执行任意 Shell，真实实验必须通过显式 CLI 命令运行；
- 正式学习记录只在长期掌握后由学习者确认创建。

## 已完成的扩展顺序

根据 M01–M03 试学反馈，已完成：

1. 扩展 M04–M07 的 Catalog、Table、字段和记录组件；

3. 扩展 M14–M17 的行为和高级数据集证据判断；

所有模块复用课程清单、评分、进度、AI 口试和复习调度，没有复制独立状态逻辑。M04–M18 拆为独立模块文件，便于后续补充知识点。

## 完成定义

完整课程只有在 18 个模块均达到 `Mastered`、六个阶段作品完成且 M18 审核通过后才算结束。完成课程也不能把未公开的高级数据集物理结构从 `Unknown` 提升为事实；必须继续区分 Physical Read、Structured Schema 和 Behavioral Parity。

课程入口见 [`../gdb/learning/README.md`](../gdb/learning/README.md)。
