# fast-gdb 源码与测试目录结构重构计划

> 状态：Current
>
> 适用版本：v0.2.0+
>
> 维护入口：docs/plan/03_源码与测试目录结构重构计划.md

## 一、目标与不可变约束

在不改变业务逻辑、解析算法、运行行为和公共接口的前提下，重新组织 `src/` 与 `tests/`，使代码职责、构建目标和测试位置容易理解。

本次只调整文件位置、include、CMake 源文件清单、安装规则和文档链接，不重新设计模块接口。

以下内容必须保持不变：

- C++ 命名空间、类型名、函数签名和运行语义；
- 所有现有 library、executable、plugin 和 test target 名称；
- CTest 测试名称、前缀、资源锁和测试数量；
- 已安装头文件的相对路径和文件名；
- `#include <reader.h>`、`#include <unified.h>`、`#include <adaptive_reader.h>` 等现有用法；
- `fast_gdb::linear`、`fast_gdb::hybrid`、`fast_gdb::adaptive` 和 `fast_gdb::unified` 导出目标；
- Reader-only 产品边界。

`src/edgar/usegdal` 仍属于不编译、不安装、不导出、无兼容承诺的历史参考代码，不得因目录迁移成为 Writer 产品的一部分。

## 二、当前事实与前置修复

当前 `src/edgar/explorgdb/reader/` 同时包含公开接口、FileGDB 格式解析、几何、索引、查询、平台兼容和 CLI，是本次整理的主要对象。

当前 `common/` 只有约 10 个源码和头文件。继续拆成 `binary/`、`encoding/`、`numeric/` 等小目录会增加跳转成本，因此本次保持平铺。

当前安装规则直接从源码目录复制头文件。移动源码后必须显式映射旧安装路径，不能依赖递归复制后形成的新目录。

实施前先单独修复一个已存在的问题：

- `cmake/FastGdbInstall.cmake` 中的 release note 路径仍为 `docs/releases/v0.2.0.md`；
- 实际路径已经是 `docs/governance/releases/v0.2.0.md`；
- 该修复独立提交，避免安装验证失败干扰目录重构。

## 三、目标源码结构

```text
src/
├── edgar/
│   └── explorgdb/
│       ├── common/                 # 底层字节、编码、日期、VarInt 和公共类型
│       ├── reader/
│       │   ├── README.md
│       │   ├── api/                # Reader、FeatureCursor、能力报告
│       │   ├── format/             # Catalog、Table、TABLX、字段和元数据
│       │   ├── geometry/           # 几何、曲线、拓扑、WKB/WKT
│       │   ├── index/              # 属性索引、空间索引和缓存
│       │   ├── query/              # QueryEngine、Where 和查询执行
│       │   ├── io/                 # mmap、滑动映射和平台兼容
│       │   └── cli/                # explorgdb_cli
│       ├── unified/                # fast_gdb::unified
│       ├── adaptive/               # Adaptive Reader
│       ├── curve_gdal/             # GDAL 曲线与 Hybrid Reader
│       └── gdal_driver/            # FastFileGDB 驱动
└── reference/
    └── usegdal/                    # 历史 GDAL/OGR wrapper
```

`usegdal` 放到 `src/reference/`，不再位于 `explorgdb` 产品模块下面。它保留参考价值，但继续排除在构建、安装、导出和 release gate 之外。

`reader/QUERY_FLOW.md` 的有效内容合并到 `docs/gdb/` 的 Reader 流程文档。源码目录只保留简短 `README.md`，用于说明模块地图并链接到正式文档。

## 四、源码文件归类规则

| 目标目录 | 文件或文件组 |
|---|---|
| `reader/api/` | `reader.*`、`feature_cursor.cpp`、`capability_report.*` |
| `reader/format/` | `catalog_resolver.*`、`gdb_catalog.*`、`gdb_table*`、`gdb_tablx*`、`field_layout.h`、`metadata_reader.*` |
| `reader/geometry/` | `curve_geometry.*`、`gdb_geometry*`、`geometry_model.h`、`polygon_topology.*`、`spatial_predicate.*`、`wkb_*`、`wkt_writer.*` |
| `reader/index/` | `gdb_indexes.*`、`gdb_attribute_index*`、`gdb_spatial_index.*` |
| `reader/query/` | `query_engine*`、`query_where_internal.*` |
| `reader/io/` | `windows_posix_compat.*`、`windows_sliding_map.h`、`unistd.h`、`sys/mman.h` |
| `reader/cli/` | `explorgdb_cli.cpp` |

以主要职责决定文件位置。跨目录依赖通过明确 include 表达，不复制头文件，也不为单个文件创建额外目录。

`gdb_table_*` 的拆分实现全部留在 `format/`，包括几何读取和字段扫描实现，因为它们共同实现 `GdbTable`，不按函数名再次拆散。

## 七、构建与安装兼容策略

### CMake 源文件管理

用按模块命名的显式源码列表替代 `common/*.cpp`、`reader/*.cpp` 和测试目录 GLOB：

```text
FAST_GDB_COMMON_SOURCES
FAST_GDB_READER_API_SOURCES
FAST_GDB_READER_FORMAT_SOURCES
FAST_GDB_READER_GEOMETRY_SOURCES
FAST_GDB_READER_INDEX_SOURCES
FAST_GDB_READER_QUERY_SOURCES
FAST_GDB_READER_IO_SOURCES
```

将这些列表聚合到现有 target，不新增同义 target，不改变链接关系和可选构建条件。

### 公共头文件

源码可以进入子目录，但当前所有已安装头文件继续安装到原来的相对路径。

例如：

```text
reader/api/reader.h               → include/fast_gdb/reader/reader.h
reader/query/query_engine.h       → include/fast_gdb/reader/query_engine.h
reader/geometry/geometry_model.h  → include/fast_gdb/reader/geometry_model.h
```

构建树中的 target include 目录覆盖对应子目录，使现有无目录前缀的 include 保持有效。

当前未安装的内部头文件继续不安装。`query_where_internal.h`、`explorgdb_constants.h` 等内部文件不得因迁移意外进入安装包。

### 目标名称

迁移前后对比全部目标，不只检查部分库：

- library 和 interface target；
- `gdal_FastFileGDB` plugin；
- `explorgdb_cli` 和验证工具；
- 数据生成工具；
- 所有测试 runner；
- 所有导出的 `fast_gdb::*` package target。

## 八、执行阶段与提交边界

每个提交必须完成同一模块的源码移动、测试移动、include 更新、CMake 更新和最小验证，不能留下不可构建的中间状态。

1. `fix: update installed release notes path`
   - 修正 `FastGdbInstall.cmake` 的 release note 路径；
   - 完成一次基线安装和 package consumer 验证。
2. `refactor: organize reader geometry and io modules`
   - 同时迁移源码、对应测试、CMake 和安装映射。
3. `refactor: organize reader format and index modules`
   - 同时迁移源码、对应测试、CMake 和安装映射。
4. `refactor: organize reader api and query modules`
   - 同时迁移源码、对应测试、CMake 和安装映射。
5. `test: organize integration boundary and fixtures`
   - 整理 GDAL parity、真实数据、生命周期边界和 fixture。
6. `chore: organize reference code and test data generators`
   - 移动 `usegdal` 参考代码和 createdata 脚本；
   - 确认它们没有进入正式产品目标。
7. `docs: synchronize source and test architecture`
   - 更新源码 README、测试索引、CI、质量文档和内部链接；
   - 合并或移除重复的 `QUERY_FLOW.md`。

提交信息可根据实际 diff 微调，但每个提交都必须独立可构建、可测试和可回退。

## 九、验证计划

### 基线快照

迁移前记录：

```bash
cmake -S . -B build/layout-baseline
cmake --build build/layout-baseline --parallel
cmake --build build/layout-baseline --target help
ctest --test-dir build/layout-baseline -N
```

保存 target 清单、CTest 测试名称和数量，用于迁移后比较。跳过的测试仍记为 `SKIPPED`，不能算作通过。

### 构建矩阵

至少验证三个独立构建目录：

```bash
# 默认：GDAL ON、Unified ON
cmake -S . -B build/layout-default
cmake --build build/layout-default --parallel
ctest --test-dir build/layout-default --output-on-failure

# Linear：GDAL OFF
cmake -S . -B build/layout-linear \
  -DFAST_GDB_WITH_GDAL=OFF \
  -DFAST_GDB_BUILD_GDAL_DRIVER=OFF
cmake --build build/layout-linear --parallel
ctest --test-dir build/layout-linear --output-on-failure

# Adaptive：GDAL ON、Adaptive ON
cmake -S . -B build/layout-adaptive \
  -DFAST_GDB_WITH_GDAL=ON \
  -DFAST_GDB_BUILD_ADAPTIVE_READER=ON
cmake --build build/layout-adaptive --parallel
ctest --test-dir build/layout-adaptive --output-on-failure
```

迁移后的 target 和 CTest 清单必须与对应配置的基线一致。

### 安装和 package consumer

分别安装 linear、默认 GDAL 和 adaptive 构建，并使用 `tests/package_consumer` 验证：

- `FAST_GDB_CONSUMER_TARGET=linear`；
- `FAST_GDB_CONSUMER_TARGET=hybrid`；
- `FAST_GDB_CONSUMER_TARGET=unified`；
- `FAST_GDB_CONSUMER_TARGET=adaptive`。

每个 consumer 都必须完成 configure、build 和 CTest。安装目录中的头文件相对路径必须与迁移前清单一致。

### 路径、文档和格式检查

检查旧源码平铺位置、旧测试目录和旧 release note 路径：

```bash
rg -n 'tests/usegdal|src/edgar/usegdal|docs/releases/v0\.2\.0\.md' \
  CMakeLists.txt cmake README.md src tests tools .github docs \
  --glob '!docs/archive/**' \
  --glob '!docs/plan/03_*'

find src/edgar/explorgdb/reader -maxdepth 1 \
  -type f \( -name '*.cpp' -o -name '*.h' \)

git diff --check
```

允许历史归档记录旧路径，但当前源码、测试、构建、CI 和有效文档不得继续依赖旧路径。

另外执行 Markdown 内部链接检查，确认源码 README、`tests/INDEX.md`、`docs/README.md` 和质量文档可以导航到新位置。

## 十、完成定义

- 源码和测试目录符合本计划的职责划分；
- 每个源码模块都能直接找到对应单元测试或集成测试；
- 所有现有构建、测试、插件、工具和 package target 名称保持不变；
- CTest 名称、数量、前缀和资源锁保持不变；
- 已安装头文件清单及相对路径保持不变；
- 四种 package consumer 均可使用原 include 写法构建和运行；
- 默认、GDAL OFF 和 Adaptive ON 构建通过；
- `src/reference/usegdal` 不被编译、安装、导出或作为发布能力宣传；
- 当前文档、CI 和 CMake 不再依赖旧路径；
- 未修改业务逻辑、解析算法和公共接口语义。

完成全部验证并记录证据后，文档状态才能从 `Proposed` 更新为 `Current`。
