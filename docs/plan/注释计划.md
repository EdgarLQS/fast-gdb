# 注释计划

## 背景

代码库约 90 个文件（50+ .cpp + 40+ .h），约 60K+ 行 C++。各模块注释密度差异大：
- `explorgdb_types.h`、`datasource.h`、`query_builder.h` 等已有丰富中文注释 + Doxygen 风格
- `geometry_model.h`、`feature_cursor.cpp`、`query_engine.cpp`、`gdb_attribute_index_query.cpp`、`curve_geometry.cpp` 等**零注释**
- 其余文件程度不一，但整体偏少

目标：提升代码可读性，降低新读者的理解成本。注释**以中文为主**，短 inline 保留英文（保持代码库既有惯例）。

## 注释惯例

### 文件头注释

```cpp
// src/edgar/explorgdb/reader/geometry_model.h
// 几何数据模型 — 定义几何编码、拓扑状态和输出表示
```

### 节标题

```cpp
// ────────────────────────────────────────────────
// 1. 坐标变换与网格点
// ────────────────────────────────────────────────
```

### 子节/函数分组

```cpp
// ========== 构造/析构 ==========
```

### 公开 API 函数文档（中文说明 + Doxygen 标签）

```cpp
/**
 * 使用连接配置打开 GDB 数据源。
 *
 * 实现步骤：
 * 1. 先 close() 释放已有的 GDALDataset
 * 2. 根据 ReadOnly 标志计算打开模式
 * 3. 将打开选项传给 GDALOpenEx
 *
 * @param info 连接配置（路径、只读、Open 选项）
 * @return true 打开成功
 */
```

### 结构体/枚举字段注释（中文）

```cpp
struct GeometryValue {
    std::vector<uint8_t> wkb;  // 输出几何的 WKB 二进制字节流
    int32_t srid = 0;           // 空间参考 ID
    uint32_t geometry_type = 0; // OGR 几何类型编码（wkbFlatten 后的值）
    bool has_z = false;         // 坐标是否包含 Z 分量
    bool has_m = false;         // 坐标是否包含 M 测量值
    ...
};
```

### 内联逻辑注释（简短中文或英文，视复杂度）

```cpp
// 跳过无效的 B+ 树页面
// spatial candidates rechecked against WHERE clause
```

## 注释原则

| 原则 | 说明 |
|------|------|
| **"做什么"放头文件** | `.h` 说明函数/类的职责、参数、返回值 |
| **"为什么"放实现文件** | `.cpp` 解释设计决策背景、算法选择原因 |
| **"怎么做"只在关键处** | 难的算法（B+ 树导航、几何解码、坐标变换）加 inline 说明，简单循环不污染 |
| **不写显而易见的代码** | `i++`、`for (auto& x : vec)` 不需要注释 |
| **不写"历史快照"** | 注释讲当前代码，不记录"之前是什么"（那是 git 的事） |
| **不写"TODO 未来"** | 除非是当前必须处理的已知问题，否则用 issue 跟踪 |

## 每批执行流程

```
1. 先头文件：文件头 → 节标题 → 类/结构/枚举说明 → 方法 Doxygen → 字段注释
2. 再实现文件：文件头 → 函数分组 → 内部函数/关键逻辑 inline 说明
3. 快速自检：确保注释格式一致，没有遗漏大段无注释代码块
4. 编译验证：确保注释不影响编译（注释不会影响，但检查意外修改）
```
