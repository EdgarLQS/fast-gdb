## 1. 目标与边界

本计划用于提升代码库的职责可读性和设计可审计性。注释以中文为主，公开 API 使用
Doxygen；短小、既有英文术语保留。

执行时遵守以下边界：

1. 头文件解释“做什么”：职责、参数、返回值、所有权、生命周期和稳定语义；
2. 实现文件解释“为什么”：索引安全、状态机、回退策略和 fail-closed 原因；
3. 只在复杂算法的关键分支解释“怎么做”，不逐行翻译循环和赋值；
4. 已有充分注释的文件不重复堆叠同义说明；
5. 注释批次不改变函数签名、状态机或算法行为。

“全量注释”按**全目录逐文件审计**定义：每个 `.h/.hpp/.cpp` 都检查文件职责、公开契约、
所有权/生命周期和关键算法原因；已有充分注释的文件记录为“审计通过”，而不是为了制造 diff
重复添加同义注释。计划 22 的 WKB-first 行为修改在注释工作之前独立完成；本文件列出的四批
工作只记录注释和职责审计范围。

## 6. 第四批：`usegdal/`

### 全目录审计结果

以下公开接口已具备并复核中文所有权、生命周期或线程安全说明：

- `datasource.h/.cpp`：GDALDataset 生命周期、打开模式和错误上下文；
- `datasets.h/.cpp`：OGRLayer 非拥有引用和数据集操作边界；
- `recordset.h/.cpp`：OGRFeature 游标所有权、空间关系后过滤和共享游标状态；
- `feature.h/.cpp`：几何深拷贝、字段顺序和值对象与 OGRFeature 双向转换；
- `field.h/.cpp`：variant 类型系统、空值和 OGR 字段映射；
- `connection_pool.h/.cpp`：池级线程安全、借出对象独占和非阻塞池满行为；
- `query_builder.h/.cpp`：SQL/空间过滤条件构造与参数边界；
- `batch_writer.h/.cpp`：缓冲阈值、OGRFeature 临时对象和非事务性 flush；
- `transaction.h/.cpp`：RAII 终结语义与底层驱动能力边界；
- `connection_info.h`、`error_context.h` 等其余头文件均完成字段语义和错误生命周期审计。

本轮重点补齐：

- `feature.cpp`：值语义、几何所有权、平行字段 vector、CPL 缓冲释放和 SetGeometry 深拷贝；
- `field.cpp`：variant 分支、窄化/拓宽规则、日期时间文本策略和不支持类型降级；
- `connection_pool.h`：明确只管理 usegdal 产品线，不参与纯 C++ Reader 生命周期；
- `batch_writer.h`：`commit()` 只是 flush + 累计数，不是数据库事务提交；
- `batch_writer.h`：`rollback()` 只丢弃未 flush 缓冲，不能撤销已写入 OGRLayer 的数据；
- `transaction.h`：RAII 只能保证作用域终结，不能补足底层驱动不支持的事务能力。

结论：`usegdal/` 全目录注释审计完成。
